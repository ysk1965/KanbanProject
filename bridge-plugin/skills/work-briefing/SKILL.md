# 업무 브리핑

사용자의 BRIDGE 데이터를 읽어 "오늘(또는 이번 주) 나의 업무"를 정리하고 무엇부터 하면 좋을지 우선순위를 제안하는 워크플로우. **읽기 중심** — 기본은 채팅에 브리핑만 출력하고, 저장/공유는 요청이 있을 때만.

## 이 스킬이 아는 것과 모르는 것

- **아는 것(워크플로우)**: 어떤 데이터를 모아, 어떤 순서로 우선순위를 매겨, 어떻게 브리핑할지.
- **모르는 것(데이터 접근)**: BRIDGE에서 어떻게 읽는지는 MCP 읽기 툴이 처리한다. 이 스킬은 툴을 부르고 결과를 엮기만 한다.

PAT가 사용자 본인이므로 개인 스코프는 자동으로 적용된다 — 대상 사용자를 물어볼 필요가 없다.

## 절차

1. **기간을 정한다.**
   - 기본은 **오늘**. "이번 주"라고 하면 오늘~일요일 범위로 잡는다.
   - 날짜 문자열은 `yyyy-MM-dd` 형식.

2. **병렬로 수집한다.** 세 툴을 한 번에 호출한다(서로 의존 없음):
   - `get_my_today` — 오늘 내 태스크·일정.
   - `get_my_board_tasks` — 내가 속한 보드들에 걸친 나의 태스크(크로스보드).
   - `get_my_calendar(start_date, end_date)` — 기간 통합 캘린더(미팅+일정). **start_date·end_date 필수**. 오늘만이면 둘 다 오늘 날짜.

3. **우선순위화한다.** 수집한 데이터를 다음 순서로 정리한다:
   1. **지연된 것** — 마감이 지났는데 안 끝난 태스크(가장 먼저).
   2. **오늘 마감** — 오늘 마감인 태스크.
   3. **오늘 미팅/일정** — 시간 있는 이벤트(시간순).
   4. **추천 순서** — "이 순서로 하면 좋겠다" 한 줄 제안(미팅 전후 시간, 마감 임박도 고려).

4. **브리핑을 출력한다(기본: 쓰기 없음).** 채팅에 사람이 읽기 좋게 정리한다:
   - 한눈 요약(오늘 할 일 N개 · 미팅 M개 · 지연 K개) → 지연 → 오늘 마감 → 일정 → 추천 순서.
   - 태스크는 어느 보드 것인지 함께 표시하면 좋다.

5. **선택: 저장/공유.** 사용자가 "저장해줘 / 노트로 남겨줘"라고 하면:
   - 브리핑을 **HTML**로 만들어 `save_document(title: "오늘 업무 브리핑 (yyyy-MM-dd)", content)`로 마이스페이스에 저장.
   - "링크로 공유"까지 요청하면 `share_document(id)`로 `share_url`을 준다.

## 판단 규칙

- 요청에 저장/공유 언급이 없으면 **4번(채팅 출력)에서 끝낸다.** 브리핑은 읽기 흐름이다.
- 수집 결과가 비어 있으면(오늘 할 일 없음) 그대로 "오늘은 예정된 태스크/일정이 없다"고 알리고, 크로스보드 태스크 중 다가오는 것을 제안한다.
- 캘린더 툴은 start_date·end_date가 필수다 — 오늘 하루면 둘 다 같은 날짜를 넘긴다.
- 툴이 401 → PAT 무효. BRIDGE에서 새 PAT 발급(`POST /api/v1/pat`) 후 플러그인 설정에 넣으라고 안내.

## 알아둘 점

- 이 스킬은 개인 스코프 전용이다. "팀/보드 리포트"는 `save-weekly-report`, "프로젝트/조직 보고서"는 `save-project-report`를 쓴다.
- 저장 시 HTML로 만든 문서는 공유 링크에서 잘 보이지만 앱 내 노트 에디터에서는 원본 그대로 열리지 않을 수 있다.
