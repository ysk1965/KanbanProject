# 📅 데일리 스케줄 기획서 (최종)

## 1. 개요

### 1.1 목적
구성원별로 하루 근무시간을 시각화하고, 체크리스트(업무) 단위로 일정을 배치하여 팀 전체의 일일 업무 현황을 한눈에 파악

### 1.2 핵심 컨셉
- **구성원 기준 뷰**: 칸반 보드의 "사람 중심" 시점
- **시간 블록 기반**: 하루 근무시간을 시간 단위로 분할
- **세로 드래그 생성**: 시간 영역을 세로로 드래그하여 블록 생성
- **리사이즈**: 블록 상하 끝을 드래그하여 시간 조절
- **계층 연결**: Schedule Block → ChecklistItem → Task → Feature 연결

### 1.3 Schedule Block 개념

```
┌─────────────────────────────────────────────────────────────────────────┐
│                                                                         │
│   ChecklistItem (체크리스트 항목)                                        │
│   ├── start_date: 1/8         ← "이 작업은 1/8 ~ 1/10 사이에 해야 해"    │
│   ├── due_date: 1/10                                                    │
│   │                                                                     │
│   └── Schedule Blocks (타임블록, 여러 개 가능)                           │
│       ├── 1/8  09:00-11:00   ← "1/8에 오전 2시간 작업"                  │
│       ├── 1/9  14:00-16:00   ← "1/9에 오후 2시간 작업"                  │
│       └── 1/10 09:00-10:00   ← "1/10에 마무리 1시간"                    │
│                                                                         │
│   → 하나의 체크리스트 항목을 여러 날에 걸쳐 시간 단위로 배치 가능         │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### 1.4 보드 근무시간 설정 용도

```
boards.work_start_time = "09:00"   → 스케줄 뷰 그리드를 09:00부터 표시
boards.work_hours_per_day = 8      → 8시간 범위 표시 (09:00 ~ 17:00)

→ "우리 팀 기본 근무시간" 설정으로 UI 표시 범위 결정
→ 개별 타임블록은 이 범위를 벗어나도 생성 가능
```

## 2. 데이터 구조

### 2.1 전체 구조
```
Feature (피쳐 카드)
    └── Task (태스크 카드)
            └── ChecklistItem (체크리스트 항목)  ← 기존 테이블 활용
                    └── Schedule Block (타임블록) ← 신규
```

### 2.2 ChecklistItem 테이블 (기존)

> ⚠️ **현재 구현 상태**: `checklist_items` 테이블이 이미 존재하며, 아래 필드들이 구현되어 있음

```sql
-- 현재 구현된 checklist_items 테이블
CREATE TABLE checklist_items (
    id              VARCHAR(36) PRIMARY KEY,
    task_id         VARCHAR(36) NOT NULL REFERENCES tasks(id) ON DELETE CASCADE,

    -- 기본 정보
    title           VARCHAR(200) NOT NULL,

    -- 담당자
    assignee_id     VARCHAR(36) REFERENCES users(id) ON DELETE SET NULL,

    -- 일정
    start_date      DATE,
    due_date        DATE,
    done_date       DATE,          -- 완료 시 자동 설정

    -- 상태
    is_completed    BOOLEAN DEFAULT FALSE,
    position        INTEGER NOT NULL,

    created_at      TIMESTAMP NOT NULL,
    completed_at    TIMESTAMP      -- 완료 시각
);
```

**기존 API 경로**: `GET/POST /boards/{boardId}/tasks/{taskId}/checklist`

### 2.3 Schedule Block 테이블 (타임블록) - 신규

```sql
CREATE TABLE schedule_blocks (
    id                  VARCHAR(36) PRIMARY KEY,
    board_id            VARCHAR(36) NOT NULL REFERENCES boards(id) ON DELETE CASCADE,
    checklist_item_id   VARCHAR(36) REFERENCES checklist_items(id) ON DELETE CASCADE,
    assignee_id         VARCHAR(36) NOT NULL REFERENCES users(id) ON DELETE CASCADE,

    -- 스케줄 정보
    scheduled_date      DATE NOT NULL,
    start_time          TIME NOT NULL,           -- 09:00:00
    end_time            TIME NOT NULL,           -- 11:30:00

    created_at          TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at          TIMESTAMP DEFAULT CURRENT_TIMESTAMP,

    -- 시간 유효성 체크
    CONSTRAINT valid_time_range CHECK (end_time > start_time)
);

CREATE INDEX idx_schedule_blocks_lookup
ON schedule_blocks(board_id, scheduled_date, assignee_id);
```

> 💡 **변경점**: `checklist_id` → `checklist_item_id` (기존 테이블명과 일치)

### 2.4 보드 설정 확장 - 신규

```sql
-- boards 테이블에 스케줄 설정 컬럼 추가
ALTER TABLE boards ADD COLUMN work_hours_per_day INTEGER DEFAULT 8;
ALTER TABLE boards ADD COLUMN work_start_time TIME DEFAULT '09:00:00';
```

> 💡 **현재 Board 엔티티**: `id`, `name`, `description`, `owner_id`, `created_at`, `updated_at` 필드만 존재

### 3.2 타임블록 상세

```
┌─────────────────┐
│ ═══════════════ │  ← 상단 리사이즈 핸들 (드래그로 시작시간 조절)
│                 │
│  로그인 API     │  ← Checklist 제목
│  개발           │
│                 │
│  ─────────────  │
│  📋 백엔드 인증  │  ← 연결된 Task (클릭 → Task 상세)
│  📁 로그인 기능  │  ← 연결된 Feature (클릭 → Feature 상세)
│                 │
│ ═══════════════ │  ← 하단 리사이즈 핸들 (드래그로 종료시간 조절)
└─────────────────┘
```

**블록 높이 = 시간 비례**
- 30분 = 40px
- 1시간 = 80px
- 2시간 = 160px

**블록 색상**
| 상태 | 색상 | 조건 |
|------|------|------|
| 기본 | 🔵 파란색 | 체크리스트 미완료 |
| 완료 | 🟢 초록색 | 체크리스트 완료 |
| 마감 임박 | 🟠 주황색 | due_date가 오늘 또는 내일 |
| 마감 초과 | 🔴 빨간색 | due_date 지남 & 미완료 |
| 미연결 | ⚪ 회색 | 체크리스트 연결 없음 |

## 7. 데이터 플로우

### 7.1 타임블록 생성 (새 체크리스트)

```
1. 사용자가 빈 영역 세로 드래그
2. "새 체크리스트 만들기" 선택
3. 모달에서 정보 입력 후 [생성] 클릭
   │
   ▼
4. API 호출: POST /schedules/with-checklist-item
   │
   ▼
5. 백엔드 처리:
   ├── ChecklistItem 생성 (task_id 연결)
   └── Schedule Block 생성 (checklist_item_id 연결)
   │
   ▼
6. 응답 → UI 업데이트
```

### 7.2 타임블록 리사이즈

```
1. 사용자가 블록 상/하단 핸들 드래그
2. 드래그 종료 시 새 시간 범위 계산
   │
   ▼
3. API 호출: PUT /schedules/{blockId}
   {
     "startTime": "09:30",
     "endTime": "12:00"
   }
   │
   ▼
4. 백엔드: schedule_blocks 업데이트
   │
   ▼
5. 응답 → UI 블록 높이 조절
```

### 7.3 체크리스트 완료 시

```
1. 상세 패널에서 [✓ 완료 처리] 클릭 또는 체크박스 토글
   │
   ▼
2. API 호출: PATCH /boards/{boardId}/tasks/{taskId}/checklist/{itemId}/toggle
   │
   ▼
3. 백엔드 (기존 toggle 로직):
   ├── checklistItem.is_completed = !is_completed
   ├── checklistItem.done_date = today (완료 시) / null (취소 시)
   └── checklistItem.completed_at = now (완료 시) / null (취소 시)
   │
   ▼
4. 응답 → 블록 색상 초록색으로 변경 (또는 원복)
```

> ✅ **기존 구현 활용**: toggle() 메서드에서 done_date 자동 관리 이미 구현됨
