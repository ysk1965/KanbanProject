「기능」 탭과 첫 번째 기능, 시간표 차트

마이 스페이스 상단 탭에 스토리지 옆으로 「기능」을 추가한다. 왼쪽 패널은 스토리지의 폴더 트리처럼 기능을 탭 형태로 쌓는 자리이고, 오른쪽은 선택한 기능의 작업 공간이다. 첫 기능은 시간표 차트다. 날짜를 상단에 두고 시간 · 장소 · 내용 · 곡목 · 비고 다섯 열이 기본이며, 행과 열을 자유롭게 늘리고 A4 가로 PDF로 내보낸다.

01

한눈에 보기

Goal목표

  • 마이 스페이스에 도구성 기능을 담는 그릇(「기능」 탭)을 만든다.
  • 첫 기능으로 시간표 차트를 넣고, 종이로 나눠 줄 수 있는 PDF까지 한 번에 만든다.
  • 이후 기능은 레지스트리에 한 줄 추가하면 왼쪽 패널에 탭으로 나타난다.

Scope이번 범위

  • 상단 탭 「기능」 추가, 왼쪽 기능 목록 패널, 오른쪽 작업 영역 골격
  • 시간표 문서 여러 개 저장 · 이름 변경 · 삭제
  • 날짜 블록 추가, 행 추가, 열 추가 · 이름 변경 · 삭제, 셀 글자색
  • 시간 열 5분 단위 피커, 장소 · 곡목 · 비고 이전 입력 추천 (색 포함)
  • 같은 열 안 세로 셀 병합 · 해제, 연속 같은 값 자동 병합, 열 순서 이동
  • PDF 내보내기 (A4 가로, 브라우저 인쇄 경로)

Out이번에 안 하는 것

  • 보드(팀) 스페이스로의 공유 · 실시간 공동 편집
  • 한 셀 안에서 단어별로 색을 다르게 주는 부분 서식 v2
  • 서버 사이드 PDF 렌더링, 엑셀 내보내기
  • 모바일 편집 최적화 (모바일은 열람 + PDF만)

Decide확인이 필요한 것

  • 기능 안의 문서 목록 위치: 왼쪽 패널에서 기능 아래로 펼치는 안(시안 A)을 제안. 스토리지의 폴더 트리와 같은 모양.
  • 셀 병합 범위: 같은 열 안 세로 병합만 지원. 가로 병합(여러 열 합치기)은 참고 자료에 쓰임이 없어 v1에서 뺐다. 필요하면 셀 모델의 span 옆에 colspan만 더하면 된다.
  • 모바일 하단 탭: 현재 6개, 7개가 되면 폭이 빠듯하다. 「기능」은 하단 탭에서 빼고 「더보기」로 묶는 안 검토.

04

시안 B · 시간표 편집기 (동작 시안)

아래는 실제로 동작하는 시안이다. 셀을 눌러 글을 고치고, 행 · 열 · 날짜를 늘리고, 셀 색을 바꾼 뒤 「PDF 미리보기」로 넘어가 보라. 참고 이미지(9/12 리허설표)를 기본 예시 데이터로 넣었다. 이 페이지에서 바꾼 내용은 저장되지 않는다.

Timetable editor · 예시 데이터 · 편집 가능

셀 색 셀을 고른 뒤 색을 누르세요
1열 머리글을 눌러 이름을 바꾼다. 「＋ 열 추가」는 맨 오른쪽에 「새 열」을 붙이고 머리글에 커서를 둔다. 머리글에 마우스를 올리면 ✕가 나타나 열을 지운다 (마지막 한 열은 못 지움).
2날짜는 표 위 블록 제목이다. 날짜 입력을 바꾸면 「9.12 (토)」 표기가 자동으로 따라온다. 날짜 블록은 여러 개 둘 수 있고, PDF에서는 블록마다 제목 + 표로 이어진다.
3셀은 여러 줄 입력(Shift+Enter 없이 Enter)이 된다. Tab으로 다음 셀, 마지막 셀에서 Tab이면 행이 하나 늘어난다.
4색은 셀 단위. 편집 화면 색은 다크 배경용으로 밝게, PDF에서는 종이용 진한 색으로 바뀐다 (같은 6색 이름을 공유).
5셀 병합: 셀 하나를 누른 뒤 같은 열의 다른 셀을 Shift+클릭(또는 Shift+↑↓)하면 범위가 잡히고 「⊟ 셀 병합」이 켜진다. 합친 셀은 편집 화면에서도 합쳐진 채로 보이고 「⊟ 병합」 표시가 붙는다. 합친 셀을 누르고 「병합 해제」하면 원래 셀들이 값까지 그대로 돌아온다.
6「PDF 내보내기」는 실제 앱에서 브라우저 인쇄 대화상자를 연다. 이 문서는 샌드박스라 인쇄를 열 수 없어 미리보기 탭으로 넘어간다.
7시간 열은 셀을 누르면 5분 단위 피커가 아래에 뜬다. 빈 셀이면 이전 행의 종료 시각에서 시작하고 길이는 이전 행과 같게 채운다. 「+30분」 같은 칩은 종료만 바꾼다. 타이핑도 그대로 된다.
8장소 · 곡목 · 비고는 셀에 들어가면 최근 쓴 값이, 글자를 치면 맞는 값이 목록으로 뜬다. ↑↓로 고르고 Enter로 넣는다. 비고는 그때 쓴 색까지 같이 들어온다. 목록 항목의 ✕는 기억에서 지운다.
9열 순서는 머리글에 마우스를 올리면 나오는 ◀ ▶로 옮긴다. 참고 이미지처럼 장소를 시간 앞에 둘 수 있다. 「같은 값 자동 병합」은 장소 · 비고처럼 연속으로 같은 값(같은 색)인 셀을 한 번에 합친다. 결과는 보통 병합과 같아서 「병합 해제」로 되돌린다.

입력 보조 · 병합 상세

Merge셀 병합 · 해제

  • 범위 잡기: 셀에서 같은 열의 다른 셀까지 드래그, 셀 클릭 → 다른 셀 Shift+클릭, 또는 Shift+↑↓. 같은 셀 안에서만 끌면 보통의 글자 선택이다. 다른 열을 Shift+클릭하면 무시하고 힌트로 알린다.
  • 병합: 범위의 맨 위 셀이 대표가 된다. 대표가 비어 있으면 범위 안 첫 값(색 포함)을 가져온다. 나머지 셀의 값은 버리지 않고 숨긴다.
  • 해제: 대표의 span만 지우면 숨겨 둔 셀들이 값 그대로 돌아온다. 그래서 「합쳤다가 다시 돌려놓기」가 손실 없이 된다.
  • 범위에 이미 합쳐진 셀이 걸치면 그 셀 전체를 포함하도록 범위를 넓혀서 합친다. 병합끼리 겹치는 일은 없다.
  • 행 삭제: 합쳐진 범위 안의 행을 지우면 span이 1 줄고, 대표 행을 지우면 바로 아래 행이 대표를 이어받는다.
  • 합친 셀도 색 · 추천 · Tab 이동이 보통 셀과 같다. Tab은 숨겨진 셀을 건너뛴다.
  • PDF는 span을 그대로 rowspan으로 그린다. 별도 계산 없음.
  • 행 순서 바꾸기는 병합과 부딪히면 거부한다: 옮기는 행이 병합 안에 있거나 이동으로 병합이 쪼개지면 「병합된 행은 먼저 병합을 풀어 주세요」. 시간 열의 병합은 상관없다 (시간 칸은 움직이지 않으므로).

Time시간 피커 (5분 단위)

  • 열 타입 time. 셀 포커스 시 시작 · 종료 각각 시 (00–23) × 분 (00, 05 … 55) 선택.
  • 기본값: 시작 = 이전 행 종료, 길이 = 이전 행 길이 (첫 행이면 13:00, 30분). 빈 셀에 들어가는 순간 채워지므로 「행 추가 → 셀 클릭」만으로 다음 시간이 잡힌다.
  • 빠른 칩 「+15분 · +30분 · +1시간 · +1시간 30분」은 종료 = 시작 + n.
  • 연쇄 이동: 어떤 행의 종료 시각이 바뀌면 같은 날짜의 아래 행들이 따라온다 (겹치는 시간이 없다는 전제). 각 행의 길이와 원래 있던 쉬는 시간(간격)은 유지하고, 겹쳐 있던 행만 끝시각에 딱 붙인다. 시작만 바꾸면 연쇄하지 않는다. 옮겨진 뒤에도 아래 행은 따로 고칠 수 있다.
  • 직접 타이핑 허용. 13:00-14:30, 1300~1430처럼 써도 저장 시 13:00 – 14:30으로 정규화하고 분은 5분 단위로 반올림.
  • 종료가 시작보다 앞서면 저장은 하되 셀 아래에 노란 경고선. 자정 넘김(23:30 – 00:30)은 허용.
  • Esc 또는 다른 곳 클릭으로 닫힘. Enter는 줄바꿈 대신 닫기.
  • 행 끼워 넣기 (행의 ＋, 또는 셀에서 Alt+Enter): 새 행은 「시작 = 위 행 종료, 길이 = 위 행 길이」로 채우고 아래 행들은 연쇄 이동 규칙 그대로 따라온다. 위 행이 세로 병합 안이면 span이 1 늘어 병합이 유지된다.
  • 겹침 경고: 시간이 읽히는 행끼리 순서대로 비교해 다음 행 시작이 앞 행 종료보다 앞서면 그 셀 위쪽에 노란 경고선 (툴팁 「위 행과 시간이 겹칩니다」). 역전 경고선(아래쪽)은 그대로. 앞 행이 자정 넘김이면 비교하지 않는다.
  • 총 소요 시간: 날짜 제목 옆에 「13:00–20:00 · 7시간 · 쉬는 시간 40분」. 첫 행 시작 → 마지막 행 종료(자정 넘김이면 +24h), 쉬는 시간은 행 사이 양의 간격 합. 0이면 생략.

Recall이전 입력 추천

  • 열 옵션 suggest. 기본으로 장소 · 곡목 · 비고에 켜고, 열 머리글 메뉴에서 열마다 끄고 켤 수 있다.
  • 출처: 이 문서 + 내가 만든 다른 시간표 전부. 사용자 단위로만 기억하고 남에게 새지 않는다.
  • 문서를 열 때 열 이름별 용어 목록을 한 번 받아 두고(열당 최대 300개) 이후 매칭은 브라우저에서 즉시. 서버 왕복 없음.
  • 정렬: 앞글자 일치 → 포함 일치 순, 같은 등급 안에서는 사용 횟수 × 최근성. 빈 입력이면 최근 6개.
  • 값과 함께 마지막 색을 기억한다. 「SJP 보컬/밴드」를 고르면 빨강까지 따라온다. 셀에 이미 색이 있으면 덮지 않는다.
  • 항목 ✕ = 기억 삭제. 오타를 한 번 저장했을 때 계속 추천되는 문제를 막는다. 한글 초성 검색은 v2.
  • 열 이름이 기억의 키다 (장소로 저장한 값은 다른 문서의 장소 열에서도 뜸). 열 이름을 바꾸면 그 이름의 기억으로 갈아탄다.
  • 색 규칙: 추천 열 셀을 색 없이 커밋(blur · Tab)했을 때 값이 기억된 용어와 정확히 같으면(공백 정리 · 대소문자 무시) 그 용어의 색이 자동으로 붙는다. 타이핑 중에는 붙지 않고, 이미 색이 있으면 덮지 않는다.

Edit편집 편의

  • 행 끼워 넣기: 행에 마우스를 올리면 ✕ 옆에 ＋. 셀에서 Alt+Enter 도 같다. 새 행의 첫 보이는 셀에 커서.
  • 행 순서: 행의 ⋮⋮ 손잡이를 끌어 사이에 놓는다 (파란 선이 놓일 자리). 시간 칸은 고정이고 내용 셀만 옮겨간다 — 시간표는 시간 슬롯이 먼저이고 내용이 슬롯을 갈아타는 것.
  • 여러 셀 붙여넣기: 스프레드시트에서 복사한 탭 구분 텍스트는 오른쪽 · 아래로 나눠 넣는다. 행이 모자라면 붙이고, 병합에 덮인 칸은 건너뛰며, 시간 열 값은 정규화. 엑셀식 따옴표 셀("줄바꿈 포함")도 한 칸. 탭이 없는 텍스트는 보통 붙여넣기 (셀은 원래 여러 줄이 되므로).
  • 되돌리기: Ctrl/⌘+Z · Shift+Z (또는 Ctrl+Y), 툴바 ↶ ↷. 문서 단위 스냅샷 100단계, 같은 셀의 연속 변경(시간 피커 select 등)은 0.8초 안이면 한 단계. 셀 안에서 아직 커밋 전인 타이핑은 브라우저의 되돌리기에 맡긴다. 되돌린 결과도 자동 저장된다.
  • 이미지로 복사: 종이(PrintSheet)를 오프스크린 1123px 폭으로 그려 2배 PNG 로 클립보드에 넣는다 (Safari 는 Promise 형 ClipboardItem). 클립보드를 못 쓰면 「문서 제목.png」로 내려받고 안내한다.

05

PDF 내보내기

현재 프론트에는 PDF 라이브러리가 없다 (package.json에 jspdf · html2canvas 없음). 한글 표는 브라우저 인쇄 경로가 가장 깨끗하고 의존성도 0이다. 글자가 벡터로 남아 확대해도 선명하고, 페이지 나눔을 CSS로 제어할 수 있다.

A. window.print + @media print편집기 DOM을 숨기고 인쇄 전용 「종이」 DOM만 출력. A4 가로, 여백 12mm. 사용자는 대화상자에서 「PDF로 저장」. 의존성 없음, 한글 폰트 그대로.
B. html2canvas + jsPDF화면을 래스터로 찍어 PDF에 붙임. 파일이 바로 내려오지만 글자가 비트맵이라 흐리고, 긴 표의 페이지 나눔이 어렵다. 번들 +400KB.
C. 서버 렌더 (Playwright/wkhtml)일관된 결과와 슬랙 첨부까지 가능하지만 EB 인스턴스에 브라우저 런타임이 필요. 팀 공유 기능이 붙을 때 다시 검토.

A안의 핵심 CSS. 종이 DOM은 편집기와 별개 컴포넌트(TimetablePrintSheet)로 두고 항상 마운트하되 화면에서는 display:none, 인쇄 시에만 보인다.

/* TimetablePrintSheet.css */
@page { size: A4 landscape; margin: 12mm; }
@media print {
  body * { visibility: hidden; }                 /* 앱 전체 숨김 */
  #timetable-print, #timetable-print * { visibility: visible; }
  #timetable-print { position: absolute; inset: 0; background: #fff; color: #111; }
  .print-day { break-inside: avoid; }            /* 날짜 블록은 한 페이지 안에 */
  .print-day + .print-day { margin-top: 10mm; }
  thead { display: table-header-group; }         /* 표가 넘어가면 머리글 반복 */
  tr { break-inside: avoid; }
  -webkit-print-color-adjust: exact; print-color-adjust: exact;  /* 셀 색 유지 */
}

Paper종이 레이아웃 규칙

  • 우상단 2줄: 버전 표기(밑줄) · 「장소 : ○○」. 참고 이미지 관례 유지.
  • 날짜는 표 위 제목 「9.12 (토)」, 18px 굵게.
  • 머리글 회색 배경 #f3f3f3, 테두리 1.5px 검정, 본문 가운데 정렬 굵게.

시간표는 문서 한 건 = JSON 한 덩어리로 다룬다. 열 구성이 문서마다 다르므로 행 · 셀을 정규화하지 않고 content JSONB에 통째로 넣는다. 서버는 크기 제한과 스키마 검증만 한다. 나중에 다른 기능이 생겨도 같은 personal_feature_docs 테이블을 feature_key로 나눠 쓴다.

추천 용어 테이블. 문서 저장(PATCH) 때 서비스가 suggest: true인 열의 값을 뽑아 upsert 한다. 문서 JSON을 검색하지 않으므로 문서가 수백 개여도 추천은 인덱스 한 번이다. 값 정규화는 trim + 연속 공백 1개로만.

-- 같은 마이그레이션 파일에 함께 (멱등)
CREATE TABLE IF NOT EXISTS personal_feature_terms (
    id            VARCHAR(36)  PRIMARY KEY,
    user_id       VARCHAR(36)  NOT NULL,
    feature_key   VARCHAR(40)  NOT NULL,          -- 'timetable'
    field         VARCHAR(60)  NOT NULL,          -- 열 이름: '장소' · '비고' …
    value         VARCHAR(300) NOT NULL,
    color         VARCHAR(16),                    -- 마지막으로 함께 쓴 색 이름
    use_count     INTEGER      NOT NULL DEFAULT 1,
    last_used_at  TIMESTAMP    NOT NULL
);
DO $$ BEGIN
    IF NOT EXISTS (SELECT 1 FROM pg_constraint WHERE conname = 'uq_pft_user_field_value') THEN
        ALTER TABLE personal_feature_terms ADD CONSTRAINT uq_pft_user_field_value UNIQUE (user_id, feature_key, field, value);
    END IF;
END $$;
CREATE INDEX IF NOT EXISTS idx_pft_lookup ON personal_feature_terms(user_id, feature_key, field, last_used_at DESC);

기능 확장 구조 (레지스트리)

「기능」 탭이 진짜로 쓸모 있으려면 두 번째, 세 번째 기능을 붙일 때 페이지 코드를 건드리지 않아야 한다. 왼쪽 패널과 오른쪽 작업 영역은 아래 레지스트리만 읽는다.

// frontend/src/app/components/personal/features/registry.ts
export interface PersonalFeature {
  key: string;                       // 'timetable' — API feature_key와 동일
  labelKey: string;                  // i18n: personal.features.timetable
  icon: LucideIcon;
  newDocLabelKey: string;            // '새 시간표'
  status: 'ready' | 'soon';
  createDefault: () => unknown;      // 새 문서 content 템플릿
  Editor: React.ComponentType<FeatureEditorProps>;
  PrintSheet?: React.ComponentType<FeaturePrintProps>;   // 있으면 PDF 버튼 노출
}

export const PERSONAL_FEATURES: PersonalFeature[] = [
  { key: 'timetable', labelKey: 'personal.features.timetable', icon: Table2,
    newDocLabelKey: 'personal.features.timetable_new', status: 'ready',

  { key: 'songlist',  labelKey: 'personal.features.songlist',  icon: ListMusic, status: 'soon', … },
];

Left왼쪽 패널

  • PERSONAL_FEATURES를 순회해 1단 항목을 그린다.
  • 선택된 기능만 문서 목록을 불러와 2단으로 펼친다.
  • status:'soon'은 흐리게, 클릭 시 토스트.

Right작업 영역

  • 선택된 기능의 Editor에 doc과 onChange만 넘긴다.
  • 자동 저장 · 제목 변경 · 복제 · 삭제 · PDF 버튼은 공통 셸(FeatureDocShell)이 담당.
  • 기능은 자기 content 스키마만 안다.
