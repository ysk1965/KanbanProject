Milkyway · PR3 설계안

처음엔 고르게 하고,
나중엔 있던 자리에서 켜게 한다.

단계를 나누는 것까지는 정해졌습니다. 남은 건 두 가지 — 시작할 때 무엇을 쓸지 어떻게 묻고, 안 쓰기로 한 걸 나중에 어디서 켜는가입니다. 아래 목업은 실제로 눌러볼 수 있고, 세 진입점이 같은 상태를 공유합니다.

원칙

세 줄로 못 박고 시작합니다

묻는 법

개념 이름을 묻지 않는다

"스프린트 쓰실래요?"는 스프린트를 아는 사람에게만 통하는 질문입니다. 일하는 방식을 묻고, 그 답에서 기능을 켭니다. 이미 아는 사람에겐 지름길을 따로 둡니다.

켜는 자리

꺼진 기능은 사라지지 않고 흐려진다

설정 화면에 숨기지 않습니다. 그 기능이 실제로 나타날 자리에 점선 유령으로 남깁니다. 위치 자체가 설명이 되고, 찾아갈 필요가 없습니다.

되돌림

끄는 건 숨기는 것이지 지우는 게 아니다

마일스톤을 꺼도 데이터는 그대로입니다. 다시 켜면 있던 그대로 돌아옵니다. 자동으로 꺼지는 일은 없습니다 — 켜고 끄는 건 항상 사람이 합니다.

설계 변경

ui_level 숫자 하나로는 안 됩니다

"나중에 개별로 켤 수 있어야 한다"는 요구가 구조를 바꿉니다. 1·2·3 숫자는 마일스톤은 켜고 구성원은 끄고 싶다를 표현할 수 없습니다.

boards — 저장하는 진실은 숫자가 아니라 켜진 기능 집합
ALTER TABLE boards ADD COLUMN ui_features TEXT NOT NULL DEFAULT '';
-- 쉼표로 구분된 키 집합. 최대 6개라 배열/JSONB까지 갈 이유가 없다.
-- 예: 'sprint,review,milestone'

-- 기존 보드는 전부 켜둔다 — 화면이 하나도 바뀌면 안 된다.
UPDATE boards SET ui_features = 'sprint,review,milestone,members,timeblock,jira'
 WHERE ui_features = '';

1·2·3 단계는 사라지지 않습니다 — 저장되는 값이 아니라 프리셋이 됩니다. "간단하게"를 고르면 집합이 '', "주기로"면 'sprint,review'가 되는 식입니다. 화면에 "지금 몇 단계"를 표시할 땐 집합을 프리셋과 대조해 파생하고, 어느 프리셋과도 다르면 직접 설정으로 표시합니다.

숫자였다면"마일스톤만 켜기"가 불가능. 2.5단계 같은 값을 만들게 됨
숫자였다면기능을 하나 추가할 때마다 단계 정의를 다시 씀
집합이면프리셋은 상수 테이블. 기능 추가는 키 하나 늘리면 끝
집합이면유령 슬롯 판정이 !features.has(k) 한 줄

① 시작할 때

보드를 만들 때 딱 한 번 묻습니다

개념 이름 대신 일하는 방식을 묻습니다. 아래에서 답을 고르면 이 페이지 전체의 보드 상태가 바뀝니다 — 다음 섹션의 화면도 함께 움직입니다.

이 팀은 일을 어떻게 굴리나요?

나중에 언제든 바꿀 수 있습니다. 지금 고른 것 때문에 못 하게 되는 일은 없습니다.

② 쓰는 중에

안 켠 기능은 자기 자리에 유령으로 서 있습니다

점선 칩이 유령입니다. 눌러보세요 — 그게 뭔지 설명하고, 켜면 바로 그 자리에 나타납니다. 오른쪽 위 기능 버튼은 전체를 한 곳에서 보는 서랍입니다.

지금 상태 간단하게 ui_features = ''

눌러볼 것

  1. 상단 탭 줄의 점선 ⊕ 단계로 묶기 — 설명이 뜨고, 켜면 마일스톤 탭이 그 자리에 생깁니다.
  2. 스프린트 헤더 오른쪽 ⊕ 구성원별로 보기 — 컬럼이 사람으로 바뀝니다.
  3. 카드 안 ⊕ 시간 블록 — 할 일마다 개인 일정이 붙습니다.
  4. 오른쪽 위 기능 버튼 — 전체 목록에서 프리셋으로 한 번에 바꾸거나 개별 토글.
  5. 팝오버의 이 제안 그만 보기 — 유령이 사라지고 서랍에서만 켤 수 있게 됩니다.

③ 유령의 규칙

유령이 화면을 잡아먹지 않게 하는 제약

좋은 아이디어도 제한이 없으면 광고판이 됩니다. 네 가지를 못 박습니다.
