트리아지 목록은 판정 시점의 스냅샷이라, 그 뒤 태스크가 QA로 넘어갔는지 완료됐는지 화면이 알지 못한다. 담당자는 아예 내려오지 않고, 축이라고는 후보·조건부·제외 3탭이 전부다. 아래는 세 문제를 한 번에 푸는 필터 우선 레이아웃과, 그걸 위해 서버가 더 내려줘야 하는 값이다.

진단

지금 화면이 못 하는 네 가지

앞의 둘은 화면 문제가 아니라 데이터가 없어서 생긴 문제다. 서버가 값을 안 주니 화면이 그릴 수가 없다.

끝난 일이 섞인다

원본 태스크가 지금 어느 칸에 있는지 목록이 모른다

JiraAutofixItem에는 task_id만 있고 태스크의 현재 상태 필드가 없다. 판정은 한 번 돌고 그대로 남으므로, 그 사이 작업완료·QA검토중·완료로 이동한 이슈도 똑같이 후보로 앉아 있다. 고칠 필요가 없어진 것을 러너에 태우면 일일 한도만 태운다.

frontend/src/app/utils/api.ts:6124

해결 행마다 현재 컬럼 뱃지 + 완료 이후 기본 숨김. 판정 후 이동한 건은 판정 후 이동 표식으로 재판정 대상임을 알린다.
담당자가 없다

누가 물고 있는 일인지 화면 어디에도 없다

체크리스트 담당자는 ChecklistItem.assignee에만 있고 트리아지 응답에 실리지 않는다. 그래서 "이건 내가 이미 손대고 있는 건데"를 판단할 수 없고, 담당자와 자동수정이 같은 파일을 동시에 건드릴 위험도 화면에 안 보인다.

backend/…/checklist/ChecklistItem.java:44

해결 담당자 아바타(기존 6색 assigneeColor 규칙 재사용) + 미배정을 별도 상태로 명시. 담당자별 필터가 여기서 나온다.
필터가 없다

74건을 걸러낼 축이 3탭뿐이다

현재 목록의 유일한 축은 후보 / 조건부 / 제외. 검색도, 담당자도, 카테고리도, 확신도 구간도 고를 수 없어서 52건을 눈으로 훑어야 한다. 게다가 담을 수 없는 행(이미 처리됨·임계값 미만)이 담을 수 있는 행과 같은 목록에 섞여 있다.

JiraAutofixDock.tsx:686 (VERDICT_TABS)

해결 검색·담당자·상태·카테고리·확신도 5축 필터 바. 활성 필터는 칩으로 되비추고, 필터 상태는 보드별로 기억한다.
제목이 없다

무슨 버그인지 모른 채 판정 근거만 두 줄 읽는다

지금 행에 보이는 건 "…확인 가능"(검증 방법)과 "…자동 비교 가능"(판정 이유)이다. 정작 이슈 제목이 없다. 모든 행이 3줄이라 12건만 떠도 화면이 꽉 차고, 문장이 서로 비슷해서 스캔이 안 된다.

JiraAutofixDock.tsx:799–808

해결 1행 = 제목 한 줄. 판정 근거는 접어두고 필요할 때만 편다. 같은 높이의 행이 반복되면 그제서야 목록이 목록으로 읽힌다.

전제

서버가 더 내려줘야 하는 값

상태·담당자는 프론트에서 만들어낼 수 없다. GET /boards/{id}/jira/autofix/items 응답에 아래 네 필드를 얹는 것이 이 개편의 유일한 백엔드 선행 작업이다. 모두 task_id로 이미 join 가능한 값이라 새 테이블은 필요 없다. 

// JiraAutofixResponse.TriageItem — 기존 8필드에 추가
public static class TriageItem {
    private String jiraIssueKey;
    private String taskId;
    private String verdict;
    private String category;
    private Double confidence;
    private String verification;
    private String reason;
    private String triagedAt;

    private String taskTitle;          // 행의 첫 줄. 지금은 판정 문장이 제목 자리를 차지한다
    private TaskState taskState;       // sprintColumn(name, kind) + qaState + isCompleted
    private List<Assignee> assignees;  // ChecklistItem.assignee 집합 (id, name, color)
    private Boolean movedAfterTriage;  // task 갱신 > triagedAt — 판정이 낡았다는 신호
}
  • taskState — SprintColumn.kind가 END거나 qaState가 VERIFIED/REVIEW면 "완료 이후"로 묶는다. 두 값 다 이미 Task에 있다. Task.java:128,146
  • assignees — ChecklistItemRepository.findByTaskIdInWithAssignee로 한 번에 조회 가능. 목록 조회 한 건에 쿼리 하나만 더 붙는다.
  • movedAfterTriage — 태스크가 판정 이후 움직였다는 뜻. 재판정 대상을 골라내는 축이자, "왜 아직 후보로 남아 있나"에 대한 답이다.
  • 필터를 서버로 넘길 필요는 없다. 보드당 트리아지가 수백 건 규모라 클라이언트 필터로 충분하고, 그래야 칩 반응이 즉시다. 다만 담기 시점 가드레일은 서버에 추가해야 한다 — 완료 이후 태스크는 enqueue에서 거절하고 그 수를 결과에 실어 보낸다 (skipped_already_done).
순서

쪼개서 넣는 방법

1단계만 넣어도 "끝난 게 섞인다"는 오늘 사라진다. 2·3단계는 그 위에 얹는다.

1단계 · 반영됨

상태·담당자·제목을 응답에 싣고, 끝난 칸을 기본으로 숨긴다

서버 4필드 + 행 레이아웃 2줄 전환 + 담기 가드레일(skipped_already_done). 화면에서 감추기만 하고 서버가 안 막으면 "조건 만족 전부"가 여전히 끝난 일을 태우므로 둘은 같은 규칙(AutofixTaskStage)을 본다.

  • 블록 필터 칩을 2단계에서 앞당겨 넣었다. 확정 신호(완료 체크 · Done 블록 · QA 검토중/완료)만으로는 "작업 완료" 같은 중간 블록이 걸러지지 않는데, 실제로 그 칸에 가장 많이 쌓여 있다. 서버가 이름으로 추측하면 조용히 틀리므로, 위치 칩을 한 번 눌러 끄면 보드별로 기억하는 방식으로 풀었다.
  • 기본값은 전부 끝난 블록만 자동으로 꺼짐. 사람이 한 번이라도 칩을 누르면 그 뒤로는 자동 판단을 쓰지 않는다.
  • QA 반려는 끝난 것으로 치지 않는다 — 되돌려 보냈다는 건 아직 안 고쳐졌다는 뜻이다.
BE 1 · FE 1
2단계 · 반영됨

남은 필터 축 5개

검색 · 담당자 · 유형 · 확신도 · 담을 수 있는 것만 (위치는 1단계에서 들어갔다). 전부 클라이언트 필터라 서버 변경 없음. 조합은 bridge-autofix-filters:{boardId}로 보드별로 기억한다.

  • 검색어는 저장하지 않는다. 다음에 도크를 열었을 때 예전 검색어가 목록을 잘라 놓고 있으면 항목이 사라진 줄 안다.
  • "담을 수 있는 것만"은 후보 탭에서만 적용한다. 조건부·제외 탭 항목은 애초에 담을 수 없어서, 그대로 걸면 탭이 통째로 비어 필터가 고장난 것처럼 보인다.
  • 담당자 축은 OR — 한 태스크에 담당자가 여럿인 게 흔해 AND로 걸면 거의 항상 0건이 된다. 축과 축 사이는 AND.
  • "조건 만족 전부" → "보이는 것 전부"로 바꿨다. 걸러 놓고 눌렀는데 화면 밖의 건까지 담기면 되돌릴 수 없다 — 이슈당 1회라 잘못 담긴 건은 취소해도 후보로 돌아오지 않는다.
  • 활성 필터 칩 대신 "숨김 N" 카운트 + 초기화 버튼으로 갔다. 도크는 보드 위에 얹히는 좁은 공간이라 칩 줄을 하나 더 쓰는 값이 정보값보다 컸다.
FE 만
3단계 · 반영됨

큐 세그먼트 + 판정 후 변경된 건만 재판정

큐를 진행·대기 / PR / 그 외 세 묶음으로 나눠 각각 접을 수 있게 하고, 판정 후 변경됨 건만 모아 그 이슈들만 다시 판정하는 버튼을 붙였다.

  • 서버에 범위 지정을 추가했다 — POST …/triage가 issue_keys를 받는다. 지정된 이슈는 변경 여부와 무관하게 무조건 다시 판정한다. 카드가 BRIDGE 안에서만 움직이면 JIRA 갱신 시각이 그대로라, 평소 기준으로는 전부 건너뛰어 버튼이 아무 일도 하지 않는다.
  • 재판정 대상은 지금 보이는 것만. 감춰 둔 칸의 항목을 태우면 AI 호출만 늘어난다.
  • "그 외"를 접어도 확인 필요 표시는 새어 나온다 — 접힘이 사람이 봐야 할 것을 삼키면 안 된다.
  • 다 접었을 때 빈 화면 대신 안내를 띄운다. 안 그러면 큐가 빈 것으로 읽힌다.
