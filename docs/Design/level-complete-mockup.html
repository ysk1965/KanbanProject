아래 화면은 전부 눌러볼 수 있습니다. 카드 6장 · 사람 4명 · 할 일 13줄은 한 번도 안 바뀝니다 — 바뀌는 건 시간을 몇 겹으로 감싸느냐(사다리)와 무엇을 켜두느냐(스위치)뿐입니다. 세 단계 모두 여러 사람이 같이 쓰는 도구입니다.

① 한 화면에서 확인

사다리를 오르내리고, 스위치를 켜고 꺼보세요

위 줄이 사다리(순서가 있고, 오를 때 정리가 따라옵니다), 아래 줄이 스위치(순서가 없고, 어느 단계서든 켭니다)입니다.

기존 보드 백필 = ui_level 3 + 전체 옵션 — 화면 무변화

눌러볼 것

  1. 보드 → 주기 — 스프린트 헤더와 "아직 안 담음" 레일이 생기고, 카드 4장만 이번 주기에 남습니다. 나머지 2장은 사라진 게 아니라 레일에서 기다립니다.
  2. 주기 → 로드맵 — 단계 탭과 로드맵 띠가 위에 얹힙니다. 아래 보드는 그대로입니다.
  3. 구성원별 보기 스위치 — 컬럼이 사람으로 바뀝니다. "튜토리얼 작업"이 두 컬럼에 서는 건 버그가 아니라 사양입니다 — 한 작업을 여럿이 나눠 밀기 때문입니다. 보드(1단계)에서도 켜집니다.
  4. 리뷰 단계 스위치 — "공용 UI · 연출 작업"이 리뷰 컬럼으로 분리됩니다. 이것도 어느 단계서든 됩니다.
  5. 개인 시간 블록 — 할 일 줄마다 내 캘린더 시간이 붙습니다. 팀 마감이 아니라 개인 일정입니다.

③ 승급의 순간

올라가는 건 스위치가 아니라 정리 작업입니다

승급 직후의 화면은 시스템이 재배치한 결과가 아니라 유저 자신이 방금 정리한 모습이어야 합니다. 그래서 토글 대신 한 장짜리 마법사를 거칩니다. 강등은 반대로 아무것도 묻지 않습니다 — 숨길 뿐 지우지 않으니까요.

보드 → 주기

ui_level 1 → 2 · 승급 마법사 1장

주기 → 로드맵

ui_level 2 → 3 · 승급 마법사 1장

⑤ 부르는 이름

화면에는 숫자를 쓰지 않습니다

"1단계"는 내 보드가 아직 모자라다는 말로 읽힙니다. 숫자는 저장값(ui_level)과 문서에만 두고, 화면에는 상태 이름만 보여줍니다.

보드 ui_level = 1

같이 쓰는 할 일 판. 카드를 적고, 나눠 맡고, 하나씩 지웁니다. 기능이 잠긴 칸반이 아니라 그 자체로 완결된 도구입니다.

주기 ui_level = 2

이번 주에 할 것만 골라 담고, 못 끝낸 건 다음 주기로 넘깁니다. 마감이 처음으로 의미를 갖습니다.

로드맵 ui_level = 3

주기 여러 개를 단계로 묶어 분기·런칭 단위로 봅니다. 간트와 이력이 여기서 제 값을 합니다.

⑥ 저장

사다리 하나, 스위치 하나

boards — 성격이 다른 두 값을 한 컬럼에 섞지 않는다
-- 사다리: 시간 묶음 깊이. 1 → 2 → 3 순서가 있고, 오를 때 마법사가 붙는다.
ALTER TABLE boards ADD COLUMN ui_level SMALLINT NOT NULL DEFAULT 3;
ALTER TABLE boards ADD CONSTRAINT ck_boards_ui_level CHECK (ui_level BETWEEN 1 AND 3);

-- 스위치: 순서가 없고, 켜도 정리할 게 없다. 쉼표 구분 키 집합.
ALTER TABLE boards ADD COLUMN ui_options TEXT NOT NULL DEFAULT '';
--   members · timeblock · review · jira

-- 기존 보드는 지금 화면 그대로 — 최고 레벨 + 전 옵션 백필.
UPDATE boards SET ui_level = 3, ui_options = 'members,timeblock,review,jira';

마일스톤 데이터는 이미 있습니다. 보드 생성 시 기본 마일스톤이 자동으로 만들어지므로, 보드·주기 상태에서는 그 한 행을 말없이 쓰고 화면에서만 숨깁니다. 로드맵으로 오를 때 이름을 붙이고 쪼개면 — 스키마 변경 없이 승급이 끝납니다. 내려간 뒤 다시 오르면 마법사를 다시 돌리지 않고 이전 구조를 그대로 복원합니다.

Milkyway · 레벨 모델 완성 목업 — 사다리(ui_level) + 스위치(ui_options) / 승급 마법사 / 트리거 유령 / 이름 체계
