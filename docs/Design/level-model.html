Milkyway · 레벨 모델 정밀 정의

단계를 가르는 축은 하나다 —
시간을 몇 겹으로 묶는가.

세 단계 모두 여러 사람이 같이 쓰는 도구이고, 묶음 · 작업 · 할 일은 전부 그대로 씁니다. 달라지는 건 그 위를 시간으로 몇 겹 감싸느냐뿐입니다 — 안 감싸거나(1) · 주기로 한 겹(2) · 단계로 두 겹(3).

정정

이전 안은 두 축을 섞고 있었습니다

이전 설계의 오류

구성원 뷰·시간 블록·JIRA를 3단계에 넣은 것

이전

1단계 = 혼자 쓰는 단순 목록, 3단계 = 여럿이 쓰는 로드맵. 사람 수와 시간 깊이를 한 축에 얹었습니다.

수정

1단계도 여럿이 씁니다. 구성원 뷰는 1단계부터 켤 수 있는 옵션이고, 레벨 축과 무관합니다.

레벨은 순서가 있는 사다리입니다 — 주기 없이 단계만 쓸 수는 없습니다. 반면 구성원 뷰·개인 시간 블록·JIRA는 순서 없는 켜기/끄기입니다. 성격이 다른 둘을 한 값에 담으면 "2.5단계" 같은 게 생깁니다. 그래서 저장도 둘로 나눕니다(맨 아래 스키마).

두 번째 오류

1단계에서 In Review · Done 컬럼을 빠뜨린 것

이전 목업

1단계 = 묶음 컬럼만. 체크가 다 된 카드도 같은 자리에 남아 컬럼이 계속 길어지고, "내 손 떠났으니 봐달라"를 말할 자리가 없었습니다.

수정

흐름 컬럼은 1단계부터 있습니다. 실제 코드도 그렇습니다 — 묶음/구성원 컬럼은 START 컬럼을 쪼갠 것이고, In Review·Done은 그 옆에 그대로 유지됩니다.

레벨이 움직이는 축은 "언제" 하나뿐입니다. "어디까지 왔나"는 시간과 독립된 축이라 주기가 없어도 필요합니다 — 일은 마감이 없어도 흐릅니다. 이 축은 세 레벨 모두 같습니다.

공통 바닥

세 단계가 똑같이 쓰는 것

이건 레벨과 무관하게 항상 있습니다. 1단계에서도 팀이 같이 씁니다.

① 구조 — 묶음 ▸ 작업 ▸ 할 일, 그리고 사람

묶음Feature ▸ 작업Task · 카드 ▸ 할 일Checklist · 담당자

담당자는 할 일 한 줄에 붙습니다 — 1단계에서도 그렇습니다. 한 작업을 여러 명이 나눠 미는 게 기본이고, 그래서 구성원별 보기가 1단계에서도 의미가 있습니다.

② 흐름 — 진행 ▸ 리뷰 ▸ 완료

진행묶음 · 구성원 컬럼 ▸ 리뷰In Review · 끌 수 있음 ▸ 완료Done · 못 끔

보드 한 줄은 묶음 컬럼들 + 리뷰 + 완료입니다. 앞쪽은 그룹 기준(묶음/구성원)에 따라 쪼개지고, 뒤의 둘은 항상 그대로입니다. 끝난 일이 갈 곳이 없으면 컬럼이 무한정 길어지므로 완료 컬럼은 끌 수 없습니다. 리뷰를 안 쓰는 팀은 꺼서 진행 → 완료 두 칸으로 씁니다.

①과 ②는 레벨과 무관합니다. 레벨이 바꾸는 건 이 위에 시간을 몇 겹 감싸느냐뿐입니다.

레벨

세 단계 — 눌러서 같은 데이터가 어떻게 재구성되는지 보세요

작업 6장, 사람 4명, 할 일 12줄. 데이터는 하나도 안 바뀝니다. 시간을 감싸는 겹만 달라집니다.

승급의 순간

올라갈 때 기존 데이터를 어떻게 옮기는가

레벨을 올리는 건 스위치가 아니라 정리 작업입니다. 지금 있는 카드와 주기를 새 구조에 넣어줘야 하고, 그걸 사용자가 눈으로 보고 정해야 합니다.

내려갈 때

강등은 숨기기일 뿐, 아무것도 지우지 않습니다

3 → 2 단계 탭이 사라지고 주기 목록만 남습니다. 마일스톤 행은 그대로 있고 다시 켜면 돌아옵니다.
2 → 1 백로그와 담긴 것의 구분이 사라지고 모든 카드가 한 판에 나옵니다. 지난 주기 기록은 보존됩니다.
내려간 뒤 다시 올라가면 승급 마법사를 다시 돌리지 않습니다 — 이전 구조를 그대로 복원합니다.

저장

컬럼 두 개 — 사다리와 스위치를 나눕니다

boards
-- 사다리: 시간 묶음 깊이. 1 → 2 → 3 순서가 있고 건너뛸 수 없다.
ALTER TABLE boards ADD COLUMN ui_level SMALLINT NOT NULL DEFAULT 3;
ALTER TABLE boards ADD CONSTRAINT ck_boards_ui_level CHECK (ui_level BETWEEN 1 AND 3);

-- 스위치: 레벨과 무관한 옵션 집합. 쉼표 구분.
ALTER TABLE boards ADD COLUMN ui_options TEXT NOT NULL DEFAULT '';
--   members · timeblock · review · jira

-- 기존 보드는 지금 화면 그대로 — 최고 레벨 + 전 옵션.
UPDATE boards SET ui_level = 3, ui_options = 'members,timeblock,review,jira';

왜 하나로 안 합치나. 레벨은 순서가 있어서 "다음 단계로"가 성립하고, 승급할 때 데이터 정리가 따라옵니다. 옵션은 순서가 없고 켜도 정리할 게 없습니다. 승급 마법사가 붙느냐 안 붙느냐가 갈리기 때문에 같은 값에 담으면 코드가 계속 둘을 구분하게 됩니다.

마일스톤 데이터는 어떻게 되나. 이미 milestones 테이블이 있고 보드 생성 시 기본 마일스톤이 자동으로 만들어집니다. 1·2단계에서는 그 기본 마일스톤 하나를 말없이 계속 쓰고, 화면에만 안 보입니다. 3단계로 올라가면 그때 이름을 붙이고 쪼갭니다 — 스키마 변경 없이 승급이 됩니다.
