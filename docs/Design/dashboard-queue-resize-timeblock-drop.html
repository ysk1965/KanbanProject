배분은 내가 정하고,
미배치는 타임블록에 바로 꽂는다

대시보드의 배분은 지금 왼쪽 열 380px · 간트 344px로 코드에 못 박혀 있다. 두 경계를 손잡이로 만들어 조절하고 브라우저에 저장한다. 그리고 미배치 행을 오른쪽 큐에서 왼쪽 타임블록의 시간대로 끌어다 놓으면 그 시각에 블록이 생기고, 같은 동작으로 그날 워크로드에도 배치된다 — 한 번의 드롭이 "언제 할지"와 "몇 시에 할지"를 동시에 정한다.

Frontend only API 변경 없음 제안 A · 스플리터 2개 제안 B · 크로스 존 드롭 구현 완료

01지금 무엇이 막혀 있나

두 요청은 뿌리가 같다 — 대시보드의 세로 공간과 가로 이동이 둘 다 코드에 고정돼 있다.

1

배분이 전부 상수다 — 세로도, 가로도

WORKLOAD_CARD_HEIGHT = 344는 "담당자 행 3레인까지는 안 잘리게", 왼쪽 열 380px는 "타임블록 카드가 두 줄을 안 자르게"라는 근거로 정한 값이다. 근거는 둘 다 타당하지만 그날의 상황은 반영하지 못한다. 바가 한 줄뿐인 날엔 간트가 빈 공간을 껴안고 있고, 미배치가 24건인 날엔 큐가 6~7행만 보여 준다(스크린샷의 상태다). 일정을 짜는 날엔 타임블록을 넓게, 배치를 도는 날엔 오른쪽을 넓게 보고 싶은데 그럴 방법이 없다.

인터랙션 사양 (두 손잡이 공통)

동작결과
포인터 드래그핸들을 잡고 끈다. 앞 칸 크기 = 시작크기 + Δ. 마우스·터치·펜 공통(pointer 이벤트 + touch-none).
드래그 중 표시핸들 바가 bridge-accent로 굵어지고, 커서는 row-resize / col-resize. 픽셀 배지는 띄우지 않는다(숫자는 의미가 없다).
더블클릭기본값으로 리셋 + 저장값 삭제.
키보드핸들에 tabIndex=0, role="separator". 세로는 ↑/↓·가로는 ←/→로 16px(Shift 48px), Home/End = 양 끝, Backspace = 리셋.
창 크기 변경ResizeObserver로 컨테이너를 보고 매번 다시 클램프한다. 저장값은 안 건드린다 — 큰 화면으로 돌아오면 원래 배분으로 복원된다.

저장 규약

키

bridge:dashboard:workloadHeight:v1 · bridge:dashboard:timeblockWidth:v1 — 보드·유저와 무관한 이 브라우저의 취향. 보드마다 다시 맞추게 하는 건 취향이 아니라 노동이다.

값

앞 칸 크기(px) 정수 하나씩. 비율(%)이 아니라 px인 이유 — 하한이 픽셀로 정해져 있고 뒤 칸은 남는 만큼 늘어나면 되기 때문.

쓰기 시점

pointerup / 키 조작 직후 한 번. 드래그 중에는 DOM에만 직접 쓰고 state·스토리지는 건드리지 않는다.

실패 안전

읽기·쓰기 모두 try/catch. 파싱 실패·범위 이탈·스토리지 차단(시크릿 모드) 시 조용히 기본값으로 간다.

성능 주의. 드래그 중 매 프레임 setState를 하면 간트(ScheduleResourceView)와 타임블록이 통째로 리렌더된다. 드래그 동안에는 DOM(높이 또는 CSS 변수)만 직접 쓰고, 손을 뗄 때 한 번 state에 커밋하며 그때 저장한다.

// components/boarddashboard/usePersistentSplit.ts (신규)

export function usePersistentSplit({
  storageKey, axis, defaultSize, minSize, minOtherSize, handleSize,
  applyDragSize,   // 그리드처럼 크기가 부모에 적혀 있을 때 CSS 변수를 대신 쓴다
  containerRef,    // 컨테이너를 밖에서 들고 있을 때 (가로 축 = 그리드 자신)
}: PersistentSplitOptions) {
  const [stored, setStored] = useState(() => readStored(storageKey) ?? defaultSize);
  const [maxSize, setMaxSize] = useState(Infinity);

  // 창이 줄면 상한도 줄어든다 — 저장값은 유지하고 화면에만 클램프를 건다
  useEffect(() => { … ResizeObserver → setMaxSize(total - minOtherSize - handleSize) … }, [...]);

  const clamp = (v) => Math.round(Math.min(Math.max(v, minSize), maxSize));
  const size  = clamp(stored);   // 렌더에 쓰는 값 (저장값 ≠ 표시값일 수 있다)

  const onPointerDown = (e) => {
    const start = axis === "x" ? e.clientX : e.clientY, startSize = size;
    document.body.style.cursor = axis === "x" ? "col-resize" : "row-resize";
    const move = (ev) => {
      const px = clamp(startSize + ((axis === "x" ? ev.clientX : ev.clientY) - start));
      // 드래그 중에는 DOM만 만진다 — 매 프레임 리렌더시키지 않는다
      if (applyDragSize) applyDragSize(px);
      else paneRef.current.style[axis === "x" ? "width" : "height"] = `${px}px`;
    };
    const up = (ev) => { commit(…); /* 여기서 한 번만 저장 */ };
    … window pointermove / pointerup / pointercancel …
  };

  return { containerRef, paneRef, size, maxSize, onPointerDown, onKeyDown, reset };
}

드롭 한 번이 하는 세 가지

타임블록 생성 — scheduleAPI.createBlock

놓은 칸이 시작 시각, 기본 길이 1시간(30분 슬롯 2칸). 기존 블록·점심시간은 이미 있는 computeSegments()가 피하고 잘라 준다 — 빈 곳 드래그로 만들 때와 완전히 같은 규칙이다.

그날 워크로드에 배치 — checklistAPI.patchItem

due_date = 드롭한 날짜, start_date는 이미 더 이른 날이면 살리고 아니면 같은 날. 기존 placeItem()을 그대로 재사용하므로 되돌리기 안내까지 공짜로 따라온다. 이게 "미배치 24 → 23"과 간트에 바가 생기는 이유다.

오늘의 체크리스트에 추가 — dailyChecklistAPI.addItem

모달 경로(handleBoardChecklistItemSelect)와 동일하게 맞춘다. 대시보드 위젯은 hideDailyChecklist라 눈에 안 보이지만, 일정 탭에서 열면 같은 항목이 같은 자리에 있어야 하기 때문이다.

존 계약을 한 칸 넓힌다

axisTransfer는 "떨어졌다"만 알리고 실제 변경은 항목을 들고 있는 쪽이 한다는 규칙으로 돌아간다. 이 규칙을 깨지 않으면서 타임블록을 넣으려면 존 하나와 필드 하나만 더 있으면 된다.

const DROP_SLOTS = 2;   // 30분 슬롯 2칸 = 기본 1시간

const handleSlotDrop = async (e, userId, slotIndex) => {
  const raw = e.dataTransfer.getData(PLACEMENT_DRAG_TYPE);
  if (!raw || isViewer) return;              // 백로그 카드는 이 키가 없어 자동으로 걸러진다
  e.preventDefault(); e.stopPropagation();
  const item = JSON.parse(raw);
  const dateStr = format(selectedDate, "yyyy-MM-dd");   // 오늘이 아니라 "보고 있는 날"

  const segments = computeSegments(
    userId, timeSlots[slotIndex],
    timeSlots[slotIndex + DROP_SLOTS] ?? `${workEndHour}:00`,
  );
  if (!segments) { setDropError(t("schedule.dropNoRoom", "그 시간에 빈자리가 없습니다.")); return; }

  try {
    await dailyChecklistAPI.addItem(boardId, {
      checklist_item_id: item.id, assignee_id: userId, assigned_date: dateStr,
    });
    for (const seg of segments) {
      await scheduleAPI.createBlock(boardId, {
        checklist_item_id: item.id, assignee_id: userId, scheduled_date: dateStr,
        start_time: seg.startTime, end_time: seg.endTime,
      });
    }
    // 여기서부터는 항목의 주인이 처리한다 — 날짜 배치 · 되돌리기 · 레일 갱신
    dispatchAxisDrop({ from: "placement", to: "timeblock", targetDate: dateStr, item });
    await loadSchedule();
  } catch (err) {
    console.warn("DailyScheduleView: failed to drop placement item", err);
    setDropError(t("schedule.dropFailed", "타임블록에 넣지 못했습니다."));
  } finally { setDropPreview(null); endAxisDrag(); }
};

  if (!canEdit || !detail.item.task_id) return;

  if (detail.from === "placement" && detail.to === "timeblock" && detail.targetDate) {
    void placeItem({ …detail.item }, detail.targetDate);   // 되돌리기 안내 · 레일 갱신 포함
    return;
  }

  if (detail.from === "workload" && detail.to === "placement") { void unscheduleItem(…); }
});

블록 위에 떨어뜨리면? 스케줄 블록 레이어는 pointer-events가 살아 있어 드래그오버를 가로챈다. 미배치 드래그가 진행 중일 때만 블록 레이어에 pointer-events-none을 걸어 아래 시간 칸이 받게 한다 (그러면 computeSegments가 겹치는 시간을 알아서 피해 준다).

드래그 중 미리보기. 드롭될 1시간 구간을 점선 고스트로 그린다(dropPreview state). 지금 빈 곳 드래그가 bg-bridge-secondary/20으로 선택 범위를 칠하는 것과 같은 자리에 얹으면 되고, 잔상 칩은 setAxisDragGhost가 이미 만들어 준다.

드래그를 못 쓰는 환경

미배치 행에는 이미 「오늘」「내일」「백로그」 버튼이 있다. 여기에 「지금」을 더한다 — 현재 시각 이후 첫 30분 경계부터 1시간, 같은 dispatchAxisDrop 경로를 태운다. 터치·키보드 사용자와 드래그 사용자가 같은 코드로 같은 결과를 얻는다.

05엣지 케이스 · 권한

상황처리
남의 대시보드(?scope=)부모가 currentUserRole을 viewer로 낮춰 보낸다 → 드롭 차단(isViewer). 높이 조절은 허용 — 내 화면의 취향이지 남의 데이터가 아니다.
보드 뷰어 역할드롭·「지금」 모두 비활성. 미배치 행 자체가 draggable=false다.
오늘이 아닌 날을 보는 중보고 있는 selectedDate에 블록이 생기고 그 날짜로 배치된다. "오늘"로 강제하지 않는다.
점심시간에 걸침1시간 구간이 점심을 가로지르면 computeSegments가 앞뒤로 쪼개 블록 2개를 만든다(기존 동작과 동일).
점심 칸에 직접 드롭빈 곳 드래그로도 못 만드는 자리다 — 하이라이트를 켜지 않고, 떨어져도 안내만 띄우고 만들지 않는다.
그 시간이 꽉 참10분 미만만 남으면 null → 만들지 않고 안내만. 날짜도 안 바뀐다.
백로그 카드를 타임블록에백로그는 아직 태스크가 아니라 PLACEMENT_DRAG_TYPE을 싣지 않는다 → 자동 거부. 승격이 먼저다.
되돌리기현재 되돌리기는 날짜만 되돌린다. 만들어진 블록은 남는다 → 안내 문구를 "일정에 배치됨 · 타임블록도 생성"으로 구분하고, 블록 삭제까지 원하면 createdBlockIds를 안내에 실어 deleteBlock을 함께 태운다(권장·별도 커밋).
「지금」인데 다른 날을 보는 중오늘로 옮긴 뒤, 오늘 데이터가 실제로 도착한 다음 만든다(loadedDate로 판정). 화면에 어제 블록이 실린 채 겹침을 판정하면 블록이 겹친다. 15초 안에 못 오면 요청을 버린다.
저장값 > 화면 크기작은 화면에서 표시만 클램프하고 저장값은 유지 → 큰 화면으로 돌아가면 복원된다.
localStorage 차단읽기/쓰기 전부 try/catch. 조절은 되고 저장만 안 된다.

React #310 주의. MyWorkloadWidget은 myMembers.length === 0 분기가 렌더 안에 있고 DailyScheduleView는 훅이 많다. 새 훅·useCallback은 반드시 early return 위에 선언한다(CLAUDE.md 규칙).

06검증 체크리스트

  • cd frontend && npm run build — 빌드·타입 통과 (확인함)
  • 세로 핸들을 위/아래로 끌면 큐/간트가 각각 자라고, 하한에서 더는 안 줄어든다
  • 가로 핸들을 좌/우로 끌면 타임블록 열이 넓어지고 워크로드 열이 줄어든다
  • 새로고침 후에도 두 배분이 유지된다 · 다른 보드에서도 같은 배분이다
  • 더블클릭으로 기본값(344 / 380) 복귀 · 저장 키가 지워진다
  • 창을 줄였다 늘리면 클램프됐다가 원래 배분으로 돌아온다
  • 창을 xl 미만으로 줄이면 두 열이 한 줄로 접히고 가로 핸들이 사라진다
  • Tab으로 핸들에 포커스 → 세로는 ↑/↓, 가로는 ←/→로 조절되고 포커스 링이 보인다
  • 미배치 행을 타임블록 빈 시간에 드롭 → 1시간 블록 생성 · 미배치 카운트 −1 · 간트에 그날 바 생성
  • 드래그 중 그리드가 위아래로 밀리지 않는다(안내 줄이 끼어들지 않아야 한다)
  • 점심시간을 가로지르게 드롭 → 블록 2개로 쪼개진다 · 점심 칸 자체에는 안 들어간다
  • 기존 블록 위에 드롭 → 겹치지 않는 빈 시간으로 들어가거나 안내가 뜬다
  • 날짜를 내일로 넘긴 뒤 드롭 → 내일 블록 · 내일 배치
  • 「지금」 버튼 → 오늘로 이동한 뒤 현재 시각부터 블록 생성 (터치·키보드 경로)
  • ?scope=로 남의 대시보드를 열면 드롭이 안 되고, 배분 조절은 된다
  • 일정 탭 타임블록(임베드 아님)에서 기존 빈 곳 드래그 생성이 그대로 동작한다
  • 라이트 모드에서 핸들·드롭 하이라이트 대비가 유지된다

실행 검증은 아직이다. 위 목록에서 빌드 항목만 확인했다 — 로컬 백엔드(:8080)·프론트(:5173)가 떠 있지 않아 화면에서 끌어 보지 못했다. 나머지는 앱을 띄운 뒤 확인이 필요하다.

오늘의 체크리스트에도 추가

모달 경로와 같은 취급. 다만 이미 올라가 있어 실패해도 삼킨다 — 이 드롭의 본질은 블록이기 때문.

만들면서 바뀐 것

  • 드래그 중 안내 줄을 뺐다. 줄이 하나 생기면 그리드가 그만큼 내려가 커서 밑의 시간 칸이 통째로 바뀐다. "놓을 수 있다"는 칸 하이라이트가, "무슨 일이 일어나는지"는 배치 레일 문구가 말한다.
  • 훅을 축 공용으로 합쳤다. 가로 배분 요청이 붙으면서 세로 전용 훅을 usePersistentSplit으로 일반화했다.
  • 「지금」에 loadedDate 관문을 붙였다. 날짜를 옮긴 직후에는 selectedDate가 이미 오늘이어도 화면에 실린 블록은 아직 어제 것이라, 그걸로 겹침을 판정하면 블록이 겹친다.
  • 점심 칸은 받지 않는다. 빈 곳 드래그로도 못 만드는 자리라 하이라이트도 켜지 않는다.
