BRIDGE · Milestone Console

피쳐 필터, 칩에서 탭으로

마일스톤 관리 콘솔의 피쳐 선택 UI를 on/off 칩에서 단일 선택 언더라인 탭으로 전환한다. 선택은 "필터를 켠다"가 아니라 "이 화면의 스코프를 정한다"이기 때문이다. 다중 선택을 없애면서 "피쳐" 라벨과 모두/해제 버튼도 함께 제거한다 — 탭은 언제나 정확히 하나가 선택되어 있다. 인라인 피쳐 추가(＋)는 유지한다.

2026-08-10 · 대상: frontend/src/app/components/MilestoneConsoleModal.tsx (859–971행 피쳐 칩 영역)

01현재 UI와 문제 진단

현재 구현을 그대로 재현한 목업. 칩을 클릭해 켜고 꺼 보면 문제가 바로 보인다.

Before 현재
피쳐
칩 클릭 = 토글 (인터랙티브 목업)

스코프가 필터처럼 읽힌다

체크박스 아이콘 + pill 형태는 바로 위 필터 행(지연만·미배정·완료)과 같은 문법이다. 하지만 피쳐 선택은 필터가 아니라 아래 보드 전체의 범위를 정하는 상위 결정이라, 위계가 구분되지 않는다.

켜질수록 시끄러워진다

선택 상태가 피쳐 색 배경 전체 채움이라, 기본 동작(전체 선택)만으로 헤더가 알록달록해진다. 정작 중요한 진행률 숫자는 색 배경 위에서 대비가 떨어진다.

기본 상태가 가장 나쁜 상태

최초 로드 시 전체 선택인데, 이는 곧 모든 칩이 최대 채도로 켜진 화면이 기본 화면이라는 뜻이다. 강조는 예외 상태여야 하는데 현재는 상시 상태다.

보드와의 연결이 약하다

둥근 칩은 공중에 떠 있는 개별 토큰처럼 보인다. 선택 결과가 바로 아래 보드에 반영된다는 "이 행이 아래 내용을 지배한다"는 관계가 형태로 드러나지 않는다.

02개선 방향: 단일 선택 언더라인 탭

탭 행을 하단 보더에 앵커하고, 선택 상태를 배경 채움 대신 피쳐 색 언더라인 + 텍스트 강조로 표현한다. 피쳐 색은 상시 노출되는 8px 도트로 축소해 색상 소음을 없앤다. 클릭하면 그 피쳐 하나만 선택된다 — "피쳐" 라벨, 모두/해제 버튼은 존재 이유가 사라지므로 제거한다.

After 개선안
탭 클릭 = 해당 피쳐만 선택 · 완료된 피쳐(17/17)는 카운트가 틸 색으로 표시

탭 문법 = 스코프 문법

보더에 붙은 탭은 "지금 보고 있는 것"을 뜻하는 보편 문법이다. 위 필터 행(pill)과 형태가 달라져 필터 ↔ 스코프의 위계가 한눈에 갈린다.

색은 식별자로만

피쳐 색은 도트와 2px 언더라인에만 쓴다. 전체 선택 상태에서도 화면이 조용하고, 텍스트·진행률은 항상 foreground 대비를 유지한다.

빈 상태가 사라진다

단일 선택 탭은 언제나 하나가 선택되어 있다. "칩을 하나 이상 선택하세요" 빈 화면이 구조적으로 불가능해지고, 최초 로드도 첫 피쳐 자동 선택으로 바로 보드를 보여준다.

완료 상태가 공짜로 생긴다

배경색에서 해방된 카운트에 의미를 실을 수 있다. done === total이면 카운트를 틸로 — 런칭 체크 콘솔에서 가장 보고 싶은 신호다.
