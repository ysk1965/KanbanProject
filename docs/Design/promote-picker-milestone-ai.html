설계 근거
결정이유
칩이 아니라 셀렉트마일스톤은 보통 2~6개고 피처보다 상위다. 칩 두 줄을 쌓으면 목록 높이가 줄어든다. 상위 축은 1줄 셀렉트, 하위 축(피처)만 칩.
기본값 = 보드의 선택 마일스톤BoardDetail.selected_milestone_id를 그대로 초기값으로 쓴다. 보드에서 보고 있던 스프린트 = 승격하려는 맥락. 없으면 오늘이 기간에 든 마일스톤, 그것도 없으면 전체.
피처 칩이 종속된다마일스톤을 고르면 그 마일스톤 태스크가 실제로 존재하는 피처만 칩으로 남는다. 20~30개 칩이 3~5개로 줄어 가로 스크롤이 사라진다.
칩·옵션에 개수 표기눌러 보기 전에 결과 크기를 안다. 0건 칩은 아예 렌더하지 않는다(빈 결과로 가는 클릭을 없앤다).
"마일스톤 없음" 옵션백로그 정리 중 가장 자주 찾게 되는 묶음. 서버도 milestoneId=none을 이미 지원한다(TaskService.java:110).
검색은 필터를 뚫는다검색어를 치면 마일스톤/피처 필터를 무시하고 보드 전체에서 찾되, 필터 밖 결과에는 다른 마일스톤 뱃지를 붙인다. "필터 때문에 안 나오는" 상황을 만들지 않는다.

구현 비용이 거의 0인 이유

  • 서버는 이미 내려주고 있다. TaskResponse.java:27,54가 milestoneId를 담아 응답한다 → JSON milestone_id. FE 인터페이스에 milestone_id?: string | null 한 줄만 추가하면 이미 불러온 목록을 클라이언트에서 즉시 필터할 수 있다. 마일스톤을 바꿔도 재요청이 없다.
  • 마일스톤 목록도 이미 있다. DashboardView가 milestones: Milestone[]를 들고 있고 buildMilestoneColorMap으로 색까지 만든다. BacklogRail → PromoteBacklogModal로 prop 하나 더 내리면 끝. 추가 네트워크 호출 없음.
  • 색은 resolveMilestoneColor(id, map)를 그대로 써서 보드/간트와 같은 색을 유지한다.

3. AI 후보 추천

규칙으로 좁히고 AI가 고른다
동작
항목내용
노출 위치목록 최상단 고정 섹션. 접기 가능하고 접힘 상태는 localStorage에 기억(이미 promoteRecent에서 쓰는 방식).
호출 시점모달 열림 즉시 자동 호출하지 않는다. 규칙 기반 3개를 먼저 0원으로 보여주고, ✨ AI로 다시 추천을 누를 때만 크레딧 1을 쓴다. 열기만 해도 크레딧이 빠지는 건 백로그 정리처럼 반복 작업에서 최악이다.
후보 수3개. 4개 이상은 "고르는 일"이 또 생긴다.
이유 한 줄추천은 근거가 없으면 신뢰받지 못한다. 30자 이내로 왜를 붙인다(키워드 일치 / 같은 담당 / 최근에 붙인 곳 / 같은 마일스톤).
선택 동작클릭 = 아래 목록에서 선택된 것과 동일한 상태. 목록에서도 해당 행이 하이라이트되어 어디에 붙는지 위치를 확인할 수 있다.
캐시(백로그 항목 id + 대상 + 마일스톤) 해시로 24h 캐시. 같은 조합 재호출은 크레딧 0. 모달을 닫았다 다시 열어도 재과금되지 않는다.
실패·크레딧 소진402면 전역 ai-credits-exhausted 모달을 띄우지 않는다. 승격이라는 본 작업을 가로막기 때문. 인라인으로 규칙 추천 뱃지로 되돌리고 안내 한 줄만 남긴다.
마일스톤 연동현재 선택된 마일스톤이 있으면 후보 풀을 그 안으로 제한한다. 사용자가 이미 좁혀 놓은 맥락을 AI가 무시하면 추천이 튄다.
랭킹 파이프라인
STEP 1 · 규칙 프리스코어 (서버, 무료)

후보 태스크 전체에 가중합 점수를 매겨 상위 25개만 남긴다.
제목 토큰 겹침(자카드) ×3 · 대괄호 태그 일치([네트워크]) ×2.5 · 내가 담당 ×1.5 · 최근에 붙인 곳 ×1.5 · 같은 마일스톤 ×1 · 미완료 ×1 · 최근 수정 ×0.5

STEP 2 · LLM 선별 (크레딧 1)

25개의 요약만 넣는다(id·제목·피처·담당·진행률). 설명 본문은 넣지 않는다 — 토큰이 튀고 정확도는 안 오른다.
출력은 { ref_id, reason } 3개 JSON. 자유 서술 금지.

STEP 3 · 폴백

LLM 실패·타임아웃(3s)·크레딧 부족이면 STEP 1의 상위 3개를 source: "RULE"로 반환. 추천 섹션은 어떤 경우에도 비지 않는다. 

// 신규 엔드포인트 1개. 마이그레이션 없음.
// 백로그 항목은 개인 데이터라 보드가 아니라 /personal/tasks 아래에 붙는다

POST /api/v1/personal/tasks/{taskId}/promote-suggestions

// request
{ "target": "CHECKLIST_ITEM",      // | "TASK" (TIMEBLOCK은 400)
  "milestone_id": "ms_2월CBT",      // null = 전체, "none" = 미배정
  "include_done": false,           // 모달의 "완료 포함"과 같은 값
  "use_ai": true,                   // false면 규칙만, 크레딧 0
  "recent_ref_ids": ["tsk_..."],    // 최근에 붙인 곳 (localStorage)

4. 행 압축

제목이 먼저 보이게
현재문제개선
제목 1줄 truncate 고르는 기준인 제목이 잘리는데 메타는 다 보인다. QA 티켓처럼 [태그] 긴 문장 형태면 잘린 뒤쪽에 핵심이 있다. 제목 최대 2줄까지 wrap(line-clamp-2), 나머지 메타를 줄여 확보한 높이로 상쇄.
메타 5종 나열
피처 · 블록 · 담당 · D-day · 체크수		 모두 같은 크기·같은 색이라 눈이 멈출 곳이 없다. 피처는 이미 섹션 헤더에 있는데 행마다 반복된다. 섹션이 피처별로 묶여 있으면 행에서 피처명 제거(중복). 블록 뱃지는 할 일 / 작업 완료처럼 상태가 다를 때만.
체크 0/1 텍스트 "이 태스크에 얼마나 붙어 있나"가 승격 판단에 중요한데 숫자만 있어 한눈에 안 들어온다. 미니 진행 바 + 숫자. 8/9처럼 거의 찬 태스크는 바로 보인다.
"내 태스크 20" 단일 덩어리 정렬이 아니라 그냥 통. 20개를 다 읽어야 한다. 마일스톤 필터로 실질 개수를 줄이고, 그 안에서 피처별 섹션으로 나눈다. 기존 최근에 붙인 곳 섹션은 그대로 최상단 유지.
정렬 고정 마감 임박 순으로 보고 싶을 때가 있다. 정렬 토글 3종: 관련도(기본) · 마감 임박 · 최근 수정. 검색 중에는 관련도 고정.

6. 엣지 케이스 · 접근성

상황처리
마일스톤이 0~1개인 보드셀렉트를 렌더하지 않는다. 지금과 동일한 화면 → 회귀 없음. (피처 칩도 features.length > 1일 때만 뜨는 기존 규칙과 같은 결)
선택 마일스톤에 태스크 0건"이 마일스톤에 태스크가 없습니다 · 전체 보기" 버튼 — 빈 화면에서 탈출로를 준다.
태스크 탭(피처 고르기)같은 마일스톤 필터를 피처 목록에도 적용. Milestone.features에 소속 피처가 이미 들어 있어 추가 호출 불필요.
AI 추천이 이미 선택된 것과 같음중복 표시 대신 추천 카드에 선택됨 표기.
추천 후보가 완료 태스크기본 제외. 완료 포함이 켜져 있을 때만 후보 풀에 넣는다.

확정된 결정 (구현 반영됨)

  • AI 자동 호출 안 함 — 열자마자는 규칙 추천(무료)만 뜨고, ✨ AI로 추천 · 크레딧 1 버튼을 눌러야 크레딧을 씁니다. 백로그 10개를 정리할 때 크레딧 10이 나가는 걸 막기 위해서입니다. 같은 (항목·대상·마일스톤·완료포함) 조합은 24h 캐시라 다시 열어도 0입니다.
  • 기본 마일스톤 = 보드의 선택 마일스톤 — kanbanSelectedMilestoneId를 그대로 물려받습니다("all"은 전체로 변환). 승격도 보드를 보던 맥락에서 일어나기 때문입니다.
  • 추천은 두 탭 모두 — 같은 엔드포인트가 target에 따라 태스크/피처 후보를 돌려주므로 분기 비용이 없었습니다. 대신 정렬 토글은 태스크 탭에만 뒀습니다(피처는 몇 개 되지 않아 정렬할 것이 없습니다).

구현 결과와 제안서의 차이

  • 엔드포인트 경로 — 백로그 항목은 개인 데이터라 보드 하위가 아니라 POST /api/v1/personal/tasks/{taskId}/promote-suggestions에 붙였습니다(기존 /promote와 같은 자리). 보드는 항목의 board_id로 서버가 찾습니다.
  • 추천 이유의 언어 — 규칙 추천은 서버가 문구를 만들지 않고 reason_code만 내려주고, 프런트가 i18n으로 그립니다. 서버가 한국어 문장을 박으면 10개 로케일에서 그대로 샙니다. AI 추천만 문장을 그대로 씁니다.
  • 피처의 마일스톤 소속 — 보드 칸반과 같은 규칙을 그대로 씁니다: 태스크가 배정된 마일스톤이 우선이고, 태스크 배정이 하나도 없는 피처만 마일스톤 멤버십으로 폴백합니다. 그래서 모달이 두 탭 모두에서 태스크 목록을 한 번 읽습니다(요청 1건, 기존과 동일).
  • 검색은 필터를 뚫습니다 — 검색 중에는 마일스톤·피처 필터를 무시하고 보드 전체에서 찾되, 필터 밖 결과에 다른 마일스톤 뱃지를 붙입니다.
