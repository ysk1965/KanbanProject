마일스톤 관리 팝업
개념 정합성 · 레이아웃 개선 분석서

"피처가 핵심이고, 마일스톤은 피처 안의 태스크 단위로 나뉘어 하나의 피처가 여러 마일스톤에 중복으로 들어갈 수 있다" — 이 모델은 강력하지만, 현재 UI는 피처 단위 할당과 태스크 단위 할당이라는 두 개의 정신 모델이 겹쳐 있어 혼란을 만듭니다. 이 문서는 혼란의 근원을 진단하고, 태스크 단위 진실을 그대로 드러내는 방향으로 재설계안을 제안합니다.

Diagnosis

2혼란의 근원 6가지

"레이아웃이 애매하다"는 체감의 실제 원인은 대부분 개념 모델의 이중성에서 비롯됩니다. 시각적 문제와 구조적 문제를 분리해 짚습니다.

구조 · 핵심

① 두 개의 배정 모델이 겹친다

같은 관계를 피처 링크(체크박스)와 태스크 배정(milestone_id) 두 곳에서 관리합니다. 모달에서 피처를 체크하면 그 피처의 태스크들에 어떤 일이 일어나는지 예측이 안 됩니다.

예: 마일스톤에서 피처 링크를 해제하면 → 그 피처의 해당 마일스톤 태스크가 orphan 처리됨. 사용자는 체크 하나 껐을 뿐인데 태스크 배정이 사라짐.
개념 · 인지부하

② "대표 / 이어짐" 개념의 부담

피처가 여러 마일스톤에 걸치니 어느 하나를 "대표(primary)"로 정해야 합니다. 사용자는 이 개념을 배워야 하고, "대표로 지정"이 무엇을 바꾸는지 불명확합니다(사실상 타임라인 바 스타일 + 소유 마일스톤).

"대표"를 바꿔도 태스크 배정·진행률은 그대로. 기능적 효과가 거의 없는데 UI 노출 비중은 큼.
데이터 · 불일치 체감

③ 같은 피처, 다른 진행률

피처 카드가 마일스톤마다 복제되고, 각기 마일스톤 범위 진행률을 보여줍니다. 칸반에서 보던 그 피처의 전체 진행률과 숫자가 안 맞아 "어느 게 맞지?" 하게 됩니다.

피처 "결제연동": 마일스톤 A에서 2/3 (66%), 마일스톤 B에서 1/2 (50%), 칸반 카드에선 3/5 (60%). 셋 다 맞지만 설명이 없음.
구조 · 사각지대

④ 태스크 분리가 관리 UI에 없다

정작 "태스크 A→A, 태스크 B→B"라는 분리 결정을 관리 모달/뷰에서 할 수 없습니다. 각 태스크를 열어 드롭다운으로만 가능. 핵심 액션이 가장 깊은 곳에 숨어 있습니다.

피처를 두 마일스톤에 걸치려면 → 태스크를 하나씩 열어 배정. 관리 화면에선 "왜 이 피처가 두 곳에 있지?"만 보이고 조정 불가.
일관성

⑤ 3화면 3은유

모달=체크박스, 뷰=피처카드, 타임라인=간트바. 하나의 정신 모델로 이어지지 않아 화면을 옮길 때마다 재학습이 필요합니다.

모달에서 "링크"한 것이 뷰에서 "카드"로, 타임라인에서 "바"로 변신. 같은 행위의 결과인지 직관적으로 안 이어짐.
레이아웃 · 시각

⑥ 모달 우측 폼의 밀집

피처 링크 행 하나에 체크박스 + 색점 + 제목 + "대표" + "이어짐" + "대표로 지정" 버튼 + N개 카운트가 다 들어가 시각적으로 시끄럽습니다. 좌측 w-56 목록도 좁습니다.

한 행에 최대 6개 요소가 경합. 정작 중요한 "이 마일스톤에 무엇이 얼마나" 정보는 묻힘.
Principles

3재설계 원칙

모든 개선안은 아래 4가지 원칙을 만족해야 합니다.

원칙 1

태스크를 일급 시민으로

배정의 진실이 태스크라면, UI도 태스크를 직접 보여주고 조작하게 한다. 피처는 그룹 헤더로 강등하되 여전히 시각적 핵심.

원칙 2

"대표"에 진짜 역할을 준다

모호한 표시용 플래그였던 is_primary를 피처의 "기본 마일스톤"으로 재정의. 새 태스크가 이곳을 상속하고, 태스크별로 덮어쓰면 그게 곧 분리(split). 개념이 사라지는 대신 명확한 기능(=생성 마찰 제거)을 얻는다.

원칙 3

숫자에 스코프 라벨을

마일스톤 범위 진행률에는 항상 "이 마일스톤 기준" 맥락을 붙인다. 피처 전체 진행률과 나란히 보여 혼동을 없앤다.

원칙 4

하나의 은유로 통일

"마일스톤은 태스크에 붙는 기간 태그"라는 단일 은유. 관리·뷰·타임라인이 모두 이 문장에서 파생되게 한다.

Options

4개선 방향 3안

태스크 단위 진실을 유지한 채(사용자 의도 존중) 관리 UX를 정리하는 3가지 접근을 비교합니다.

A. 피처 그룹 + 태스크 배정

모달 재구성

모달 우측을 "피처 아코디언 → 태스크 행 + 마일스톤 칩" 구조로. 태스크를 직접 이 마일스톤에 넣고 뺀다.

+진실(태스크)을 그대로 조작
+"대표/이어짐" 제거 가능
−태스크 많으면 목록 길어짐
★ 추천

B. 매트릭스 + 태스크 배정

A안 + 피처×마일스톤 오버뷰

관리 진입 시 피처 × 마일스톤 매트릭스로 "무엇이 어디에 몇 개" 한눈에. 셀 클릭 → 그 교차점의 태스크 배정 패널.

+중복 배정을 한 장으로 이해
+A안의 태스크 조작 그대로 계승
+혼란 근원 ①③④를 동시 해결
−마일스톤 많으면 가로 스크롤

C. 칸반식 태스크 이동

마일스톤 = 컬럼

마일스톤을 컬럼으로 두고 태스크 카드를 드래그해 배정. "미배정" 컬럼 포함.

+드래그 직관성 최고
−피처 그룹핑이 약해짐
−미니칸반 뷰와 역할 중복
추천: B안 (매트릭스 + 태스크 배정) — "하나의 피처가 여러 마일스톤에 중복으로 들어가는" 바로 그 개념을 매트릭스 한 장으로 자연스럽게 보여주고, 셀을 열면 태스크 단위로 정확히 조정하게 합니다. 혼란의 근원 ①(이중 모델) ③(다른 진행률) ④(사각지대)를 동시에 해소합니다.

6생성 플로우 설계

매트릭스 모델의 진짜 강점은 생성이 곧 그리드에 즉시 보인다는 것 — 마일스톤을 만들면 새 컬럼이, 피처를 만들면 새 행이 생깁니다. 관건은 "새로 만든 뒤 태스크를 매번 일일이 배정해야 하나?"라는 마찰을 없애는 것입니다.

핵심 메커니즘

6-1. 마일스톤 생성 = 새 컬럼 채우기

빈 마일스톤은 쓸모가 없으므로, 생성 직후 자연스럽게 채우도록 유도하되 강제하지 않습니다. 마일스톤은 기간을 가지므로 이를 이용한 스마트 추천이 강력합니다.

1
최소 입력

제목 + 기간, 딱 2개

인라인 폼으로 제목·기간(범위 캘린더)만 받고 즉시 생성. 설명·연결은 나중에. 진입 장벽을 최소화.

2
즉시 가시화

매트릭스에 새 컬럼 등장 + 하이라이트

생성과 동시에 컬럼이 나타나고 해당 위치로 스크롤·강조(펄스). "무엇이 만들어졌는지" 즉각 인지.

3
스마트 채우기

기간이 겹치는 작업 자동 추천

빈 컬럼 empty-state에서 "기간(7/1~7/14)에 걸치는 태스크 N개 추천" → 체크해서 일괄 배정. 마일스톤 날짜 기반이라 정확도 높음.

4

6-2. 피처 생성 = 새 행 + 미배정 안전망

피처는 칸반 Feature 블록에서 태어납니다(기존 유지) — 마일스톤 매니저가 아닙니다. 따라서 새 피처의 태스크는 어딘가로 흘러가야 하고, 여기서 두 개의 편의 장치가 작동합니다.

장치 1

생성 시 "기본 마일스톤" 선택(옵션)

피처 생성/편집에 기본 마일스톤 필드를 둔다. 지정하면 이후 서브태스크가 자동 상속 → 매트릭스에서 그 셀이 대표(굵게)로 표시. 미지정도 허용.

장치 2

"미배정" 컬럼 = 놓친 일의 안전망

기본 마일스톤 없이 만든 피처의 태스크는 미배정에 모여 뱃지로 가시화. 일이 조용히 사라지지 않고, 나중에 배정하도록 드러난다.

  • 행 단위 원클릭 배정 — 새 행 헤더의 "미배정 N" 뱃지 옆에 "전체를 [마일스톤]에" 퀵액션. 공통 케이스(피처 하나 → 마일스톤 하나)를 한 번에.
  • 스마트 기본값 후보 — 보드에 활성 마일스톤(selectedMilestoneId)이 있으면 그것을, 없으면 피처 기간과 겹치는 마일스톤을 기본 마일스톤 후보로 선제안.
  • 분리는 자연 발생 — 개별 태스크를 칩으로 다른 마일스톤에 옮기는 순간 새 셀이 채워지며 split이 그리드에 즉시 나타남.

Open Questions

8결정이 필요한 지점

Q1

매트릭스 vs 아코디언 — 진입 오버뷰를 매트릭스(B안)로 갈지, 심플하게 피처 아코디언(A안)만으로 갈지. 마일스톤 개수가 보통 몇 개까지 쓰이나요? (5개 초과면 매트릭스 가로 스크롤 고려)

Q2

기본 마일스톤 상속 채택 — is_primary를 "피처의 기본 마일스톤(새 태스크 상속)"으로 재정의하는 데 동의하나요? 아니면 자동 파생+숨김이 더 나은가요? (생성 마찰 vs 개념 노출의 트레이드오프)

Q3

피처 생성 시 마일스톤 지정 — 칸반에서 피처 만들 때 기본 마일스톤 필드를 노출할지(선택), 아니면 항상 미배정으로 시작하고 매트릭스에서만 배정할지.

Q4

스마트 채우기 기준 — 마일스톤 생성 시 추천을 "기간 겹침(태스크 due date)"으로 할지, "활성 피처"로 할지, 둘 다 제공할지.

Q5

진행률 정의 — 마일스톤 진행률을 "그 마일스톤에 속한 태스크만"으로 계속 볼지, "걸친 피처들의 전체"로 볼지. 현재는 전자(태스크 스코프)입니다.
