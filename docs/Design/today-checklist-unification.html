오늘의 체크리스트 개념 통합 개선안

BRIDGE · 2026-07-29 · 대상: 데일리 스케줄 뷰 / 타임블록 추가 모달 / 데일리 체크리스트 도메인

한 줄 요약

“오늘의 체크리스트”는 따로 담는 목록이 아니라, 내 체크리스트를 오늘 기준으로 거른 뷰여야 한다. 별도 테이블(daily_checklists)은 목록의 주인이 아니라 예외 지정(핀 / 제외) 용도로 축소한다.

01

지금 무엇이 어긋나 있나

두 개의 "오늘"이 서로를 모른 채 공존

현재 “오늘 할 체크리스트”를 결정하는 근거가 두 개 존재하고, 둘은 서로 동기화되지 않는다.

근거저장 위치결정 방식이걸 쓰는 곳
A. 수동 담기 daily_checklists
domain/dailychecklist/DailyChecklist.java		 사용자가 모달에서 항목을 골라 (board, item, assigned_date) 행을 만든다 데일리 뷰 좌측 레일, 타임블록 모달 상단
B. 항목의 일정 checklist_items.start_date / due_date
domain/checklist/ChecklistItem.java		 항목 자체에 기간이 있으면 그 기간 동안 “오늘 할 일” 워크로드/간트, D-Day 뱃지, 리포트, 마이스페이스
이미 반쯤 섞여 있다

DailyScheduleView.tsx:311-352 는 B(기간 기반)로 조회한 항목을 isVirtual: true 로 만들어 A의 목록에 합쳐서 그리고 있다. 즉 데일리 뷰는 이미 “파생 + 수동” 혼합 목록이다. 그런데 ChecklistCreateModal.tsx:315-328 의 필터는 A만 보고 있어, 같은 항목이 모달에선 “기존 항목”으로 분류된다.

증상 1 — 화면이 스스로 모순된다

스크린샷: “오늘의 체크리스트가 없습니다” 바로 아래 “기존 항목”에 ~7/29 · D-Day 항목이 떠 있다. 오늘 마감인 항목이 오늘의 체크리스트가 아니다.

증상 2 — 같은 의도를 두 번 입력

체크리스트에 마감일을 오늘로 잡아도 오늘의 체크리스트에는 안 들어간다. “오늘 하겠다”를 일정으로 한 번, 담기로 또 한 번 표현해야 한다.

증상 3 — 두 목록 중 뭘 봐야 할지 모호

레일에는 가상 항목(순서변경·삭제 불가)과 실제 항목이 시각적 구분 없이 섞인다. EmbeddedDailyChecklist.tsx:55-56,163-166

증상 4 — “제거”의 의미가 불명확

레일의 × 는 항목 삭제가 아니라 “오늘 목록에서 빼기”인데 안내가 없다. 게다가 가상 항목은 아예 뺄 수 없다(onRemove no-op).

02

개념 재정의 — 목록이 아니라 필터

단일 소스 + 예외 지정

“내 체크리스트 중 오늘이 포함된 것”을 기본값으로 삼고, 사람이 손대는 부분만 예외로 저장한다.

오늘의 체크리스트(나, D)
  = { 내 체크리스트 항목 | 기간이 D를 포함 }  ← 자동 (파생)
  + { D에 핀한 항목 }  ← 기간 밖인데 오늘 하기로 한 것
  − { D에서 제외한 항목 }  ← 기간에 걸리지만 오늘 안 할 것

포함 규칙

항목 상태 (담당자 = 나)오늘 포함그룹표시
start ≤ 오늘 ≤ due✅ 자동오늘진행중 기간 7/27–7/31
due = 오늘 (start 없음)✅ 자동오늘D-Day
start = 오늘 (due 없음)✅ 자동오늘시작
due < 오늘 · 미완료⚠️ 자동(접힘)지연3일 지남 + [오늘로 옮기기]
기간 없음 (미배정)❌—“다른 항목 추가”에서 핀으로만 진입
기간이 오늘을 안 덮음 (미래/과거)❌ (핀하면 포함)오늘📌 핀 원래 기간 함께 표기
완료됨△완료오늘 완료한 것만 하단 접힌 섹션

핀 (PIN)

“일정은 그대로 두고 오늘만 당겨 온다.” 기존 daily_checklists 행이 곧 핀이다 — 데이터 마이그레이션 없이 의미만 재정의된다. 제목만 있는 임시 항목(checklist_item_id = NULL)도 핀으로 유지.

제외 (EXCLUDE)

“기간엔 걸리는데 오늘은 안 한다.” 지금은 표현할 방법이 없어서 가상 항목을 못 지우는 문제의 해법. kind='EXCLUDE' 행 하나로 해결된다.

대안 검토 — 핀 대신 due_date를 오늘로 밀기

테이블을 아예 없앨 수 있어 가장 단순하지만, 원래 마감일 정보가 사라지고 간트/워크로드/리포트의 일정 신뢰도가 깨진다. “오늘 좀 봐야지”가 곧 “마감일 변경”이 되어버려 부작용이 크다. → 비추천. 다만 핀 항목의 액션 메뉴에 “일정도 오늘로 변경” 을 명시적 선택지로 제공한다.

  • 가상/실제 구분 제거 — 전부 동일하게 렌더, 순서 변경도 모두 허용(파생 항목은 첫 이동 시 position override 행 생성).
  • × 버튼 라벨을 “오늘에서 빼기” 로 명시(툴팁 + aria-label). 파생 항목이면 EXCLUDE, 핀이면 행 삭제.
  • 추가 버튼 라벨을 “오늘로 가져오기” 로. “추가”는 새 항목 생성으로 오해된다.
  • 항목 액션 메뉴: 오늘에서 빼기 / 일정 오늘로 변경 / 내일로 미루기.

데이터 모델 · API 변경

테이블 유지, 의미만 재정의

스키마 (멱등 마이그레이션)

-- V20260729_HHMMSS__add_kind_to_daily_checklists.sql
-- 파일명 타임스탬프는 `date -u +%Y%m%d_%H%M%S` 로 생성

DO $$ BEGIN
    ALTER TABLE daily_checklists ADD COLUMN kind VARCHAR(16) NOT NULL DEFAULT 'PIN';
EXCEPTION WHEN duplicate_column THEN NULL; END $$;

DO $$ BEGIN
    IF NOT EXISTS (SELECT 1 FROM pg_constraint WHERE conname = 'ck_daily_checklist_kind') THEN
        ALTER TABLE daily_checklists ADD CONSTRAINT ck_daily_checklist_kind
            CHECK (kind IN ('PIN', 'EXCLUDE'));
    END IF; END $$;

CREATE INDEX IF NOT EXISTS idx_daily_checklist_assignee_date
    ON daily_checklists(assignee_id, assigned_date);

기존 행은 전부 PIN 으로 자연 이관된다. 유니크 제약 (board_id, checklist_item_id, assigned_date) 는 그대로 유지 — 같은 날 같은 항목에 핀과 제외가 동시에 존재할 수 없다.

API

엔드포인트변경내용
GET /boards/{id}/daily-checklists 동작 변경 파생(기간 기반) + 핀 − 제외를 서버에서 병합해 반환. 프론트의 가상 항목 병합 로직 제거.

05

구현 결과

2026-07-29 적용 완료
1

서버에서 병합 완료

DailyChecklistResolver 를 추가해 파생 + 핀 − 제외를 한 곳에서 병합한다. 데일리 뷰(getDailyFull) · 타임블록 모달(timeblock-data) · 보드 Today · 다이어리 AI 컨텍스트가 모두 이 리졸버를 통해 같은 목록을 본다. 응답에 source / pinned / start_date / due_date 추가. 프론트의 가상 항목 조회·병합 로직은 삭제됐다(데일리 뷰 API 호출 1회 감소).

2

모달·레일 단일 목록화 완료

타임블록 모달의 두 섹션을 오늘 / 지연 / 다른 항목 세그먼트 하나로 합쳤다. 오늘·지연이 모두 비면 “다른 항목”이 자동으로 선택된다. 레일과 모달이 DailyChecklistBadge 를 공유해 D-Day · 지연 · 당겨옴 뱃지를 같은 모양으로 표시하고, 버튼 라벨은 “오늘로 가져오기 / 오늘에서 빼기”로 바뀌었다.

3

EXCLUDE 도입 완료

kind 컬럼 마이그레이션(기존 행 → 모두 PIN), POST /daily-checklists/exclude 추가. 파생 항목도 이제 오늘에서 뺄 수 있고, 다시 가져오면 EXCLUDE가 PIN으로 되돌아간다. DELETE 도 원본이 연결된 행이면 삭제 대신 EXCLUDE로 전환해, 어느 경로로 빼도 항목이 되살아나지 않는다.

이번 범위에서 제외한 것
  • 파생 항목 드래그 정렬 — 순서를 저장할 행이 없어 레일에서는 핀 항목만 정렬 가능하다(기존 동작과 동일). 파생 항목은 오늘 → 지연 → 완료 순으로 자동 정렬된다. 정렬까지 허용하려면 드래그 시점에 PIN 행을 만들어주는 처리가 필요하다.
  • AddDailyChecklistModal 통합 — 두 모달의 Picker 공통화는 별도 작업으로 남겼다.
  • 마이스페이스 대시보드 — 이미 담당 체크리스트 전체를 따로 보여주고 있어 핀 목록만 사용하도록 그대로 두었다(중복 방지).
06

결정이 필요한 지점

기본값은 제안해 두었음
지연 항목을 오늘 목록에 자동으로 넣을까?
제안: 넣되 “지연” 그룹으로 분리하고 기본 접힘. 안 넣으면 놓친 일이 영원히 안 보이고, 그냥 섞으면 오늘 목록이 부풀어 무의미해진다.
기간이 아예 없는 항목은?
제안: 자동 포함하지 않는다. 기간 없는 항목이 전부 매일 뜨면 필터가 무의미해진다. “다른 항목에서 찾기”를 통해 핀으로만 진입.
핀은 언제까지 유효한가?
제안: 그 날짜에만 유효(현행과 동일, assigned_date 기준). 다음 날 자동 이월은 하지 않는다 — 이월이 필요하면 일정을 바꾸는 게 맞다.
데일리 뷰는 보드 전원을 보여준다. 팀원 행에도 같은 규칙?
제안: 동일 규칙 적용. 이미 워크로드가 기간 기준으로 전원을 그리고 있으므로 규칙이 갈리면 같은 화면에서 또 어긋난다.
완료 항목 처리
제안: 오늘 완료한 것만 하단 “완료 N” 접힌 섹션에. 과거에 완료된 항목은 기간에 걸려도 노출하지 않는다.
