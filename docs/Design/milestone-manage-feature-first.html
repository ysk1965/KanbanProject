마일스톤 관리
피처 우선 · 보드 방안

"어떤 피처가 여러 마일스톤에 걸치는 일은 그렇게 많지 않다" — 이 한 문장에서 출발한 대안입니다. 드문 경우를 위해 화면 전체를 매트릭스로 만드는 대신, 흔한 경우(피처 하나 = 마일스톤 하나)를 원클릭으로 만들고 걸침은 예외적인 갈래(split)로 접어둡니다. 백엔드 변경은 사실상 없습니다.

홈 · 마일스톤 = 컬럼, 피처 = 카드 배정 · 카드 드래그 한 번 걸침 · 카드 갈래 배지 + 유령 카드 작성일 · 2026-07-01
The Reframe

1흔한 경우 vs 드문 경우

최종안(매트릭스)은 옳지만, 그것이 최적화하는 대상은 "피처가 여러 마일스톤에 걸침"이라는 소수 케이스입니다. 실제 사용 분포가 아래라면, 무게중심을 옮기는 게 맞습니다.

≈ 83%
피처 하나 = 마일스톤 하나. 이 릴리스에 이 기능이 들어간다. 끝.
≈ 17%
걸침(split). 일부 태스크만 다음 릴리스로 밀린다.

매트릭스는 이 17%를 한눈에 보여주려고 100%의 화면을 2차원 격자로 만듭니다. 셀 단위 편집, "기본 마일스톤 → 상속"이라는 개념 학습이 모두 그 17%를 위한 비용입니다. 걸침이 정말 드물다면 — 그 비용은 83%에게 과합니다.

같은 열린 질문(Q1~Q5), 다른 무게중심의 답

결정 사항이 방안이유
진입 오버뷰 마일스톤 보드 (컬럼 = 마일스톤, 카드 = 피처) Trello식 컬럼. 83%는 카드가 한 컬럼에 깔끔히 들어감. 팀이 이미 아는 은유라 학습 0.
배정의 기본 단위 피처 단위 (드래그 = 마일스톤 이동) 카드를 컬럼으로 끌면 그 피처의 (오버라이드되지 않은) 모든 태스크가 따라 이동. 원클릭.
걸침(split) 처리 예외 액션 — 카드 갈래 배지 + 유령 카드 걸친 피처만 ⑂ 2 → v1.1 배지 + 다음 컬럼에 흐린 유령 카드로 등장. 정보는 유지, 격자는 불필요.
태스크 단위 조정 드릴다운에서만 (카드 클릭) 태스크별 마일스톤 칩은 카드를 열었을 때만 노출. 평소엔 숨어 화면이 조용함.
진행률 정의 피처 전체가 기본, 걸침 시 컬럼별 병기 83%는 피처=마일스톤이라 진행률이 하나로 일치 → 혼동 자체가 없음. 걸친 카드만 "이 마일스톤 n/m" 보조 표기.
The Model

2하나의 모델 — 피처가 마일스톤을 가진다

Single Mental Model
마일스톤은 피처가 속하는 릴리스다.
태스크는 기본적으로 피처를 따라가고, 필요할 때만 갈라진다.
→ 홈 = 릴리스별 피처 보드 · 배정 = 카드 드래그 · 걸침 = 몇몇 태스크만 오버라이드. 흔한 경우가 짧은 문장 안에 있습니다.
저장 구조는 그대로

진실의 원천은 여전히 task.milestone_id입니다. 다만 피처의 마일스톤 = "그 피처 태스크들이 기본으로 갖는 값(= 기존 기본 마일스톤)". 태스크가 그 값을 따르면 상속, 다르면 오버라이드(=걸침). 스키마·집계 쿼리 변경 없음.

달라지는 것은 "리드"

매트릭스는 셀(태스크 교차점)을 리드로 삼습니다. 이 방안은 카드(피처)를 리드로 삼고, 태스크 편집을 드릴다운으로 밀어넣습니다. 같은 데이터, 다른 진입 표면 — 그래서 최종안과 공존·전환이 쉽습니다.

3최종 홈 — 마일스톤 보드

컬럼 = 마일스톤, 카드 = 피처. 카드를 다른 컬럼으로 끌면 그 피처의 마일스톤이 바뀝니다. 대부분의 카드는 한 컬럼에 얌전히 들어갑니다.

결제 연동은 v1.0 컬럼에 살지만 태스크 2개가 v1.1로 갈라져 ⑂ 2 → v1.1 배지 + v1.1에 유령 카드로 비칩니다. 걸침 정보는 그대로 보이되, 격자 없이 카드 한 장에 담깁니다.

이 화면이 지키는 3가지

  • 흔한 경우는 조용하다 — 걸치지 않은 카드엔 배지도 유령도 없음. 한 컬럼 = 한 릴리스의 정직한 목록.
  • 드문 경우도 사라지지 않는다 — 갈래 배지 + 유령 카드가 걸침을 드러내고, 미배정은 전용 컬럼으로 안전망.
  • 이동은 물리적이다 — 드래그 = 마일스톤 변경. "대표/이어짐" 같은 추상 조작을 배울 필요 없음.
The Exception

4걸침이 필요할 때 — 카드 열기

17%의 경우에만 들어오는 화면입니다. 카드를 클릭하면 태스크 목록이 열리고, 밀어낼 태스크의 마일스톤만 칩으로 바꿉니다. 나머지는 상속 그대로 둡니다.

결제 연동
피처 마일스톤: v1.0
전체 태스크 5 상속 3 · 갈래 2
✔PG사 API 연동v1.0 (상속)
✔결제 취소 로직v1.0 (상속)
○영수증 발행v1.0 (상속)
○정기결제 스케줄러v1.1 ▾
○환불 정책 문서화v1.1 ▾

기본은 전부 "v1.0 (상속)" — 손댈 게 없습니다. 아래 2개만 v1.1로 바꿔 걸침을 만들었고, 이게 홈의 ⑂ 2 → v1.1 배지가 됩니다. "피처 마일스톤" 자체를 바꾸면 상속 3개가 통째로 따라 이동합니다(= 홈에서 카드 드래그와 동일).

핵심 차이 — 최종안 슬라이드오버는 태스크마다 칩을 매번 만나게 합니다(모두 개별 값처럼 보임). 이 방안은 대부분을 "(상속)"으로 눌러두어, 실제로 갈라진 것만 눈에 띄게 합니다. 편집 대상이 5개 → 2개로 줄어듭니다.
Interactions

5세 가지 동작이 전부

1

카드를 컬럼으로 드래그

피처 마일스톤 변경. 상속 태스크 일괄 이동. 갈래(오버라이드) 태스크는 자기 자리 유지 → 유령 카드로 남음.

2

카드를 클릭

드릴다운. 태스크별 칩으로 소수만 갈라내기(= split). 흔한 경우엔 열 일조차 없음.

3

＋ 새 마일스톤 = 새 컬럼

제목 + 기간 2필드. 생성 즉시 컬럼 등장. 기간 겹치는 피처를 "이 릴리스로 옮길까요?" 제안(스마트 채우기).

피처 생성 시 — 칸반에서 피처를 만들 때 활성 마일스톤을 기본값으로 선제안(비우면 미배정). 새 태스크는 피처 마일스톤을 상속 → 배정 마찰 0. 최종안과 동일한 원리이며, 단지 홈 표면만 보드입니다.

이 방안이 항상 옳은 건 아닙니다. 걸침 빈도가 무게추입니다.

What Changes vs 최종안

7최종안에서 무엇을 옮기나

◧ 최종안(매트릭스)의 전제

  • 화면 = 2D 격자, 셀이 리드
  • 걸침을 항상 정면에 보여줌 (17%를 위해 100% 격자)
  • "기본 마일스톤 → 상속" 개념을 먼저 이해해야 함
  • 태스크 칩이 매번 노출 (모두 개별처럼)
  • 진행률: 합계 vs 피처 전체를 나란히 설명해 혼동 방어

◨ 보드 방안의 전환

  • 화면 = 릴리스 컬럼, 카드가 리드
  • 걸침은 배지+유령으로 접음 (필요할 때만 매트릭스 토글)
  • 드래그로 바로 씀, 상속은 "(상속)" 칩으로 뒤에서 작동
  • 태스크 칩은 드릴다운에서만, 갈래만 강조
  • 진행률: 1:1이라 애초에 하나, 걸친 카드만 보조 표기
Build Notes

8구현 메모

  • 백엔드 변경 0 — task.milestone_id + 피처 기본 마일스톤(is_primary) 그대로. 집계도 기존 countByMilestoneAndFeature 재사용.
  • 신규 컴포넌트 1개 — MilestoneBoard.tsx(컬럼=마일스톤, 카드=피처, @dnd-kit 드래그). 갈래 배지·유령 카드는 셀 카운트에서 파생.
  • 드릴다운 재사용 — 최종안의 태스크 배정 슬라이드오버를 그대로 씀. 차이는 "(상속)" 기본 표기 + 갈래만 강조.
  • 매트릭스는 토글로 보존 — MilestoneMatrix.tsx를 폐기하지 않고 "격자 보기" 보조 뷰로. viewMode: 'board' | 'matrix' 하나 추가.
  • 스마트 채우기 동일 — 새 마일스톤 생성 시 기간 겹침 후보 제안 쿼리 1개(최종안과 공유).
  • 점진 적용 — P1 보드 홈 + 드래그 배정 → P2 갈래 배지/유령 → P3 매트릭스 토글 → P4 레거시 체크박스 링크 제거.
같은 폴더의 milestone-manage-final.html(매트릭스 확정본)과 milestone-manage-redesign.html(분석서)의 결정을 그대로 상속하되, 홈 표면만 보드로 바꾼 것이 이 문서입니다. 데이터·개념은 동일, 리드하는 표면만 다릅니다.
