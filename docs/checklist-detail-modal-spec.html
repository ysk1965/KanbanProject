방향 확정

패널 전환이 아니라 모달

선행 문서에서는 오른쪽 CommentPanel의 범위를 좁히는 안을 기본으로 뒀다. 모달 위 모달을 피하려던 것인데, 코드를 보니 이 저장소는 이미 그렇게 하고 있다. 체크리스트 행에서 ChecklistHistoryModal이 열리고, 삭제·완료 확인 창도 태스크 모달 위에 뜬다. 그리고 그게 안전하게 동작하도록 만들어 둔 장치가 이미 있다.

걱정거리이미 해결돼 있는 것
ESC가 둘 다 닫는다 escStack이 LIFO로 최상단 하나만 닫는다 (useEscClose.ts). 디테일을 닫아도 태스크 모달은 열려 있다.
포커스가 튄다 MotionModal이 열릴 때 document.activeElement를 저장하고 닫을 때 되돌린다. 뱃지를 눌러 열었으면 닫을 때 그 뱃지로 돌아온다.
쌓임 순서가 꼬인다 둘 다 z-50이지만 createPortal로 body에 나중에 붙으므로 나중 모달이 위에 그려진다. 기존 중첩 모달들이 같은 방식으로 동작 중.
오버레이 클릭으로 다 닫힌다 디테일의 오버레이 클릭은 디테일만 닫는다 — 이벤트가 stopPropagation된다.

모달이 더 나은 실질적 이유도 있다. 패널 전환은 폭 320px 남짓이라 이미지 갤러리와 항목 정보를 같이 놓을 자리가 없다. 모달은 폭을 직접 정할 수 있고, 태스크 모달의 체크리스트 목록을 뒤에 그대로 남겨 두므로 "어디서 왔는지"가 계속 보인다.

이탈

  • ESC · 오버레이 클릭 · ✕ 버튼 — 셋 다 디테일만 닫는다.
  • 닫으면 그 행이 잠깐 강조된다(기존 하이라이트 스타일 재사용). 목록이 길 때 "내가 보던 줄"을 잃지 않는다.
  • 댓글 입력창에 쓰다 만 내용이 있으면 오버레이 클릭으로는 닫지 않는다 (overlayClose={false} 동적 적용). ESC·✕는 확인 없이 닫되 초안은 항목별로 보관한다.
구조

왼쪽은 항목, 오른쪽은 대화

태스크 모달이 쓰는 문법(왼쪽 내용 / 오른쪽 댓글)을 한 단계 아래에서 그대로 반복한다. 사용자가 새 규칙을 배울 게 없다. sm:max-w-4xl, 높이는 max-h-[85dvh].

상세

영역별로 무엇이 되는가

헤더

  • 체크박스 — 여기서 바로 완료 토글. 태스크 모달의 행과 같은 API를 부르고, 결과는 뒤에 있는 행에도 즉시 반영된다.
  • 제목 — 클릭하면 인라인 편집(행에서 쓰는 동작 그대로). Viewer는 편집 불가.
  • 브레드크럼 — 태스크 · 피처 · 마일스톤. 항목이 어느 맥락에 있는지 디테일에서도 잃지 않는다. 태스크명을 누르면 디테일이 닫히고 그 행으로 돌아간다.
  • 우측 — 이력 버튼(기존 ChecklistHistoryModal을 그대로 연다), ⋮ 메뉴(병합·이동·맥에 맡기기·삭제 — 행 메뉴와 동일 구성), 닫기.
이력 모달은 3단이 된다

태스크 → 디테일 → 이력. escStack이 LIFO라 동작은 맞지만 3단은 깊다. 대안은 이력을 디테일 왼쪽 하단에 인라인 섹션으로 접어 넣는 것. 결정이 필요하다 — 기본값은 기존 모달 재사용(코드 0줄 추가).

왼쪽 — 항목 정보

  • 담당자 / 기간 / 기록 시간. 담당자·기간은 행에서와 동일한 피커로 여기서도 바꾼다. 기록 시간은 타임블록 합계이며, 누르면 타임블록 목록이 펼쳐진다.
  • 이미지 갤러리 — 이 항목 댓글들의 첨부 중 이미지만 모아 격자로. 최대 3개 + +N, 클릭 시 기존 라이트박스. 이미지가 없으면 섹션 자체를 숨긴다(빈 액자를 두지 않는다).
  • 설명 — 4단계 전까지는 렌더링하지 않는다. 자리만 잡아두고 "준비 중"을 띄우는 건 화면을 낭비하는 일이다.

오른쪽 — 댓글 스레드

  • 이 항목의 댓글만 시간순. 태스크 댓글과 기능 차이가 없다 — 답글, 이미지 첨부, 멘션, 리액션, 수정·삭제 모두 동일하다.
  • 입력창 placeholder가 "이 항목에 댓글 남기기…"로 바뀐다. 지금 쓰는 글이 어디로 가는지가 화면에 적혀 있어야 한다.
  • 우상단 "태스크 전체 보기" — 디테일을 닫고 태스크 댓글 패널로 돌아간다.
  • AI 요약 버튼은 여기 두지 않는다. 항목 3개짜리 스레드를 요약할 이유가 없고, 크레딧만 쓴다.
반응형

모바일에서는 대화가 먼저다

MotionModal은 좁은 화면에서 하단 시트로 붙는다(items-end, rounded-t-2xl, safe-area 패딩). 디테일도 그 형태를 따르되 순서를 바꾼다 — 항목 정보를 접고, 대화를 위로 올린다.

  • 정보 줄에는 담당자·기간·D-day·이미지 개수만. 나머지는 펼쳐야 나온다.
  • 키보드가 올라올 때 입력창이 가려지지 않아야 한다 — dvh 기준 높이와 env(safe-area-inset-bottom)는 MotionModal이 이미 처리한다.
  • 이미지 갤러리는 가로 스크롤 한 줄로. 세로 공간을 격자에 쓰지 않는다.

동기화

열려 있는 동안 계속 맞는다

디테일은 태스크 모달 안에서 열리므로 이미 들어오고 있는 WebSocket 이벤트를 쓰면 된다. 새 구독도, 폴링도 필요 없다.

수신 이벤트디테일이 하는 일
COMMENT_CREATED checklist_item_id가 이 항목이면 스레드 하단에 추가 + 뒤 행의 뱃지 +1
COMMENT_UPDATED / DELETED 해당 댓글 교체 또는 제거. 삭제면 뱃지 −1, 갤러리에서도 이미지 제거
COMMENT_REACTION_TOGGLED리액션 줄만 갱신
CHECKLIST_UPDATED / TOGGLED헤더의 제목·체크·담당자·기간 갱신
CHECKLIST_DELETED삭제 배너 표시 + 쓰기 차단 (모달을 강제로 닫지 않는다)
CHECKLIST_MOVED이동 배너 표시
모달을 임의로 닫지 않는다

남이 항목을 지웠다고 내가 보던 창을 없애면, 방금 읽던 대화가 사라진다. 배너로 알리고 쓰기만 막는다 — 닫는 건 사용자가 정한다.

주의

함정왜 생기나대응
스크롤이 두 겹 MotionModal의 콘텐츠 래퍼에 이미 overflow-y-auto가 걸려 있다. 안에서 좌우 칼럼을 따로 스크롤시키면 바깥 스크롤과 겹친다. className에 overflow-hidden을 넘겨 바깥 스크롤을 끄고, 칼럼 각각에 overflow-y-auto custom-scrollbar를 준다.
행 뱃지 클릭이 드래그가 된다 체크리스트 행은 useSortable 대상이다. 드래그는 dragHandleProps가 달린 요소에서만 시작하므로 구조적으로는 안전. 뱃지에 e.stopPropagation()을 붙여 확실히 한다.
Hooks 순서 오류 (React #310) 새 모달도 if (!item) return null 패턴을 쓰게 된다. 그 뒤에 useCallback을 추가하는 실수가 이 저장소에서 반복됐다. 모든 hook을 early return 위에. CLAUDE.md에 명시된 규칙.
드롭다운이 모달 뒤로 간다 ⋮ 메뉴(Radix)가 포털로 나가면서 모달과 쌓임 순서가 어긋날 수 있다. 행의 ⋮가 태스크 모달 안에서 잘 뜨고 있으므로 같은 구성을 유지. QA에서 실제로 한 번 확인한다.
뱃지 숫자가 어긋난다 낙관적 추가 + WS 이벤트 수신으로 두 번 세기 쉽다. 댓글 id 기준으로 중복 제거 후 길이를 센다. 증감 카운터를 따로 두지 않는다.
개인 스페이스에서 터진다 개인 태스크는 boardId가 없어 댓글 API 자체가 없다. boardId가 없으면 뱃지와 메뉴 항목을 아예 렌더링하지 않는다.

확인

착수 전에 정해야 할 것

선행 문서의 4개에 더해, 화면에서 갈리는 것 셋.

이력을 3단 모달로 둘까, 디테일 안에 접어 넣을까?

기본값 = 기존 이력 모달 재사용(추가 코드 없음, 대신 태스크→디테일→이력 3단). 깊이가 부담이면 디테일 왼쪽 하단에 접이식 섹션으로 옮긴다 — 이 경우 이력 모달을 디테일에서만 쓰도록 바꾸는 작업이 따라온다.

디테일에서 담당자·기간을 바꿀 수 있게 할까?

기본값 = 가능. 행에서 쓰는 피커를 그대로 가져온다. 읽기 전용으로 두면 화면이 단순해지지만, 항목을 보러 들어와서 고치려면 창을 닫고 나가야 한다.

태스크 댓글 패널의 항목 칩을 누르면?

기본값 = 디테일 모달을 연다. 선행 문서에서는 "행 하이라이트"였는데, 모달이 생긴 이상 칩이 곧 그 항목으로 가는 문이 되는 게 자연스럽다. 행 하이라이트는 모달을 닫을 때 자동으로 걸린다.
