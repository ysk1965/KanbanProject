체크리스트 항목에 디테일을 붙인다

체크리스트 한 줄에 이미지와 댓글을 달 수 있게 하되, 거기 달린 댓글이 태스크 모달의 댓글 목록에 그대로 섞여 보이게 한다. 핵심은 새 댓글 도메인을 만들지 않는 것 — 기존 comments에 소속 항목을 한 칸 더 적는다.

현황

이미 있는 것과 없는 것

코드를 확인한 결과, 필요한 재료는 대부분 이미 있다. 댓글은 첨부·썸네일·리액션·멘션·답글· 슬랙/디스코드 알림·JIRA 양방향 동기화까지 완비돼 있고, 체크리스트는 담당자·기간·타임블록· 휴지통·자동수정까지 붙어 있다. 둘 사이를 잇는 선만 없다.

영역지금비고
댓글 comments → task_id NOT NULL, board_id, parent_id(답글) 붙는 단위가 태스크뿐
댓글 이미지 comment_attachments — S3 키 + 썸네일, 최대 5개, temp→영구 이동 그대로 재사용 가능
체크리스트 checklist_items — 제목·담당자·기간·position·soft delete 본문/첨부 없음
태스크 모달 왼쪽 체크리스트 + 오른쪽 CommentPanel 2단 레이아웃 패널 자리를 그대로 쓴다
항목 하이라이트 highlightChecklistItemId → 해당 행으로 스크롤 + 강조 댓글→항목 점프에 재사용
알림 대상 태스크 댓글 → 태스크 생성자 + 모든 체크리스트 담당자 항목 지정 시 좁힐 여지
결정

새 도메인을 만들지 않는다

"체크리스트에 달린 댓글이 태스크 댓글에 그대로 보인다"는 요구가 설계를 결정한다. 두 저장소로 나누면 화면에서 다시 합쳐야 하고, 그 합치기가 정렬·페이징·실시간·알림·JIRA 전부에 반복된다. 애초에 한 테이블에 두면 합칠 일이 없다.

A안 · comments 확장

채택

comments.checklist_item_id(nullable)를 추가한다. 값이 없으면 지금까지처럼 태스크 댓글, 있으면 그 항목의 댓글.

  • 태스크 댓글 목록은 쿼리 변경 없이 항목 댓글까지 포함한다
  • 첨부·리액션·멘션·답글·알림·JIRA가 전부 공짜로 따라온다
  • 새 컨트롤러/서비스/레포지토리 0개
  • 비용: 항목 이동·병합·삭제 시 댓글 소속을 맞춰줘야 한다

B안 · checklist_comments 신설

미채택

체크리스트 전용 댓글 도메인을 따로 만든다.

  • 첨부·리액션·멘션·알림 로직을 전부 복제해야 한다
  • 태스크 모달에서 두 목록을 시간순으로 머지 — 실시간 갱신 때마다 재머지
  • JIRA 동기화·주간 리포트·AI 요약이 한쪽만 본다
  • 얻는 것: 체크리스트 삭제 시 댓글 생명주기가 깔끔 — 그 하나뿐
이미지는 어떻게 붙나

1단계에서는 댓글 첨부를 그대로 쓴다. 항목 스레드에 이미지를 올리면 그게 곧 그 항목의 이미지다 — 별도 첨부 테이블도, 별도 업로드 경로도 필요 없다. 항목 자체의 고정 본문(description + 인라인 이미지)이 필요하다는 게 확인되면 4단계에서 노트 에디터가 쓰는 /api/v1/files/upload-note 경로를 재사용해 얹는다.

스키마

컬럼 한 개

Flyway 마이그레이션은 타임스탬프 네이밍 + 멱등 규칙을 따른다. 파일명 타임스탬프는 작성 시점에 date -u +%Y%m%d_%H%M%S로 생성한다. 

-- V20260806_HHmmss__add_checklist_item_id_to_comments.sql

DO $$ BEGIN
    ALTER TABLE comments ADD COLUMN checklist_item_id VARCHAR(36);
EXCEPTION WHEN duplicate_column THEN NULL;
END $$;

CREATE INDEX IF NOT EXISTS idx_comment_checklist_item
    ON comments(checklist_item_id);

-- 태스크 열 때 항목별 댓글 수를 한 번에 세기 위한 복합 인덱스
CREATE INDEX IF NOT EXISTS idx_comment_task_checklist
    ON comments(task_id, checklist_item_id);
FK 매핑이 아니라 문자열로 든다

ChecklistItem에는 @SQLRestriction("deleted_at IS NULL")이 걸려 있다. Comment에서 @ManyToOne ChecklistItem으로 매핑하면 항목을 휴지통에 넣는 순간 기존 댓글을 읽을 때 프록시 해석이 깨진다(EntityNotFoundException). 그러므로 엔티티 연관이 아니라 String checklistItemId 컬럼으로 들고, 제목은 조회 시 별도 쿼리로 붙인다. DB FK 제약도 걸지 않는다 — 휴지통·복원 흐름과 충돌한다.

4단계(선택)에서 항목 본문이 필요해지면 컬럼 하나가 더 붙는다.

-- 4단계에서만. 지금은 만들지 않는다.
DO $$ BEGIN
    ALTER TABLE checklist_items ADD COLUMN description TEXT;
EXCEPTION WHEN duplicate_column THEN NULL;
END $$;
API

기존 엔드포인트에 필드만 얹는다

새 경로를 만들지 않는 것이 이 설계의 요점이다. 프론트가 이미 호출하고 있는 네 곳에 필드가 늘어날 뿐이라, 클라이언트 구버전도 그대로 동작한다(추가 필드 무시). 모든 JSON 필드는 프로젝트 규칙대로 snake_case.

엔드포인트변경구분
POST …/tasks/{taskId}/comments 요청 body에 checklist_item_id(nullable) 추가. 값이 있으면 해당 항목이 이 태스크 소속인지 검증 후 저장. 필드 추가
GET …/tasks/{taskId}/comments 응답 각 댓글에 checklist_item_id, checklist_item_title, checklist_item_deleted 추가. 항목 제목은 IN 쿼리 한 번으로 벌크 조회. 필드 추가
GET …/tasks/{taskId}/checklist 각 항목에 comment_count 추가. GROUP BY 카운트 쿼리 1회로 붙인다(N+1 금지). 필드 추가
PUT …/comments/{commentId} 변경 없음 — 소속 항목은 수정 대상이 아니다. 그대로
PATCH …/checklist/{itemId} (4단계) description 필드 추가. 보류

권한

  • 읽기 checkViewerOrAbove, 쓰기 checkMemberOrAbove — 기존 댓글과 동일하다.
  • 항목 소속 검증을 반드시 넣는다: checklist_item_id의 task_id가 경로의 taskId와 다르면 CHECKLIST_ITEM_NOT_FOUND. 다른 태스크 항목에 댓글을 꽂는 경로를 막는다.
화면

오른쪽 패널이 항목 스레드로 바뀐다

태스크 모달은 이미 왼쪽 체크리스트 / 오른쪽 댓글 2단이다. 디테일을 위해 새 창을 띄우는 대신, 오른쪽 패널의 범위를 태스크 전체에서 항목 하나로 좁혔다 폈다 한다. 모달 위 모달이 생기지 않고, 항목을 보면서 대화할 수 있다.

기본 상태 — 전체 댓글

  • 패널은 지금처럼 태스크의 모든 댓글을 시간순으로 보여준다. 항목 댓글도 여기 그대로 섞인다 — 요구사항 그대로다.
  • 항목 댓글에는 본문 위에 작은 칩이 붙는다: 체크리스트 · 에러 화면 문구 확정
  • 칩을 누르면 왼쪽에서 해당 행이 강조된다. 이미 있는 highlightChecklistItemId 흐름을 그대로 태운다.
  • 삭제된 항목의 댓글은 칩에 취소선 — 대화 기록은 지우지 않는다.

좁힌 상태 — 항목 스레드

  • 진입: 행의 💬 뱃지 클릭, 또는 행 우측 메뉴의 "디테일".
  • 패널 상단에 항목 제목 + "← 전체 댓글" 브레드크럼. 입력창 placeholder도 "이 항목에 댓글 남기기…"로 바뀌어 어디에 쓰는지가 화면에 드러난다.
  • 이 상태에서 쓴 댓글은 checklist_item_id가 실린다. 그 외에는 전부 동일 — 이미지 첨부·멘션·리액션·답글 다 된다.
  • 필터는 클라이언트에서 한다. 이미 전체 목록을 받아왔으므로 재요청이 없다.
모바일

모바일에서는 2단이 위아래로 쌓인다(border-t md:border-l). 항목 스레드로 진입하면 댓글 영역으로 자동 스크롤해야 한다 — 안 그러면 뱃지를 눌렀는데 화면이 안 변한 것처럼 보인다.

동기화

실시간과 알림

WebSocket — 새 이벤트 없음

COMMENT_CREATED 페이로드가 곧 CommentResponse.Detail이므로, 여기에 checklist_item_id가 실리면 기존 wsCommentEvent 핸들러가 그대로 처리한다. 추가로 할 일은 하나: 이벤트를 받으면 왼쪽 행의 comment_count를 ±1 해준다.

알림 — 대상을 좁힌다

지금 태스크 댓글은 태스크의 모든 체크리스트 담당자에게 간다. 항목이 지정된 댓글까지 그렇게 뿌리면 20줄짜리 체크리스트에서 소음이 20배가 된다.

댓글 종류알림 대상문구
태스크 댓글 태스크 생성자 + 전체 체크리스트 담당자 그대로 변경 없음
항목 댓글 그 항목의 담당자 + 태스크 생성자 신규 슬랙/디스코드에 [항목명] 접두 표시
멘션 멘션된 사람 그대로 기존 중복 제거 로직 유지

딥링크는 이미 있는 highlightChecklistItemId 파라미터로 연결하면 알림 클릭 → 태스크 모달 → 해당 항목 강조까지 이어진다.

함정

댓글이 항목을 따라다녀야 하는 곳

A안의 유일한 비용이 여기다. 체크리스트 항목은 움직이고, 합쳐지고, 지워진다. 각 경로에서 댓글 소속을 맞춰주지 않으면 댓글이 엉뚱한 태스크에 남는다.

상황지금 동작추가할 처리
항목을 다른 태스크로 이동 moveChecklistItemToTask — 항목의 task_id만 바뀜 그 항목 댓글의 task_id도 함께 UPDATE. 안 하면 댓글이 원래 태스크에 고아로 남는다.
항목 병합 mergeChecklistItems — 소스 항목 삭제, 타임블록만 이관 소스 항목 댓글의 checklist_item_id를 대표 항목으로 재지정.
항목 휴지통 이동 soft delete (deleted_at) 댓글은 건드리지 않는다. 태스크 댓글 목록엔 계속 보이되 칩에 취소선. 복원하면 그대로 돌아온다.
항목 영구 삭제 hardDeleteChecklistItem — row 삭제 댓글의 checklist_item_id를 NULL로 떨어뜨린다. 댓글 자체는 태스크 댓글로 남는다 — 대화 기록은 지우지 않는다.
태스크 삭제 댓글 cascade 삭제 변경 없음. 항목도 같이 사라진다.
개인 스페이스 boardId가 없어 CommentPanel 자체가 안 뜬다 항목 뱃지도 보드에서만 노출. 개인 태스크는 이번 범위 밖.
JIRA 에코 주의

댓글 생성은 CommentCreatedEvent를 발행하고, JIRA 연동 보드에서는 이게 JIRA 코멘트로 올라간다. 항목 댓글도 같은 경로를 타면 JIRA 이슈에 맥락 없는 조각들이 쌓인다. 접두어를 붙여 올릴지, 항목 댓글은 JIRA로 보내지 않을지 결정이 필요하다.

착수 전에 정해야 할 것

기본값을 정해뒀으니, 다르게 갈 것만 말해주면 된다.

항목 본문(설명)이 지금 필요한가?

기본값 = 아니오. 이미지는 댓글 첨부로 충분하다고 보고 1–2단계만 만든다. "항목마다 스펙 본문을 적고 싶다"면 4단계를 1단계와 함께 넣는다.

항목 댓글도 JIRA로 올릴까?

기본값 = 올린다, 단 [항목명] 접두어를 붙여서. JIRA 이슈를 깔끔하게 유지하고 싶다면 항목 댓글은 BRIDGE에만 남기는 쪽으로 뒤집는다.

기본 화면은 "전체 댓글"인가?

기본값 = 전체. 태스크를 열면 지금과 똑같이 모든 댓글이 보이고, 항목 댓글은 칩으로 구분된다. 반대로 "항목별로만 보고 싶다"면 패널에 토글을 둘 수 있지만, 요청하신 "그대로 보인다"와는 어긋난다.

체크리스트 항목에 첨부 개수 제한은?

기본값 = 댓글당 5개(기존 제한 그대로). 항목 단위 총량 제한은 두지 않는다.
