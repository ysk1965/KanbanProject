## 프로젝트 소통의 현실

팀에서 이런 대화가 오갑니다:

> "이 부분 확인 부탁드려요" → Slack DM

> "어떤 작업 건이야?" → Slack에서 다시 물어봄

> "링크 보내줄게" → Trello 카드 링크 첨부

> "댓글 달았어" → Trello에 가서 확인

> "아 그거 어제 슬랙에서 말한 건데..." → 대화 내역 검색

**작업과 소통이 분리되면**, 맥락이 흩어집니다. Slack에서 논의한 내용이 Trello 카드에는 기록이 안 남고, Trello에서 댓글을 달아도 상대방이 안 보면 의미가 없습니다.

BRIDGE에서는 **작업 맥락 안에서 소통하고, 알림은 인앱과 Slack을 동시에 커버**합니다.

## @멘션 댓글 — 작업 카드 안에서 대화

### 이렇게 동작합니다

Task 카드를 열면 오른쪽에 **댓글 패널**이 있습니다.

1. 댓글 입력창에 `@` 를 입력
2. **멤버 드롭다운**이 나타남 (이름으로 검색 가능)
3. 멤버를 선택하면 `@이름` 이 삽입됨
4. Enter 키로 댓글 전송

멘션된 이름은 **시안 색상으로 하이라이트**되어 눈에 띕니다. 누가 태그되었는지 한눈에 보이죠.

### 댓글에서 할 수 있는 것

- **@멘션**: 팀원 태그 → 인앱 + Slack 알림 동시 발송
- **이미지 첨부**: 최대 5장, JPEG/PNG/GIF/WebP 지원
- **드래그 앤 드롭**: 이미지를 댓글 창에 끌어다 놓으면 업로드
- **붙여넣기**: 클립보드의 이미지를 Ctrl+V로 첨부
- **수정/삭제**: 자신이 쓴 댓글은 수정 및 삭제 가능

[이미지: @멘션 드롭다운 — 멤버 목록이 필터링되는 화면]

### 왜 Slack에서 대화하면 안 되나?

Slack 대화의 문제는 **맥락 소실**입니다.

2주 후에 "이 기능 왜 이렇게 구현했지?"라고 물어보면, Slack에서 관련 대화를 찾아야 합니다. 채널을 뒤지고, 키워드로 검색하고, 시간대를 좁히고... 보통 10분은 걸립니다.

BRIDGE에서는 **Task 카드를 열면 관련 논의가 전부 거기에 있습니다.** "이 API 왜 이렇게 설계했지?" → Task 카드의 댓글을 보면 됩니다. 맥락이 작업에 붙어있으니까 찾을 필요가 없습니다.

## 이미지 첨부 — 스크린샷 한 방으로 설명

"이 버그 말인데..." 하고 텍스트로 설명하다가 3줄 넘어가면, 대부분 스크린샷 하나가 더 효과적입니다.

BRIDGE 댓글에서는 **3가지 방법**으로 이미지를 첨부할 수 있습니다:

1. **클릭**: 첨부 버튼 클릭 → 파일 선택
2. **드래그**: 이미지를 댓글 영역에 끌어다 놓기
3. **붙여넣기**: 스크린샷 캡처 후 Ctrl+V (또는 Cmd+V)

세 번째 방법이 가장 빠릅니다. 화면을 캡처하고 바로 붙여넣으면 끝. 파일을 저장하고 이름 짓고 업로드하는 과정이 없습니다.

업로드 중에는 **스피너와 파일 크기가 표시**되고, 업로드가 끝나면 썸네일 미리보기가 나타납니다. 실패하면 빨간색으로 표시되어 다시 시도할 수 있습니다.

첨부된 이미지를 클릭하면 **라이트박스**로 크게 볼 수 있습니다.

## 알림 시스템 — 놓치는 게 없도록

BRIDGE의 알림은 **3가지 이벤트**에 반응합니다.

### 1. 댓글 멘션 (COMMENT_MENTION)

누군가 댓글에서 나를 @멘션하면 알림이 옵니다.

> "**민수**님이 'API 설계' Task에서 당신을 멘션했습니다"

### 2. 체크리스트 배정 (CHECKLIST_ASSIGNED)

체크리스트 항목에 내가 담당자로 지정되면 알림이 옵니다.

> "'에러 핸들링 추가' 체크리스트가 당신에게 배정되었습니다"

### 3. 태스크 댓글 (TASK_COMMENT)

내가 관여하는 Task에 새 댓글이 달리면 알림이 옵니다.

> "**지영**님이 '로그인 API' Task에 댓글을 남겼습니다"

"관여하는 Task"란, 내가 **Task를 만들었거나** 해당 Task의 **체크리스트 항목에 배정된 경우**를 의미합니다. 댓글을 쓴 사람과 이미 멘션으로 알림을 받은 사람은 중복 알림에서 제외됩니다.

## 인앱 알림 — 벨 아이콘 하나로

화면 우측 상단의 **벨 아이콘**에 빨간 배지가 표시됩니다.

클릭하면 알림 패널이 열리고:

- **읽지 않은 알림**: 왼쪽에 인디고 색상 바가 표시됨
- **아이콘 구분**: 멘션(@), 체크리스트(클립보드), 댓글(말풍선)
- **시간 표시**: "방금 전", "2분 전", "3시간 전", "5일 전"
- **알림 클릭**: 해당 Task로 바로 이동

"모두 읽음" 버튼으로 한 번에 읽음 처리할 수 있고, 알림이 많으면 "더 보기" 버튼으로 과거 알림을 불러옵니다.

[이미지: 알림 드롭다운 — 읽지 않은 알림이 인디고 하이라이트로 표시된 화면]

## Slack 연동 — 설정부터 알림 수신까지

### Slack 웹훅 연결 (5분)

BRIDGE는 **Slack Incoming Webhook**으로 알림을 보냅니다.

설정 순서:

1. [api.slack.com/apps](https://api.slack.com/apps)에서 Slack 앱 생성
2. "Incoming Webhooks" 활성화
3. 알림 받을 채널 선택
4. Webhook URL 복사
5. BRIDGE 보드 설정 → Slack 패널에 URL 붙여넣기
6. "테스트" 버튼 클릭으로 연결 확인

BRIDGE 안에 **6단계 가이드 모달**이 내장되어 있어서, 처음 하는 분도 따라하면 됩니다. Slack 앱 생성 페이지로 바로 이동하는 링크와, Webhook URL 형식 예시(`https://hooks.slack.com/services/T.../B.../...`)까지 제공합니다.

### Slack으로 받는 알림

설정이 끝나면, 인앱 알림과 동일한 3가지 이벤트가 **지정한 Slack 채널로도 전송**됩니다.

```
#project-bridge

🔔 BRIDGE 알림
민수님이 'API 설계' Task에서 @지영님을 멘션했습니다
"이 부분 확인 부탁드려요. 내일까지 리뷰 가능할까요?"
```

Slack에서 바로 내용을 확인하고, 필요하면 BRIDGE로 이동해서 댓글을 달 수 있습니다.

### 연결 상태 확인

Slack 설정 패널에는 **연결 상태**가 색상으로 표시됩니다:

| 색상 | 상태 |
|------|------|
| 초록 | 연결됨 + 활성 |
| 주황 | 연결됨 + 비활성 (수동으로 끈 상태) |
| 빨강 | 미연결 |

## 알림 설정 — 내가 원하는 것만 받기

모든 알림을 다 받으면 **알림 피로**가 옵니다. BRIDGE에서는 **3가지 이벤트 × 2가지 채널** = 6개 토글로 세밀하게 제어합니다.

### 설정 매트릭스

|  | 인앱 | Slack |
|--|:----:|:-----:|
| 댓글 멘션 | On/Off | On/Off |
| 체크리스트 배정 | On/Off | On/Off |
| 태스크 댓글 | On/Off | On/Off |

**활용 예시:**

- **"중요한 멘션만 Slack으로 받고, 나머지는 인앱으로"**
  - 댓글 멘션: 인앱 On + Slack On
  - 체크리스트 배정: 인앱 On + Slack Off
  - 태스크 댓글: 인앱 On + Slack Off

- **"Slack 알림은 전부 끄고, 인앱만 쓸래"**
  - 모든 항목: 인앱 On + Slack Off

- **"체크리스트 배정은 알림이 필요 없어"**
  - 체크리스트 배정: 인앱 Off + Slack Off

설정은 **보드별, 사용자별**로 적용됩니다. A 프로젝트에서는 모든 알림을 받고, B 프로젝트에서는 멘션만 받는 것도 가능합니다.

### 설정 위치

알림 드롭다운을 열면 **알림 설정** 패널이 접혀 있습니다. 한 번 클릭하면 토글 매트릭스가 펼쳐지고, 토글을 바꾸면 **자동 저장**됩니다 (500ms 디바운스).

[이미지: 알림 설정 매트릭스 — 3×2 토글이 보이는 패널]

## Slack 데일리 스탠드업 — 매일 아침 AI가 팀 현황을 보내줍니다

이벤트 기반 알림(멘션, 배정, 댓글)과 별도로, BRIDGE에는 **매일 자동 발송되는 Slack 데일리 스탠드업**이 있습니다.

### 이렇게 동작합니다

1. **보드 설정**에서 발송 시간과 타임존을 지정 (예: 매일 오전 9시, Asia/Seoul)
2. 매일 지정 시간에 **전일 보드 활동 데이터**를 AI가 자동 수집
   - 타임블록 작업 시간
   - 체크리스트 완료 현황
   - 댓글 및 논의 내용
3. AI가 데이터를 분석해서 **데일리 스탠드업 요약**을 생성
4. Slack 웹훅이 설정된 **모든 멤버에게 자동 발송**

### Slack 메시지 내용

```
#project-bridge

☕ BRIDGE - Daily Standup (2026-02-10)

[AI 요약 내용]
- 어제 주요 성과: API 설계 완료, UI 프로토타입 1차 리뷰
- 주요 논의: OAuth 연동 방식 변경 (댓글에서 감지)
- 주의 사항: 결제 시스템 Task 3일째 정체

[BRIDGE에서 보기 →]
```

### 설정 옵션

| 설정 | 내용 |
|------|------|
| **발송 시간** | 시/분 단위 (15분 간격) |
| **타임존** | Asia/Seoul, UTC 등 11개 |
| **언어** | 한국어 / 영어 |
| **활성화** | On/Off 토글 |

**Admin 이상**만 설정 가능하고, **Premium 보드**에서만 사용 가능합니다.

활동이 없는 날에는 "어제 기록된 활동이 없습니다" 메시지가 간단히 전송됩니다. 불필요한 AI 분석 없이 깔끔하게 처리됩니다.

[이미지: Slack 데일리 스탠드업 메시지 — AI 요약 + BRIDGE 링크]

## 활동 로그 — 팀의 모든 행동이 기록됩니다

알림 드롭다운의 두 번째 탭은 **활동 로그**입니다.

모든 변경 사항이 시간순으로 기록됩니다:

- 체크리스트 **체크/해제**
- 총 16가지 액션 타입

"누가 이 카드를 Done으로 옮겼지?", "이 Feature가 언제 수정됐지?" — 로그를 보면 바로 답이 나옵니다. **투명한 팀 운영**의 기본입니다.

## 실전 팁 3가지

### 1. @멘션은 "행동 요청"에만 쓰세요

"확인 부탁드려요", "리뷰해 주세요", "의견 주세요" — 이런 **액션이 필요한 경우**에 멘션을 사용합니다. 단순 정보 공유는 멘션 없이 댓글만 달면 됩니다. 멘션이 너무 많으면 알림이 무의미해집니다.

### 2. Slack 채널을 프로젝트별로 나누세요

하나의 Slack 채널에 모든 보드의 알림을 보내면 채널이 시끄러워집니다. 보드(프로젝트)별로 Slack 채널을 만들고, 각 보드에 해당 채널의 Webhook URL을 설정하세요.

### 3. 첫 주는 알림을 전부 켜고, 2주 차부터 조정하세요

처음에는 어떤 알림이 유용한지 모릅니다. 일주일 동안 전부 켜서 사용해보고, 불필요하다고 느끼는 것만 꺼 나가는 게 좋습니다.

## 마치며

팀 협업의 핵심은 **소통**이고, 소통의 핵심은 **맥락**입니다.

Slack에서 대화하면 맥락이 채널에 묻히고, 이메일로 소통하면 맥락이 받은편지함에 섞입니다. BRIDGE에서는 **작업 카드 안에서 대화하고, 그 대화가 알림으로 연결**됩니다.

@멘션 하나로 인앱 알림과 Slack 알림이 동시에 가고, 어떤 알림을 받을지는 6개 토글로 내 마음대로 조정합니다. 매일 아침에는 AI가 팀 현황을 Slack으로 보내주고, 회의가 끝나면 회의록도 원클릭으로 공유됩니다. 작업과 소통이 한 곳에 있으니까, "이거 어디서 얘기했더라?"가 사라집니다.

다음 편에서는 이 모든 기능을 아우르는 **마일스톤과 프로젝트 건강 체크** 기능을 다뤄보겠습니다.
