## 마일스톤 — 작업을 묶는 단위

### 마일스톤이란?

마일스톤은 **Feature들을 묶는 상위 단위**입니다. 스프린트, 릴리즈, 분기 목표 등 팀이 정하는 단위를 말합니다.

```
마일스톤: v1.0 릴리즈 (3/1 ~ 3/31)
  ├─ Feature: 사용자 인증 ────── 진행률 100%
  ├─ Feature: 대시보드 ────────── 진행률 75%
  └─ Feature: 결제 시스템 ──────── 진행률 30%
                                  ───────────
                              전체 진행률: 68%
```

마일스톤에 Feature를 연결하면, **마일스톤의 진행률은 연결된 Feature들의 평균으로 자동 계산**됩니다. Feature의 진행률은 Task 완료 비율이고, Task의 진행률은 Checklist 완료 비율입니다. 체인이 연결되어 있어서, 체크리스트 하나를 체크하면 마일스톤 진행률까지 올라갑니다.

### 마일스톤 만들기

1. 간트차트 또는 관리 뷰에서 **"마일스톤 추가"** 클릭
2. 제목 입력 (예: "Sprint 3", "v2.0 릴리즈")
3. 시작일/종료일 설정 (캘린더에서 범위 선택)
4. 연결할 Feature 체크박스 선택
5. 저장

처음 마일스톤을 만들면 **온보딩 가이드**가 나타납니다. 샘플 마일스톤(65% 진행률, Feature 3개 연결)이 미리보기로 표시되고, 마일스톤의 3가지 장점(그룹핑, 추적, 차트)을 안내합니다.

## 관리 대시보드 — 프로젝트 건강 점수

관리 뷰를 열면 **4개의 요약 카드**가 상단에 나타납니다.

### 요약 카드

| 카드 | 내용 | 예시 |
|------|------|------|
| **건강 점수** | 프로젝트 전체 건강 (0~100) | 78점 (초록) |
| **마일스톤 진행률** | 현재 마일스톤의 완료율 + Task 수 | 64% (12/19 Task) |
| **팀 멤버** | 정상 작업 중인 멤버 수 / 전체 | 4/5명 |
| **지연 항목** | 정체된 Task + 멈춘 체크리스트 | 3건 |

건강 점수의 색상은 자동으로 바뀝니다:
- **초록** (80~100): 순조로움
- **노랑** (60~79): 주의 필요
- **주황** (40~59): 위험
- **빨강** (0~39): 긴급 대응 필요

## 마일스톤 건강 탭 — 속도와 정확도

관리 대시보드의 첫 번째 탭은 **마일스톤 건강**입니다.

### 상태 뱃지

각 마일스톤에 **4단계 상태**가 표시됩니다.

| 상태 | 색상 | 의미 |
|------|------|------|
| On Track | 초록 | 현재 속도로 일정 내 완료 가능 |
| Slow | 노랑 | 속도가 느려지고 있음 |
| At Risk | 주황 | 일정 지연 위험 |
| Overdue | 빨강 | 이미 마감 초과 |

### 속도 분석 (Velocity)

마일스톤마다 다음 지표가 표시됩니다:

- **현재 속도**: 하루 평균 작업 시간 (예: 2.5h/일)
- **필요 속도**: 마감까지 필요한 하루 작업 시간 (예: 3.0h/일)
- **완료 Task**: 12/19 Task 완료

현재 속도가 필요 속도보다 낮으면 **일정을 맞추기 어렵다는 경고**입니다.

### 추정 정확도 (Estimation Accuracy)

Task에 **예상 소요 시간**을 설정했다면, 실제 소요 시간과 비교한 **추정 정확도**가 퍼센트로 표시됩니다.

```
추정 정확도: 85%
- 예상: 40시간
- 실제: 47시간
```

| 정확도 | 색상 | 의미 |
|--------|------|------|
| 80~120% | 초록 | 추정이 정확함 |
| 50~79% 또는 121~150% | 노랑 | 보통 |
| 그 외 | 빨강 | 추정 능력 개선 필요 |

추정 정확도는 팀의 **플래닝 포커 실력**을 나타냅니다. 이 숫자가 꾸준히 80~120% 범위에 있다면, 팀이 작업량을 잘 예측하고 있다는 뜻입니다.

### 시간 할당 (Allocation)

마일스톤 내 Task별로 **예상 시간과 실제 시간**을 비교할 수 있습니다. Task 목록에서 예상 시간은 인라인으로 바로 수정 가능합니다.

[이미지: 마일스톤 건강 — 속도 분석 + 추정 정확도가 보이는 화면]

## 팀 생산성 탭 — 멤버별 워크로드

두 번째 탭은 **팀 생산성**입니다.

### 멤버별 현황

각 멤버의 다음 지표가 카드로 표시됩니다:

- **투입 시간**: 타임블록 기반 총 시간
- **Task 완료율**: 완료 Task / 전체 Task
- **워크로드 상태**: Normal, Overworked, Relaxed

### 워크로드 감지

BRIDGE는 멤버별 작업량을 분석해서 **워크로드 상태를 자동 판별**합니다.

| 상태 | 색상 | 의미 |
|------|------|------|
| Normal | 초록 | 적절한 업무량 |
| Overworked | 빨강 | 과부하 상태 (재배분 필요) |
| Relaxed | 파랑 | 여유 있음 (추가 배정 가능) |

팀장이 이 화면을 보면 **"민수는 과부하니까 지영에게 일부를 넘기자"** 같은 판단을 데이터 기반으로 할 수 있습니다.

각 멤버 카드를 펼치면 **어떤 Task에 시간을 쓰고 있는지** 상세 목록도 볼 수 있습니다.

## 지연 항목 탭 — 정체된 작업 자동 감지

세 번째 탭은 **지연 항목**입니다.

### 두 가지 지연 유형

1. **정체 Task (Stagnant Tasks)**: N일 이상 블록이 안 바뀐 Task
2. **멈춘 체크리스트 (Stuck Checklists)**: N일 이상 완료되지 않은 항목

### 기준 설정

지연 판단 기준은 **설정에서 조정**할 수 있습니다:

- 정체 Task: 1~7일 (기본 3일)
- 멈춘 체크리스트: 1~5일 (기본 2일)

급한 프로젝트라면 기준을 1일로 줄이고, 여유 있는 프로젝트라면 5일로 늘릴 수 있습니다.

### 마일스톤별 그룹핑

지연 항목은 **마일스톤별로 묶여서** 표시됩니다. "Sprint 3에서 정체된 Task가 2개, Sprint 4에서 1개" — 이런 식으로 보이니까, 어떤 스프린트에 문제가 있는지 바로 파악됩니다.

[이미지: 지연 항목 탭 — 정체 Task와 멈춘 체크리스트가 마일스톤별로 그룹핑된 화면]

## 통계 뷰 — 6가지 분석 관점

관리 대시보드와 별개로, **통계 뷰**에서는 더 깊은 분석이 가능합니다.

### 6개의 분석 탭

| 탭 | 분석 내용 |
|----|----------|
| **Overview** | KPI 4종 + 일별 트렌드 + Feature 분포 + 멤버 기여 |
| **Individual** | 멤버별 개인 생산성 분석 |
| **Team** | 팀 전체의 협업 패턴 분석 |
| **Work** | 작업 유형별 시간 분배 |
| **Impact** | 작업의 영향도 분석 |
| **AI Report** | AI가 작성하는 서술형 분석 리포트 |

### Overview 탭 상세

Overview를 열면 4개의 KPI 카드가 나타납니다:

- **총 작업 시간**: 팀 전체의 투입 시간 + 완료 작업 시간
- **Task 완료율**: 완료 Task 수 / 전체 Task 수 (%)
- **집중률**: 추적된 작업에 쓴 시간의 비율
- **평균 Feature 진행률**: 모든 Feature의 평균 진행률

KPI 카드 아래에는:

- **일별 트렌드 차트**: 작업 시간 vs 완료 시간 라인 그래프
- **Feature 분포**: 상위 8개 Feature별 투입 시간
- **멤버 기여**: 상위 6명의 기여 시간

### 기간 필터

기간을 자유롭게 설정할 수 있습니다:

- 프리셋: 7일, 30일, 이번 달, 지난달, 전체
- 커스텀: 시작일/종료일 직접 선택
- 마일스톤: 특정 마일스톤 기간으로 필터

### 고급 필터

멤버별, 태그별로 필터링해서 **"프론트엔드 팀의 지난 2주 생산성"** 같은 세밀한 분석도 가능합니다.

## 주간 요약 — 개인 리포트

멤버별로 **주간 요약 리포트**를 확인할 수 있습니다.

### 통계 탭

- 총 타임블록 수
- 총 작업 시간
- 체크리스트 완료율 (%)
- 일 평균 작업 시간
- 일별 작업 시간 바 차트
- Feature별 시간 분배

### 기록 탭

한 주 동안의 **댓글 기록**을 모아서 보여줍니다. 어떤 Task에서 누구와 어떤 대화를 나눴는지, 작업 맥락과 함께 확인할 수 있습니다.

정량적 데이터(시간, 완료율)와 정성적 데이터(댓글, 논의 내용)를 함께 볼 수 있어서 **1:1 미팅이나 주간 회고**에 활용하기 좋습니다.

## 이 모든 게 연결됩니다

BRIDGE의 기능은 독립적으로 존재하는 게 아니라 **하나의 데이터로 연결**됩니다.

```
체크리스트 체크 ✓
    ↓
Task 진행률 업데이트
    ↓
Feature 진행률 업데이트
    ↓
마일스톤 진행률 업데이트
    ↓
건강 점수 재계산
    ↓
속도 분석 업데이트
    ↓
지연 항목 재평가
```

체크리스트 하나를 체크하는 행위가, 프로젝트 전체의 건강 상태를 바꿉니다. **입력은 한 번, 반영은 모든 곳에.** 이게 BRIDGE가 "통합 도구"인 이유입니다.

## 실전 팁 3가지

### 1. 마일스톤은 2~4주 단위로 만드세요

마일스톤이 너무 짧으면 의미 있는 데이터가 쌓이지 않고, 너무 길면 피드백 루프가 느려집니다. 2주 스프린트가 가장 일반적이고, 4주까지도 괜찮습니다.

### 2. 예상 시간을 꼭 입력하세요

추정 정확도는 **예상 시간이 있어야 계산**됩니다. 처음엔 대략적으로라도 넣어두세요. 3~4번의 마일스톤을 거치면 추정 실력이 눈에 띄게 좋아집니다.

### 3. 건강 점수가 60 이하면 즉시 액션

건강 점수가 60 아래로 떨어지면 **노랑~주황 경고**입니다. 이때는:
- 지연 항목 탭을 먼저 확인하고
- 워크로드가 Overworked인 멤버를 찾아서
- Task를 재배분하거나, 마일스톤 범위를 조정하세요

점수가 빨갛게 변하기 전에 대응하는 게 핵심입니다.
