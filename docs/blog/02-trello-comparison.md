> **시리즈: 팀워크 레벨업** — BRIDGE로 팀 협업을 한 단계 올리는 방법
> #2 Trello 비교편

---

## Trello, 분명 좋은 도구인데

오해하지 마세요. Trello는 좋은 도구입니다.

직관적이고, 가볍고, 처음 쓰는 사람도 5분이면 카드를 만들 수 있어요. 개인 할 일 관리나 간단한 프로젝트라면 Trello만으로 충분합니다.

문제는 **팀이 커지고, 프로젝트가 복잡해질 때** 시작됩니다.

1년 동안 Trello로 팀 프로젝트를 관리하면서 겪었던 6가지 한계와, BRIDGE로 갈아타면서 어떻게 해결됐는지를 솔직하게 공유합니다.

---

## 한계 1. 카드가 전부 같은 레벨이다

Trello의 가장 큰 구조적 문제입니다.

"사용자 인증 기능 개발"이라는 카드와 "JWT 토큰 만료 시간 변경"이라는 카드가 **같은 리스트에 같은 크기로** 들어갑니다. 하나는 2주짜리 기능이고, 하나는 30분짜리 수정인데요.

카드가 쌓이기 시작하면 "어떤 게 큰 덩어리고, 어떤 게 세부 작업인지" 파악이 안 됩니다. 라벨로 구분하려고 해봤는데, 카드가 30개만 넘어가면 라벨도 한계예요.

### BRIDGE는 어떻게 다른가

BRIDGE는 카드에 **명확한 계층**이 있습니다.

```
Feature "사용자 인증 기능 개발"     ← 큰 기능 단위
  ├─ Task "로그인 API 구현"        ← 세부 작업
  │    ├─ Checklist "JWT 구현"     ← 실행 항목
  │    ├─ Checklist "OAuth 연동"
  │    └─ Checklist "테스트 작성"
  └─ Task "회원가입 UI 구현"
       ├─ Checklist "폼 디자인"
       └─ Checklist "유효성 검사"
```

Feature가 "뭘 만들어야 하는지", Task가 "뭘 해야 하는지", Checklist가 "구체적으로 뭘 하는지"를 담당합니다.

Feature를 클릭하면 하위 Task 목록과 **전체 진행률**이 바로 보여요. "사용자 인증 기능이 지금 몇 퍼센트 진행됐지?"에 대한 답이 모달 하나로 나옵니다.

## 한계 2. 진행률을 수동으로 관리해야 한다

Trello에서 "이 기능이 얼마나 완료됐지?"를 확인하려면요.

1. 해당 기능과 관련된 카드들을 찾고
2. 완료된 카드 수를 직접 세고
3. 전체 카드 수로 나누고
4. 스프레드시트에 기록

이걸 매주 반복합니다. 스프린트 리뷰 때마다 이 작업을 하고 있었어요.

### BRIDGE는 어떻게 다른가

Task 카드를 **Done 블록으로 드래그하면 끝**입니다.

Feature의 진행률이 자동으로 업데이트됩니다. 3개 Task 중 2개를 Done으로 옮기면, Feature에 "67%"가 바로 표시돼요. 계산할 것도, 기록할 것도 없습니다.

```
Feature "사용자 인증" — 진행률 67%
  ├─ Task "로그인 API"      → Done ✓
  ├─ Task "회원가입 UI"     → Done ✓
  └─ Task "비밀번호 재설정" → In Progress
```

이게 당연한 것 같지만, Trello에서는 안 되는 기능이에요. BRIDGE를 쓰면서 "이걸 왜 수동으로 했지?" 싶더라고요.

---

## 한계 3. 자동화를 추가할수록 보드가 느려진다

Trello의 자동화 기능인 Butler, 처음엔 꽤 편했습니다. "카드가 Done으로 이동하면 라벨 변경", "마감일이 지나면 알림 전송" — 이런 규칙을 몇 개 만들었어요.

문제는 규칙이 늘어날수록 **보드 전체가 눈에 띄게 느려진다**는 겁니다.

카드를 드래그하면 잠깐 멈칫하고, 리스트를 열 때 로딩이 걸리고, 자동화 실행 결과가 반영되는 데도 시간이 걸렸어요. 자동화의 수준을 올릴수록 사용성이 떨어지는 모순적인 상황이 됩니다.

결국 "빠른 보드 vs 자동화된 보드" 사이에서 타협해야 했어요. 규칙을 10개 넘게 만들었다가, 느려져서 절반을 다시 끄는 일이 반복됐습니다.

### BRIDGE는 어떻게 다른가

BRIDGE는 별도 자동화 규칙을 만들 필요 자체가 적습니다.

- Task를 Done으로 옮기면 **Feature 진행률이 자동 반영** (규칙 설정 불필요)
- 체크리스트 완료 시 **Task 상태에 자동 반영** (규칙 설정 불필요)
- 마감 초과/임박 **색상이 자동 변경** (규칙 설정 불필요)

자동화를 "만들어야" 하는 게 아니라, **구조 자체가 자동화**되어 있는 거예요. 그래서 보드에 규칙을 덕지덕지 붙일 일이 없고, 성능 저하도 없습니다.

## 한계 4. Power-Up 없이는 기본적인 것도 안 된다

간트차트만 Power-Up이 필요한 게 아닙니다. Trello를 팀용으로 제대로 쓰려고 하면, **놀라울 정도로 많은 것들이 유료 Power-Up** 뒤에 숨어 있어요.

몇 가지 예를 들면:

- **보드에서 체크리스트 확인**: 카드를 일일이 열어야 체크리스트가 보입니다. 카드 표면에서 체크리스트 내용을 보려면? 유료 Power-Up.
- **간트차트 / 타임라인**: 유료 Power-Up.
- **통계 / 분석**: 완료 카드 수, 멤버별 작업량 같은 기본 통계도 유료 Power-Up.
- **카드 의존성**: "이 카드가 끝나야 저 카드 시작" 같은 의존 관계 표시도 유료 Power-Up.

보드에서 체크리스트를 바로 보는 것조차 Power-Up이라니, 처음 알았을 때 좀 당황했어요. 결국 Trello 무료 플랜의 "가벼움"은, 필요한 기능을 전부 빼놓은 결과이기도 합니다.

### BRIDGE는 어떻게 다른가

BRIDGE는 이런 기능들이 **전부 기본 내장**입니다.

| Trello에서 Power-Up 필요 | BRIDGE |
|--------------------------|--------|
| 보드에서 체크리스트 보기 | 카드 표면에 체크리스트 진행률 표시 |
| 간트차트 | Premium 기본 내장 |
| 통계 / 분석 | Premium 기본 내장 |
| 카드 의존성 | Feature → Task 계층으로 자연스럽게 해결 |

간트차트를 예로 들면, Task에 시작일과 마감일을 넣으면 **간트차트 탭이 자동으로 그려집니다.** Feature 단위로 접기/펼치기, 바를 드래그해서 일정 조정, 마일스톤으로 필터링까지 다 됩니다.

칸반 보드의 데이터와 **완벽히 동기화**되기 때문에, 칸반에서 Task를 Done으로 옮기면 간트차트에서도 완료 표시가 되고, 간트차트에서 날짜를 바꾸면 칸반 카드에도 반영돼요. Power-Up 연동에서 겪었던 동기화 문제가 없습니다.

[이미지: BRIDGE 간트차트 — Feature별 Task 바 + 날짜 그리드]

## 한계 5. "오늘 뭐하지?"에 대한 답이 없다

Trello는 **흐름(flow)** 관리에는 강하지만, **일정(schedule)** 관리에는 약합니다.

"오늘 내가 뭘 해야 하지?"를 Trello에서 확인하려면, 모든 리스트를 스크롤하면서 내 이름이 달린 카드를 찾아야 합니다. 마감일 필터를 걸 수는 있지만, "오늘 어떤 순서로 뭘 하면 되는지"는 알려주지 않아요.

데일리 스크럼 때도 마찬가지예요. 팀원 각자가 자기 카드를 찾아서 "저는 이거 하고 있습니다" 하는데, 한 화면에서 팀 전체 현황이 보이지 않습니다.

### BRIDGE는 어떻게 다른가

**데일리 스케줄 뷰**를 열면, 멤버별로 오늘 할 일이 시간 단위로 배치되어 있습니다.

```
        김개발           박디자인          이기획
09:00  ┌──────────┐
       │ JWT 구현  │                     ┌──────────┐
10:00  └──────────┘                     │ 기획서    │
       ┌──────────┐   ┌──────────┐     │ 작성     │
11:00  │ OAuth    │   │ UI 작업  │     └──────────┘
       │ 연동     │   │          │
12:00  └──────────┘   └──────────┘
```

데일리 스크럼 때 이 화면만 띄우면 됩니다. "누가 오늘 뭘 하는지", "어디서 막혀 있는지"가 한눈에 보여요.

여기에 **데일리 체크리스트**도 있어서, 날짜별로 체크리스트 항목을 멤버에게 할당하고 우선순위를 정할 수 있습니다. Trello에는 이런 뷰 자체가 없어요.

[이미지: BRIDGE 데일리 스케줄 뷰 — 멤버별 타임블록 배치]

## 한계 6. 결국 비용이 만만치 않다

위에서 말한 것들을 정리하면, Trello를 팀용으로 "제대로" 쓰려면 이런 것들이 필요합니다.

- 카드 자동화 → Butler (한도 초과 시 유료)
- 간트차트 → Timeline Power-Up (유료)
- 칸반 통계 → Analytics Power-Up (유료)
- 보드 체크리스트 보기 → Card Checklist Power-Up (유료)
- 투표/의사결정 → Voting Power-Up (유료)

하나씩 붙이다 보면 **Trello Standard($5/인) + Power-Up 2~3개** 해서 인당 $10~15는 쉽게 넘어갑니다. 10명 팀이면 **월 $100~150**이에요.

"그냥 Trello Premium($10/인)으로 올려서 해결하면 되지 않나?" 하지만, Premium에서도 서드파티 Power-Up은 별도 과금인 경우가 많습니다. 게다가 한계 3에서 말한 것처럼, Power-Up을 붙일수록 보드가 느려지는 문제도 있고요.

### BRIDGE는 어떻게 다른가

**$5/인/월. 이게 끝입니다.**

| 데일리 스케줄 | 없음 | **Premium 포함** |

## 그럼 Trello는 언제 쓰면 좋을까?

공정하게 말하자면, Trello가 더 나은 경우도 있습니다.

- **개인 할 일 관리**: 혼자 쓰는 간단한 보드라면 Trello 무료로 충분
- **Power-Up 생태계가 필요한 경우**: 특수한 서드파티 연동이 많다면 Trello의 Marketplace가 강점
- **이미 팀 전체가 Trello에 익숙한 경우**: 전환 비용이 클 수 있음

하지만 **5명 이상의 팀이 프로젝트를 체계적으로 관리**하려면, BRIDGE가 맞습니다. Feature → Task 계층, 자동 진행률, 간트차트, 데일리 스케줄 — 이런 것들이 Power-Up 없이 $5에 전부 들어 있으니까요.

## 갈아타면 기존 데이터는?

걱정되는 부분이죠. 솔직히 Trello 데이터를 그대로 옮기는 마이그레이션 기능은 아직 없습니다.

대신 저는 이렇게 했어요.

1. Trello의 리스트를 BRIDGE의 **Feature 단위**로 재정리
2. 각 카드를 Feature 아래 **Task**로 재배치
3. 카드 안의 체크리스트를 그대로 **Checklist**로 이동

이 과정에서 오히려 좋았던 게, **작업 구조가 명확해졌다**는 겁니다. Trello에서는 뒤섞여 있던 기능 단위와 세부 작업이 Feature/Task로 깔끔하게 분리되니까, 프로젝트 전체 그림이 처음으로 선명하게 보이더라고요.

## 마치며

Trello를 나쁘다고 말하는 게 아닙니다. 1년 동안 잘 썼고, 덕분에 칸반이라는 방식 자체에 익숙해질 수 있었어요.

다만, 팀이 커지고 프로젝트가 복잡해지면서 **"칸반 보드 하나로는 부족하다"**는 걸 느꼈고, 그때 BRIDGE가 딱 맞았다는 이야기입니다.

정리하면:

- 카드에 계층이 필요하다 → BRIDGE
- 진행률을 자동으로 추적하고 싶다 → BRIDGE
- 자동화 규칙 때문에 보드가 느려지는 게 싫다 → BRIDGE
- 체크리스트 보는 것까지 Power-Up 결제하기 싫다 → BRIDGE
- "오늘 팀원들이 뭘 하는지" 한눈에 보고 싶다 → BRIDGE
- AI가 주간 리포트를 써줬으면 좋겠다 → BRIDGE
