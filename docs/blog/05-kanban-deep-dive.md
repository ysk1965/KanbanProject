# 팀워크 레벨업 #5 | Feature → Task → Done, 진행률이 알아서 올라가는 칸반

> **시리즈: 팀워크 레벨업** — BRIDGE로 팀 협업을 한 단계 올리는 방법
> #5 칸반 보드 딥다이브

---

## "이 프로젝트, 지금 몇 퍼센트야?"

PM이라면 매주 듣는 질문입니다.

그때마다 스프레드시트를 열고, 완료된 작업을 세고, 전체 대비 비율을 계산합니다. Task가 30개쯤 되면 이것만 해도 10분입니다. 그런데 숫자를 정리해서 보고하면 또 이런 질문이 돌아옵니다.

"그래서 이번 주에 뭐가 끝났는데?"

BRIDGE에서는 이 질문에 대한 답이 **칸반 보드 안에 이미 있습니다.** 카드를 Done으로 옮기면 진행률이 자동으로 올라가니까요.

[이미지: 칸반 보드 전체 뷰 — Feature/커스텀 블록/Done이 보이는 화면]

## 3단계 계층 — BRIDGE 칸반의 핵심

대부분의 칸반 도구는 **카드가 전부 같은 레벨**입니다. "로그인 기능 구현"이나 "버튼 색상 변경"이나 똑같은 카드예요. 프로젝트가 커지면 중요한 카드가 잡다한 카드 사이에 묻힙니다.

BRIDGE는 다릅니다. **세 단계 계층**으로 작업을 구조화합니다.

```
Feature (기능 단위)
  └─ Task (작업 단위)
       └─ Checklist (세부 항목)
```

### Feature — 큰 그림

Feature는 **하나의 기능 묶음**입니다. "사용자 인증", "대시보드 리뉴얼", "결제 시스템" 같은 단위예요.

Feature에는 다음 정보가 표시됩니다:

- **진행률 바**: 하위 Task 완료 비율이 자동 계산
- **하위 Task 수**: 전체 몇 개 중 몇 개 완료
- **담당자**: Feature 책임자
- **태그**: 카테고리 분류
- **색상**: Feature별 컬러 코드 (간트차트, 스케줄에서도 동일 색상 적용)

[이미지: Feature 카드 — 진행률 바 + Task 카운트가 보이는 상태]

### Task — 실행 단위

Feature 아래에 실제로 수행할 **작업 단위**를 만듭니다. "API 엔드포인트 설계", "프론트엔드 폼 구현", "단위 테스트 작성" 같은 것들이요.

Task에 설정할 수 있는 항목:

- **시작일 / 마감일**: 간트차트에 자동 반영
- **예상 소요 시간**: 마일스톤 속도 분석에 활용
- **Checklist**: 세부 실행 항목
- **댓글**: @멘션으로 팀원 태그
- **첨부 이미지**: 최대 5장

Task를 Done 블록으로 옮기면, **상위 Feature의 진행률이 자동으로 올라갑니다.** 수동 계산 없이요.

[이미지: Task 상세 모달 — Checklist + 댓글 + 마감일이 보이는 상태]

### Checklist — 잊지 않을 세부 사항

하나의 Task를 더 잘게 나눌 수 있습니다. "API 문서 작성", "에러 핸들링 추가", "코드 리뷰 요청" 같은 체크리스트 항목을요.

체크리스트는 **담당자를 개별 배정**할 수 있어서, 하나의 Task를 여러 명이 나눠서 처리할 수 있습니다. 항목을 체크하면 Task의 완료율이 올라가고, 그게 다시 Feature의 진행률에 반영됩니다.

```
Feature: 사용자 인증 ──────────── 진행률 67%
  ├─ Task: 로그인 API ──────── Done ✓
  ├─ Task: 회원가입 폼 ─────── Done ✓
  └─ Task: 비밀번호 찾기 ────── In Progress
       ├─ ☑ 이메일 발송 로직
       ├─ ☑ 토큰 생성
       └─ ☐ 비밀번호 재설정 UI
```

**진행률은 항상 실시간**입니다. 누군가 체크리스트 항목 하나를 완료하면, Task 진행률이 올라가고, Feature 진행률이 올라가고, 마일스톤 진행률까지 올라갑니다. 체인 반응처럼요.

## 블록 구조 — 고정 + 자유

BRIDGE 칸반 보드의 블록 구조는 **의도적으로 설계**되었습니다.

### 고정 블록 3개

| 블록 | 위치 | 역할 |
|------|------|------|
| **Feature** | 맨 왼쪽 | 기능 단위 목록 (항상 여기에 시작) |
| **Task** | Feature 다음 | 세부 작업 (Feature에서 펼쳐짐) |
| **Done** | 맨 오른쪽 | 완료된 작업 (자동 집계) |

### 커스텀 블록 (자유 추가)

Task와 Done 사이에 **팀 프로세스에 맞는 블록**을 넣습니다.

**개발팀 예시:**
```
Feature → Task → In Progress → Code Review → QA → Done
```

**디자인팀 예시:**
```
Feature → Task → 디자인 → 피드백 → 수정 → Done
```

**마케팅팀 예시:**
```
Feature → Task → 기획 → 제작 → 검수 → Done
```

핵심 흐름인 **Feature → Task → Done**은 고정이고, 그 사이의 과정은 팀이 자유롭게 정의합니다. Trello처럼 "리스트를 전부 직접 만들어야 하는" 번거로움도 없고, Jira처럼 "워크플로우 에디터에서 상태 전이를 설정해야 하는" 복잡함도 없습니다.

[이미지: 커스텀 블록이 추가된 칸반 보드 — In Progress, Review, QA 블록이 있는 화면]

## 드래그 앤 드롭 — 카드를 옮기면 모든 게 바뀝니다

BRIDGE의 칸반 보드는 **드래그 앤 드롭이 핵심 인터랙션**입니다.

### 카드 이동

Task 카드를 다른 블록으로 드래그하면:

1. **블록이 변경**됩니다 (예: Task → In Progress)
2. **활동 로그에 기록**됩니다 ("Task '로그인 API'를 In Progress로 이동")
3. **Done으로 이동 시** Feature 진행률이 자동 업데이트

### 블록 내 정렬

같은 블록 안에서도 카드를 위아래로 드래그하여 **우선순위를 조정**할 수 있습니다. 가장 급한 작업을 맨 위로 올리세요.

### Feature 접기/펼치기

Feature 카드를 클릭하면 하위 Task 목록을 펼쳐볼 수 있고, 다시 접어서 **큰 그림만 볼 수도 있습니다.** 이건 Trello에서는 불가능한 기능이에요.

## 태그 시스템 — 보드 전체를 가로지르는 분류

Feature와 Task에 **태그를 붙여서 분류**할 수 있습니다.

### 태그 관리

- 보드별로 태그를 생성하고 관리
- 색상 지정으로 시각적 구분
- 태그 이름은 자유롭게: "프론트엔드", "백엔드", "긴급", "v2.0" 등

### 필터링

태그를 기준으로 **보드 전체를 필터링**할 수 있습니다.

"프론트엔드 태그가 붙은 작업만 보기", "긴급 태그 필터" — 이런 식으로 현재 상황에 집중할 카드만 골라볼 수 있어요. Feature, Task, 커스텀 블록을 가리지 않고 보드 전체에 적용됩니다.

[이미지: 태그 필터가 적용된 칸반 보드 — 특정 태그만 하이라이트된 상태]

---

## 활동 로그 — 누가 뭘 했는지 투명하게

모든 변경 사항은 **활동 로그에 자동 기록**됩니다.

- 블록/Feature/Task 생성, 수정, 삭제
- Task 이동 (어디서 어디로)
- Task 완료 처리
- 체크리스트 체크/해제

"누가 이 카드를 옮겼지?", "이 Feature 언제 완료됐지?" — 이런 질문에 로그만 보면 됩니다. 회의에서 "지난주에 뭐 했죠?"라고 물어볼 때도, 활동 로그를 열면 **팀 전체의 작업 이력이 한눈에** 보입니다.

---

## Trello와의 차이 — 한눈에 비교

| | Trello | BRIDGE |
|--|--------|--------|
| **계층 구조** | 카드 1단계 | Feature → Task → Checklist 3단계 |
| **진행률** | 수동 계산 | 자동 (카드 이동 시 실시간 반영) |
| **블록 구조** | 모든 리스트 수동 생성 | 고정 3블록 + 커스텀 블록 |
| **체크리스트 담당자** | Power-Up 필요 | 기본 제공 (개별 배정 가능) |
| **활동 로그** | 기본 제공 | 기본 제공 + 16개 액션 타입 분류 |
| **태그 필터** | 라벨 필터 | 태그 + 멤버 + 마일스톤 복합 필터 |

가장 큰 차이는 **진행률 자동화**입니다. Trello에서는 "이 프로젝트 몇 퍼센트야?"라는 질문에 답하려면 카드를 하나하나 세야 합니다. BRIDGE에서는 Feature 카드만 보면 됩니다.

## 실전 팁 3가지

### 1. Feature는 "릴리즈 가능 단위"로 쪼개세요

Feature 하나가 너무 크면 진행률이 오래 정체됩니다. "사용자 관리" 대신 "회원가입", "로그인", "프로필 수정"으로 나누면 진행률이 자주 올라가서 팀 동기 부여에도 좋습니다.

### 2. 커스텀 블록은 3개 이하로

블록이 너무 많으면 카드가 분산됩니다. 대부분의 팀은 **"진행중 → 리뷰 → QA"** 정도면 충분합니다.

### 3. 태그로 스프린트를 나누세요

"Sprint 1", "Sprint 2" 태그를 만들어 두면, 스프린트별로 필터링해서 현재 스프린트에 집중할 수 있습니다.

## 마치며

칸반 보드는 단순합니다. 카드를 만들고, 옮기고, 완료합니다.

그런데 그 단순한 행위가 **자동으로 진행률을 계산하고, 팀 전체의 현황을 보여주고, 활동 이력을 남기면** — 프로젝트 관리의 절반이 해결됩니다.

BRIDGE의 칸반 보드는 "보드판 위에 포스트잇 붙이기"가 아닙니다. **Feature → Task → Checklist로 이어지는 구조화된 작업 관리**이고, 그 위에서 진행률, 일정, 소통이 자연스럽게 연결됩니다.

다음 편에서는 이 칸반 보드 위의 작업을 **오늘 할 일로 바꿔주는 데일리 스케줄** 기능을 다뤄보겠습니다.
