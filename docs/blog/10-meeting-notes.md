# 팀워크 레벨업 #10 | 회의 끝나면 Feature/Task가 알아서 생긴다 — AI 회의록

> **시리즈: 팀워크 레벨업** — BRIDGE로 팀 협업을 한 단계 올리는 방법
> #10 AI 회의록 편

---

## 회의의 진짜 문제

회의가 끝나면 보통 이런 흐름입니다:

1. 누군가 회의록을 정리한다 (10~20분)
2. 회의록에서 액션 아이템을 뽑는다 (5~10분)
3. 액션 아이템을 칸반 보드에 카드로 만든다 (10~15분)
4. 카드에 담당자와 마감일을 배정한다 (5분)

**회의 1시간, 후처리 30~50분.** 합치면 거의 2시간입니다.

그리고 솔직히, 3번과 4번은 대부분 안 합니다. "나중에 정리하자" 하다가 다음 회의가 오고, 지난 회의에서 나온 액션 아이템은 슬랙 어딘가에 묻힙니다.

BRIDGE의 AI 회의록은 이 과정을 **녹음 → 텍스트 변환 → AI 분석 → Feature/Task/Checklist 자동 생성**으로 바꿉니다. 회의가 끝나면 10분 안에 보드에 카드가 생깁니다.

[이미지: AI 회의록 전체 화면 — 메모/녹음/트랜스크립트/AI 제안이 보이는 뷰]

---

## 전체 흐름 — 4단계

```
녹음 (Recording)
  → 텍스트 변환 (Transcription)
    → AI 분석 (AI Organize)
      → 보드에 적용 (Apply)
```

하나씩 살펴보겠습니다.

---

## 1단계. 녹음 — 브라우저에서 바로

별도 앱이 필요 없습니다. BRIDGE 안에서 **녹음 버튼 하나**로 시작합니다.

### 이렇게 동작합니다

1. 회의록 화면에서 **녹음 버튼** 클릭
2. 브라우저가 마이크 권한을 요청 (처음 한 번만)
3. **빨간 점 + 경과 시간**이 표시되며 녹음 시작
4. 회의가 끝나면 **정지 버튼** 클릭
5. 녹음된 오디오가 자동으로 서버에 업로드

녹음 중에도 **메모를 동시에 작성**할 수 있습니다. 회의 중 중요한 포인트를 메모하면서 녹음하면, 나중에 AI가 메모와 녹음 텍스트를 **함께 분석**합니다.

### 지원 사양

| 항목 | 내용 |
|------|------|
| **포맷** | WebM (Opus 코덱) |
| **최대 크기** | 25MB |
| **입력 장치** | 노트북 내장 마이크, 외장 마이크, 헤드셋 |
| **브라우저** | Chrome, Edge, Safari (마이크 권한 필요) |

30분 회의 기준 대략 5~10MB 정도이므로, 일반적인 회의에서 25MB 제한에 걸리는 일은 거의 없습니다.

[이미지: 녹음 중 화면 — 빨간 녹음 인디케이터 + 경과 시간 + 메모 입력창]

## 2단계. 텍스트 변환 — Whisper가 알아서

녹음이 끝나면 **자동으로 음성-텍스트 변환(STT)**이 시작됩니다.

### 변환 엔진

OpenAI의 **Whisper** 모델을 사용합니다. 현재 가장 정확한 STT 중 하나로, 한국어를 포함한 다국어를 지원합니다.

### 변환 과정

1. 녹음 파일이 서버로 업로드
2. Whisper API로 전송 → 텍스트 변환
3. 변환된 텍스트가 회의록의 **트랜스크립트 영역**에 자동 입력

변환된 텍스트는 수정할 수 있습니다. Whisper가 놓친 부분이나 전문 용어를 직접 고치면, 다음 단계인 AI 분석의 정확도가 올라갑니다.

### 추가 녹음도 가능

회의를 나눠서 녹음해도 됩니다. 두 번째 녹음의 텍스트는 **기존 트랜스크립트에 이어 붙기**됩니다. 오전 세션과 오후 세션을 따로 녹음하고 하나의 회의록으로 합칠 수 있어요.

[이미지: 텍스트 변환 완료 — 트랜스크립트 영역에 변환된 텍스트가 표시된 화면]

## 3단계. AI 분석 — 회의 내용을 구조화

이 단계가 핵심입니다. **메모 + 트랜스크립트**를 AI가 읽고, 구조화된 보고서와 액션 아이템을 생성합니다.

### "AI 정리하기" 버튼 클릭 한 번

메모나 트랜스크립트가 있는 상태에서 **"AI 정리하기"** 버튼을 클릭하면:

1. AI가 회의 내용을 분석
2. **핵심 포인트** 추출
3. **주제별 요약** 생성 (중요 표시 포함)
4. **Feature → Task → Checklist** 계층 구조의 액션 아이템 생성

### AI가 만들어주는 것

#### 핵심 포인트 (Key Points)

회의에서 결정된 사항이나 중요한 합의를 불릿 리스트로 정리합니다.

```
- OAuth 2.0 방식으로 소셜 로그인 구현하기로 결정
- 다음 스프린트까지 결제 API 연동 완료 목표
- 디자인 시스템 통일 작업을 먼저 진행하기로 합의
```

#### 주제별 요약 (Summary)

회의 내용을 주제(토픽)별로 묶어서 요약합니다. 각 토픽에 **중요도 표시**가 붙어서, 어떤 주제가 핵심이었는지 한눈에 보입니다.

```
[중요] 소셜 로그인 구현
- Google, Kakao 우선 지원
- Apple 로그인은 2차에서 진행
- 기존 이메일 계정과의 연동 방안 논의 필요

결제 시스템
- 토스페이먼츠 SDK 사용
- 테스트 환경 셋업 이번 주 내 완료
```

#### 액션 아이템 (Feature → Task → Checklist)

여기가 BRIDGE만의 진짜 차별점입니다. AI가 회의 내용에서 **실행 가능한 작업을 추출**하고, 보드의 Feature/Task/Checklist 계층에 맞게 구조화합니다.

```
Feature: 소셜 로그인 구현 [NEW]
  ├─ Task: Google OAuth 연동
  │    ├─ Checklist: OAuth 2.0 클라이언트 설정
  │    ├─ Checklist: 콜백 URL 처리 구현
  │    └─ Checklist: 프로필 정보 매핑
  └─ Task: Kakao 로그인 연동
       ├─ Checklist: Kakao SDK 설치
       └─ Checklist: 로그인 플로우 구현

Feature: 결제 시스템 [EXISTING — 기존 Feature에 연결]
  └─ Task: 토스페이먼츠 연동
       ├─ Checklist: SDK 설치 및 설정
       ├─ Checklist: 테스트 환경 구축
       └─ Checklist: 결제 플로우 구현
```

**[NEW]**와 **[EXISTING]**의 차이가 중요합니다:

- **NEW**: 보드에 없는 새로운 Feature → 새로 생성
- **EXISTING**: 보드에 이미 있는 Feature → 기존 Feature 아래에 Task를 추가

AI가 현재 보드의 Feature/Task 목록을 인식하고 있기 때문에, **기존 작업과 겹치지 않게** 제안합니다. "이미 있는 Feature에 Task만 추가"하는 스마트한 판단을 해줍니다.

[이미지: AI 분석 결과 — 핵심 포인트 + 주제별 요약 + Feature/Task/Checklist 계층 구조]

## 4단계. 보드에 적용 — 체크박스로 골라서

AI가 제안한 항목을 **전부 적용할 필요는 없습니다.** 체크박스로 원하는 것만 골라서 적용할 수 있습니다.

### 적용 화면

AI 제안이 **Feature → Task → Checklist** 계층의 체크박스 트리로 표시됩니다.

- **Feature 레벨 체크박스**: Feature 전체를 선택/해제
- **Task 레벨 체크박스**: 개별 Task 선택
- **Checklist 레벨 체크박스**: 세부 항목 선택
- **"전체 선택/해제"** 토글: 한 번에 전체 제어

### 중복 감지

이미 보드에 존재하는 Feature나 Task는 **파란색 뱃지로 표시**되고 **체크박스가 잠깁니다.** "이건 이미 있으니까 다시 만들 필요 없어요"라는 의미입니다.

### "적용" 클릭

선택한 항목만 보드에 생성됩니다. 적용이 완료되면:

```
생성 완료
- Feature 1개 생성
- Task 3개 생성
- Checklist 7개 생성
```

이렇게 결과가 표시되고, 칸반 보드로 가면 **방금 회의에서 나온 작업들이 카드로 배치되어 있습니다.**

[이미지: 적용 화면 — 체크박스 트리 + 중복 뱃지 + "적용" 버튼]

## 회의록 관리

### 날짜별 정리

회의록은 **날짜별로 자동 정리**됩니다. 캘린더에서 날짜를 선택하면 해당 날의 회의 목록이 나타납니다.

### 회의 정보 관리

각 회의록에는 다음 정보가 포함됩니다:

- **제목**: 회의 주제 (클릭해서 바로 수정)
- **날짜**: 회의 일자
- **시간**: 시작/종료 시간
- **참석자**: 타임블록 기반 자동 연결
- **컬러**: 회의 유형별 색상 구분 (기본 보라색)
- **메모**: 수기 메모
- **트랜스크립트**: 녹음 텍스트
- **AI 제안**: 구조화된 분석 결과

## 팀 공유 — 알림 한 번이면 끝

회의록을 정리했으면 팀에 공유해야겠죠. **"알림 보내기"** 버튼 하나면 됩니다.

- **인앱 알림**: 보드 멤버 전원에게 알림
- **Slack 알림**: Slack 웹훅이 설정된 멤버에게 자동 전송

Slack으로 전송되는 내용에는 **회의 제목, 메모 요약, BRIDGE에서 보기 링크**가 포함됩니다. 팀원이 Slack에서 바로 확인하고, 상세 내용은 BRIDGE에서 볼 수 있어요.

## 실전 시나리오

### 시나리오 1: 주간 스프린트 플래닝

```
09:00  스프린트 플래닝 회의 시작
       → BRIDGE에서 녹음 시작 + 메모 작성

10:00  회의 종료
       → 녹음 정지 → 자동 텍스트 변환 (1~2분)

10:02  AI 정리하기 클릭
       → AI가 Feature/Task/Checklist 제안 생성 (10~30초)

10:05  제안 확인 → 체크박스로 선택 → 적용
       → 칸반 보드에 이번 스프린트 작업이 생성됨

10:07  알림 보내기
       → 팀 전원에게 회의록 + 작업 목록 공유
```

**회의 끝나고 7분 만에 보드 셋업 완료.** 예전에는 30~50분 걸리던 일입니다.

### 시나리오 2: 클라이언트 미팅

클라이언트와의 미팅에서 나온 요구사항을 빠르게 보드에 반영해야 할 때:

1. 미팅 중 메모로 핵심 요구사항 기록
2. 미팅 후 AI 분석 → 요구사항이 Feature/Task로 구조화
3. 팀에 공유 → "클라이언트가 요청한 것" 목록이 바로 보드에

### 시나리오 3: 장애 대응 회의

장애가 발생해서 긴급 회의를 했다면:

1. 회의 중 메모로 원인 분석, 대응 방안 기록
2. AI가 "긴급 수정 Task"와 "재발 방지 Task"를 분리해서 제안
3. 긴급 Task만 먼저 적용 → 담당자 배정 → 즉시 작업 시작

## 실전 팁 3가지

### 1. 메모 + 녹음을 함께 쓰세요

녹음만 하면 AI가 분석할 재료가 "대화 흐름" 뿐입니다. 회의 중 핵심 결정 사항을 메모에 짧게 적어두면, AI가 **메모(핵심)와 트랜스크립트(상세)를 교차 분석**해서 더 정확한 결과를 냅니다.

### 2. AI 제안은 "출발점"으로 쓰세요

AI가 완벽한 Task를 만들어주진 않습니다. 하지만 **80%의 구조화 작업**을 대신해줍니다. 적용 후에 보드에서 Task의 담당자, 마감일, 세부 내용을 조정하는 게 처음부터 직접 만드는 것보다 훨씬 빠릅니다.

### 3. 정기 회의에 루틴으로 만드세요

주간 스프린트 플래닝, 데일리 스크럼, 월간 회고 — 정기 회의에서 항상 BRIDGE 회의록을 쓰면, **회의 → 실행**의 간극이 거의 사라집니다. "회의에서 결정한 건데 아무도 안 했다"가 없어집니다.

## 마치며

회의의 가치는 **"얘기한 것"**이 아니라 **"실행한 것"**에서 나옵니다.

아무리 좋은 아이디어가 나와도, 회의록 정리가 안 되고, 액션 아이템이 보드에 안 올라가면, 그 회의는 시간 낭비입니다. 반대로, 회의가 끝나자마자 칸반 보드에 Feature/Task/Checklist가 생기면, **회의의 모든 결정이 바로 실행으로 연결**됩니다.
