미니 칸반 (Mini Kanban) 뷰

블록에서 태스크가 마인드맵처럼 파생되고, 각 태스크 노드는 TODO · DOING · DONE 3열의 미니 칸반입니다. 안의 카드는 체크리스트 항목 — TODO↔DOING은 오늘 날짜 vs 일정 기간으로 자동 전환, DONE으로 옮기면 체크(완료) 처리됩니다.

A

노드 헤더 = 태스크

태스크명 · 소속 피처 칩(색) · 진행률(완료 체크/전체) · 담당자 아바타

B

TODO — 예정

start_date가 미래(오늘 < 시작일)이거나 일정 미등록. 날짜 칩은 회색.

C

DOING — 진행 중 (자동)

오늘이 [start_date, due_date] 안에 들어오면 자동으로 TODO→DOING. 앰버 칩.

D

DONE — 완료 (수동)

카드를 DONE으로 드롭 → completed=true, done_date=오늘. 체크 표시 + 취소선.

E

카드 = 체크리스트 항목

제목 + 날짜 칩. 드래그로 열 이동, DONE에서 되돌리면 체크 해제.

3

열 전이 규칙 — 무엇이 자동이고 무엇이 수동인가

TODO↔DOING = 날짜 기반 자동 · DOING↔DONE = 사용자 체크(수동)

TODO

일정 start_date가 오늘보다 미래이거나, 일정이 아직 등록되지 않은 체크리스트 항목.

자동 · 날짜 ⇄

오늘 ≥ 시작일
→ DOING
(기간 지나면 되돌지 않음)

DOING

오늘 날짜가 등록한 일정 기간 [start_date, due_date] 안에 있는 항목. 별도 클릭 없이 날짜만으로 진입.

수동 · 체크 →

카드를 DONE으로 이동
= 완료 체크

DONE

completed=true · done_date 기록. DONE에서 빼내면 체크 해제되어 날짜 기준(TODO/DOING)으로 복귀.

자동 전환 로직 (렌더 시 계산)

  • completed = true → DONE (최우선)
  • start_date ≤ 오늘 ≤ due_date → DOING
  • 오늘 < start_date 또는 일정 없음 → TODO
  • 지났어도(오늘 > due_date) 미완료면 → DOING 유지(지연 강조 옵션)
중요: TODO/DOING은 저장 값이 아니라 오늘 날짜로 매 렌더 파생. 시간이 흐르면 새로고침만으로 카드가 이동합니다.

드래그로 바뀌는 실제 데이터

TODO→DOING 드래그start_date=오늘
DOING→TODO 드래그start_date=미래/null
→ DONE 드래그completed=true
DONE→ 되돌림completed=false

즉 “카드를 옮긴다”는 곧 체크리스트 항목의 start_date 또는 completed를 바꾸는 것.

일정(스케줄) 연동

체크리스트 항목의 start_date/due_date는 이미 리소스뷰·캘린더에서 쓰는 값. 미니 칸반에서 DOING 진입/드래그 시 그 값을 갱신하면 스케줄 뷰와 자동 동기화됩니다.

  • 날짜 칩 클릭 → 기간 편집 팝오버
  • 담당자 아바타 = 항목 assignee

인터랙션 요약

노드 안 (체크리스트)

  • 카드 드래그 TODO↔DOING → start_date 조정
  • 카드 드래그 → DONE → 완료 체크(completed=true)
  • 날짜 방치 시 자동 이동 → 오늘이 기간 진입하면 렌더에서 DOING
  • 날짜 칩 클릭 → 기간 편집(스케줄 동기화)

캔버스 (블록·태스크)

  • 태스크 노드 드래그 배치 → 좌표 저장
  • 태스크를 다른 블록으로 이동 → Task.block_id 변경 = 실보드 반영
  • 블록 허브 접기/펼치기 → 파생 태스크 노드 표시 토글
  • 필터 → 담당자·마일스톤별 태스크 노드 강조
6

구현 계획 (MindMapView 재사용)

마인드맵과 동일한 뼈대 — 노드 타입 2종(블록 허브 · 태스크 3열)과 날짜 파생 로직만 추가

프론트엔드

  • 새 뷰 views/MiniKanbanView.tsx (MindMapView 구조 복제)
  • 노드 타입 blockHubNode + taskNode(3열 미니 칸반)
  • 열 파생 함수 resolveColumn(item, today) → completed/start_date/due_date로 TODO·DOING·DONE 계산
  • 드래그 핸들러 열 간 = 체크리스트 start_date/completed PATCH · 노드 간 = task.move(block_id)
  • ViewMode union 3곳 동기화: KanbanBoardPage(BOARD_SUB_MODES) · BoardSubTabs · FloatingViewSwitcher
  • 영속 localStorage boardSubMode_{boardId}="minikanban"
  • i18n kanban.viewBoardMiniKanban + minikanban.* (10 로케일)

백엔드

  • 레이아웃 저장 board_minikanban 1행/보드 JSON (마인드맵 선례)
  • 재사용 API: 체크리스트 항목 수정(start_date/completed) · 태스크 블록 이동 — 신규 로직 없음
  • 마이그레이션 타임스탬프 V{YYYYMMDD_HHmmss}__create_board_minikanban.sql (멱등)
  • 권한 GET=Viewer+ · 편집/이동=Member+
불변식(마인드맵 교훈): 노드엔 task_id/좌표만 저장. 태스크·체크리스트·진행률은 context로 live 주입(node.data에 넣으면 autosave 폭주). 날짜 파생 카드는 저장 문서 제외.

단계별 로드맵

Phase 1 — 캔버스 + 블록/태스크 노드

블록 허브에서 태스크 노드 방사 배치, 좌표 저장(읽기). 3열은 정적 표시.

Phase 2 — 날짜 파생 3열

resolveColumn으로 TODO/DOING/DONE 자동 분류 + 오늘 기준 실시간 이동.

Phase 3 — 드래그 편집

열 간 드래그 → start_date/completed PATCH + 낙관적 업데이트 + WebSocket.

Phase 4 — 노드 간 이동 & 필터

태스크를 다른 블록으로 이동(block_id), 담당자/마일스톤 필터, 지연 강조.

정리

★ 확정 방향

노드 = 태스크, 내부 = TODO/DOING/DONE 미니 칸반, 카드 = 체크리스트 항목. TODO↔DOING은 오늘 날짜 vs 일정 기간으로 자동, DONE은 이동 시 완료 체크. 전체 화면은 블록 허브에서 태스크가 마인드맵처럼 파생되며, 태스크를 다른 블록으로 옮기면 실제 보드의 block_id가 함께 바뀝니다. 기존 마인드맵(React Flow) 아키텍처와 체크리스트 날짜 필드를 그대로 재사용하므로 백엔드 신규 로직은 거의 없습니다.
