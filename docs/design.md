# 🎯 팀 칸반보드 - 기획서

## 1. 서비스 개요

### 1.1 프로젝트 목적
소규모 팀(5~15명)이 **Feature 단위**로 업무를 관리하고, 자유로운 워크플로우를 구성할 수 있는 **칸반보드 웹 애플리케이션**

### 1.2 핵심 컨셉

| 컨셉 | 설명 |
|------|------|
| **고정 블록 3개** | Feature, Task, Done (삭제/수정 불가) |
| **커스텀 블록** | 팀 상황에 맞게 Task와 Done 사이에 자유롭게 추가 |
| **Feature-Task 연동** | Feature 내 서브태스크 추가 시 Task 블록에 카드 자동 생성 |
| **완료 추적** | Task가 Done 블록으로 이동하면 Feature 진행률 자동 반영 |
| **팀 협업** | 보드에 멤버 초대 및 역할 기반 권한 관리 |
| **태그 시스템** | Feature/Task에 태그 부여하여 분류 및 필터링 |
| **체크리스트** | Task 내부에 세부 항목 관리 |

### 1.3 서비스 구조

```
┌─────────────────────────────────────────────────────────────────────┐
│                           사용자 (User)                              │
│  - 이메일/소셜 로그인                                                 │
│  - 여러 보드 소유 또는 참여 가능                                       │
└───────────────────────────────┬─────────────────────────────────────┘
                                │
                    ┌───────────▼───────────┐
                    │       보드 (Board)      │
                    │  - 팀 단위 작업 공간     │
                    │  - 구독/결제 단위        │
                    └───────────┬───────────┘
                                │
        ┌───────────────────────┼───────────────────────┐
        │                       │                       │
┌───────▼───────┐       ┌───────▼───────┐       ┌───────▼───────┐
│  블록 (Block)   │       │ 멤버 (Member) │       │  태그 (Tag)    │
│  - 고정 3개     │       │  - 역할 기반   │       │  - 분류 용도   │
│  - 커스텀 추가  │       │  - 권한 관리   │       │  - 필터링      │
└───────┬───────┘       └───────────────┘       └───────────────┘
        │
┌───────▼───────┐
│ Feature (카드) │  ← 보드의 Feature 블록에만 생성
│  - 업무 단위    │

└───────┬───────┘
        │
┌───────▼───────┐
│  Task (카드)   │  ← Feature의 서브태스크로만 생성
│  - 세부 작업    │
│  - 블록 간 이동 │
└───────┬───────┘
        │
┌───────▼───────┐

## 3. 회원 및 권한 시스템

### 3.1 회원 가입/로그인

**가입 방식**
- 이메일 + 비밀번호
- 소셜 로그인 (Google, GitHub)

**회원 정보**
- 프로필 이미지
- 이름 (닉네임)
- 이메일
- 내가 만든 보드 목록
- 초대받은 보드 목록
- **즐겨찾기 보드** (user_board_stars)

### 3.2 보드 역할 (Role)

| 역할 | 설명 | 부여 방식 | 과금 대상 |
|------|------|----------|:--------:|
| **Owner** | 보드 생성자, 최고 권한 | 보드 생성 시 자동 | ✅ |
| **Admin** | 관리자, Owner와 유사 | Owner가 지정 | ✅ |
| **Member** | 일반 멤버, 카드 작업 가능 | 초대 시 기본값 | ✅ |
| **Viewer** | 읽기 전용 | Owner/Admin이 지정 | ❌ |

### 3.4 멤버 초대 방식

**1. 이메일 초대**
- Owner/Admin이 이메일 입력
- 역할 지정 가능
- 초대 메일 발송

**2. 초대 링크**
- 링크 생성 시 옵션:
  - 기본 역할 (Member/Viewer)
  - 만료 기간 (1일/7일/30일/무제한)
  - 사용 횟수 (1회/10회/무제한)
- 링크 비활성화 가능

## 4. 블록 시스템

### 4.1 블록 타입

| 구분 | 블록 | 삭제 | 이름변경 | 위치 | 역할 |
|------|------|:----:|:-------:|------|------|
| 고정 | **Feature** | ❌ | ❌ | 항상 첫째 | Feature 카드 생성 장소 |
| 고정 | **Task** | ❌ | ❌ | 항상 둘째 | 서브태스크 자동 생성 위치 |
| 고정 | **Done** | ❌ | ❌ | 항상 마지막 | 완료된 Task, Feature 진행률 반영 |
| 커스텀 | (자유) | ✅ | ✅ | Task~Done 사이 | 팀 맞춤 워크플로우 |

### 4.2 블록 배치

```
┌─────────┬─────────┬─────────────────────────────┬─────────┐
│ Feature │  Task   │      커스텀 블록 영역        │  Done   │
│ (고정)  │ (고정)  │    (자유롭게 추가/삭제)       │ (고정)  │
│ 첫째    │ 둘째    │    순서 변경 가능            │ 마지막  │
└─────────┴─────────┴─────────────────────────────┴─────────┘
```

### 4.3 커스텀 블록 활용 예시

```
# 진행 단계별
Feature → Task → [In Progress] → [Review] → [QA] → Done

# 담당자별
Feature → Task → [Frontend] → [Backend] → [Design] → Done

# 우선순위별
Feature → Task → [🔴 긴급] → [🟡 일반] → [🟢 여유] → Done

# 미니멀
Feature → Task → Done
```

## 5. 카드 시스템

### 5.1 계층 구조

```
Board (보드)
  └── Feature (카드)           ← Feature 블록에서만 생성
        ├── 제목, 설명
        ├── 담당자, 우선순위, 마감일
        ├── 태그 (다중 선택)
        ├── 진행률 (완료된 Task / 전체 Task)
        │
        └── Task (서브태스크)    ← Feature 상세에서 추가
              ├── 제목, 설명
              ├── 담당자, 마감일
              ├── 현재 블록 위치
              ├── 태그 (다중 선택)
              │
              └── Checklist (체크리스트)
                    ├── 항목명
                    ├── 완료 여부
                    ├── 담당자
                    └── 마감일
```

### 5.2 카드 생성 규칙

| 카드 타입 | 생성 위치 | 생성 방법 |
|----------|----------|----------|
| Feature | Feature 블록 | [+ Feature] 버튼 클릭 |
| Task | Task 블록 (자동) | Feature 상세 → 서브태스크 추가 |
| Checklist | Task 내부 | Task 상세 → 체크리스트 추가 |

### 5.3 카드 이동 규칙

```
Feature 블록: 이동 불가 (고정)

Task 이동 경로:
  Task ↔ 커스텀 블록 ↔ Done

  ✅ Task → 커스텀 블록
  ✅ Task → Done
  ✅ 커스텀 → 커스텀
  ✅ 커스텀 → Done
  ✅ Done → 커스텀 (재오픈)
  ✅ Done → Task (재오픈)
  ❌ Feature 블록으로 이동 불가
```

### 5.4 완료 처리

```
Task가 Done 블록으로 이동
        │
        ▼
Task.isCompleted = true
Task.completedAt = 현재시간
        │
        ▼
해당 Feature의 completedTasks 증가
        │
        ▼
Feature 진행률 자동 업데이트 (예: 3/5 완료)
```

User ──┬── owns ──────> Board ──┬── has ──> Block
       │                        ├── has ──> Feature ──> Task ──> ChecklistItem
       ├── joins ─────> BoardMember          │            │
       │                        ├── has ──> Tag <────────┴── tagged
       ├── stars ─────> UserBoardStar        │
       │                        ├── has ──> InviteLink
       └── creates ───> ActivityLog          │
                                └── has ──> Subscription
```

## 10. 핵심 규칙 요약

| 항목 | 규칙 |
|------|------|
| **고정 블록** | Feature, Task, Done (삭제/이름변경 불가) |
| **블록 위치** | Feature(첫째) → Task(둘째) → 커스텀... → Done(마지막) |
| **Feature 생성** | Feature 블록에서만 가능 |
| **Task 생성** | Feature 내 서브태스크로만 가능 |
| **카드 이동** | Task ↔ 커스텀 ↔ Done 자유롭게 |
| **완료 반영** | Done 이동 시 Feature 진행률 자동 업데이트 |
| **역할 순서** | Owner > Admin > Member > Viewer |
| **블록 관리** | Owner, Admin만 가능 |
| **카드 작업** | Member 이상 가능 |
| **태그 관리** | Admin 이상 생성/삭제, Member는 부여만 |
| **무료 체험** | 보드 생성 후 7일 |
| **과금 기준** | Owner + Admin + Member 수 (Viewer 제외) |
| **결제 주체** | Owner만 가능 |
