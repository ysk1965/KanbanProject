## 2. Backend 추가 변경 상세

### 2.1 Board 엔티티 확장

```java
// 신규 Enum: BoardType.java
public enum BoardType {
    TEAM,       // 기존 팀 보드 (기본값)
    PERSONAL    // 개인 보드 (1인 1개)
}

// Board.java 변경
@Entity
@Table(name = "boards")
public class Board extends BaseTimeEntity {
    // ... 기존 필드 ...

    @Column(name = "board_type", nullable = false)
    @Enumerated(EnumType.STRING)
    private BoardType boardType = BoardType.TEAM;

    public boolean isPersonal() {
        return this.boardType == BoardType.PERSONAL;
    }

    public boolean canInviteMembers() {
        return !isPersonal();
    }

    public boolean canAccessMeeting() {
        return !isPersonal() && isPremium();
    }
}
```

### 2.2 Personal Board 생성 서비스

```java
// BoardService.java에 추가
@Transactional
public BoardResponse.Detail createPersonalBoard(User user) {
    if (boardRepository.existsByOwnerAndBoardType(user, BoardType.PERSONAL)) {
        throw new BusinessException(ErrorCode.PERSONAL_BOARD_ALREADY_EXISTS);
    }

    Board board = Board.builder()
            .name("My Space")
            .boardType(BoardType.PERSONAL)
            .owner(user)
            .tier(determineTier(user))
            .build();
    boardRepository.save(board);

    // 기본 블록 3개: To Do / Doing / Done
    createBlock(board, "To Do", BlockType.FEATURE, 0);
    createBlock(board, "Doing", BlockType.TASK, 1);
    createBlock(board, "Done", BlockType.DONE, 999);

    // OWNER 멤버십
    createOwnerMembership(board, user);

    // 구독
    Subscription subscription = Subscription.createTrial(board);
    subscriptionRepository.save(subscription);

    return BoardResponse.Detail.from(board, membership);
}
```

## 4. 아키텍처 레이어 정리

### 4.1 데이터 소스별 역할

```
┌──────────────────────────────────────────────────────┐
│                   My Space (/my-board)                 │
│                                                        │
│  칸반 탭           일정 탭          일기 탭     캘린더 탭  │
│  ─────────        ─────────      ─────────  ─────────  │
│  Board(PERSONAL)  PersonalEvent  DiaryEntry  Board     │
│  + Block          (기존 도메인)   (기존 도메인)  + Task    │
│  + Task                                     + Feature  │
│  + Tag                                                 │
│  + Checklist                                           │
│                                                        │
│  ↕ Today API에서 통합 ↕                                  │
│                                                        │
│  Today View = Task(오늘) + PersonalEvent(오늘)           │
│              + DailyChecklist(오늘)                      │
└──────────────────────────────────────────────────────┘
```

### 4.2 도메인 간 관계

```
Board (PERSONAL)
  │
  ├── Block → Task → Checklist   (기존 Board 인프라 100% 재사용)
  │     └── Tag
  │
  └── [Today API 통합]
        ├── Task (due_date = today)
        ├── PersonalEvent (event_date = today)  ← 별도 도메인이지만 조회 시 합침
        └── DailyChecklist (date = today)

DiaryEntry ← 독립 도메인 (user_id 직접 참조, board 불필요)
PersonalEvent ← 독립 도메인 (user_id 직접 참조, board 불필요)
```

**핵심 결정**: Diary와 PersonalEvent는 Board에 종속시키지 않음.
- 이미 user_id로 직접 참조하는 구조로 구현 완료
- Board와 연결하면 불필요한 마이그레이션 + 기존 코드 수정 필요
- Today API에서 **조회 시점에만 통합** → 깔끔한 분리
