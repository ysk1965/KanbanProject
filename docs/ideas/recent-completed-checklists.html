0. 핵심 인사이트 — 진행률 바를 "움직인 것"이 곧 최근 완료

블록 진행률 바는 이미 그 블록 안 모든 태스크의 체크리스트 완료 합계입니다 (KanbanBlock.tsx — Σ checklist_completed / Σ checklist_total). 즉 "최근 완료된 체크리스트" = 이 바를 방금 앞으로 민 항목들. 둘은 원래 같은 데이터입니다.

🔑 백엔드 거의 불필요. 프론트가 이미 checklistDataMap ({ [taskId]: ChecklistItem[] })로 블록 안 모든 체크리스트 항목을 completed_at 포함해 메모리에 들고 있음 → 블록 단위 "최근 완료"는 클라이언트에서 바로 파생 가능 (별도 API 0개로 1차 버전 가능).
이미 있는 것설명
completed_at (UTC)항목별 완료 시각 — 저장·API·FE타입 노출 완료
블록 진행률 바done/total (pct%) 집계·렌더 완료
checklistDataMap블록 안 전체 항목이 FE 메모리에 로드됨
정렬·"오늘/어제" 판정은 completed_at(UTC) 기준 + FE dateUtils로 클라이언트 TZ 변환. done_date는 서버 로컬 TZ라 경계 오차 위험 → 최근순엔 쓰지 않음.

  • A/B보다 구현량 큼

2. 구현 — 2단계 로드맵

1단계 · 블록 로컬 (BE 0개) 반나절

안 A + B를 KanbanBlock.tsx 안에서 checklistDataMap만으로 파생.

// 블록 안 모든 항목을 평탄화 → 최근 완료만
const recent = tasks
  .flatMap(t => (checklistDataMap?.[t.id] ?? [])
    .filter(c => c.is_completed && c.completed_at)
    .map(c => ({ ...c, taskTitle: t.title })))
  .filter(c => new Date(c.completed_at) >= startOfToday())   // dateUtils
  .sort((a,b) => +new Date(b.completed_at) - +new Date(a.completed_at));

const deltaToday = recent.length;        // → 안 A 뱃지
// recent.slice(0, 5)                     // → 안 B 팝오버
  • 진행률 바 렌더 블록(KanbanBlock.tsx:400~424)에 뱃지 + 클릭 팝오버 추가
  • 기간 기준 startOfToday()/startOfWeek()은 dateUtils(클라이언트 TZ)로
  • 항목 클릭 → 기존 태스크 상세 모달 오픈 핸들러 재사용
  • i18n block.recentDone.*

2단계 · 보드 전역 드로어 (안 D) 추가 하루

GET /api/v1/boards/{boardId}/checklist-items/recently-completed
    ?since=<iso>&limit=30&cursor=<completed_at>&group_by=block
  • 리포지토리: 기존 findCompletedByAssigneeAndBoardIdsAndDateRange 패턴 복제 → WHERE t.board.id=:boardId AND c.isCompleted=true AND c.completedAt>=:since ORDER BY c.completedAt DESC
  • JOIN FETCH task/feature/block/assignee (N+1 방지) → 응답에 block_id/block_name 포함해 FE 그룹핑
  • 커서 페이지네이션(completed_at 기준) + 권한 Board.Viewer+
  • 실시간: useBoardWebSocket이 이미 체크리스트 토글 이벤트 브로드캐스트 → 델타/피드 즉시 갱신 (폴링 불필요)
  • JSON은 snake_case 필수 (completed_at, block_name)

3. 추천

안 A(델타 뱃지) + 안 B(클릭 팝오버) 세트를 1차로. 데이터가 이미 블록 안에 있으니 백엔드 0개, FE만 반나절. 진행률 바라는 기존 맥락에 정확히 얹혀 "이 블록이 얼마나 / 무엇을 최근에 끝냈나"를 한 흐름으로 답함.

필요해지면 안 D(전역 드로어, 블록별 그룹 + 미니 바)로 확장 — "보드 전체 완료 속도" 조망. 안 C(바 하이라이트)는 취향이면 A와 병행 가능한 시각 옵션.

4. 결정할 것

  • "최근" 기준: 오늘? 이번 주? 최근 N개? → 뱃지에 기간 토글 두면 유연
  • 범위: 1차는 블록 로컬(열람 중인 데이터)만으로 충분. 전역 필요 시 2단계
  • 뱃지 표현: ▲ 오늘 +5(증가분) vs 오늘 5개 완료 — 어느 쪽이 직관적?
  • 클릭 대상: 진행률 바 전체 클릭 vs 델타 뱃지만 클릭
