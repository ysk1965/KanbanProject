05 백엔드가 소비하는 AWS — Spring Boot가 호출하는 방식

백엔드(Java 21 / AWS SDK v2)는 S3·CloudWatch만 직접 호출하고, CloudFront는 URL 조립용, 이메일은 SES가 아닌 Gmail SMTP입니다. 자격증명은 키 하드코딩 없이 인스턴스 역할(DefaultCredentialsProvider)에 의존합니다.

S3 핵심

버킷 ${S3_BUCKET} · SDK v2 · 리전 ap-northeast-2 하드코딩
  • 메인 업로드 = presigned PUT: temp/{uuid} 10분 만료 → FE가 브라우저에서 S3 직접 PUT → 저장 시 headObject→copyObject(comments/…)→deleteObject
  • customicon/ref·result, 만료 temp 정리(listObjectsV2)
  • → 버킷 CORS + 인스턴스역할 s3:PutObject 권한에 절대 의존

CloudWatch

CLOUDWATCH_ENABLED 시 활성 (기본 off)
  • GetMetricStatistics(5분, AVG)로 EC2(CPU/Net) · RDS(CPU/Conn/Mem/IOPS) 지표 pull
  • 관리자 모니터링 대시보드 + 임계치 초과 시 Slack/메일 알림

CloudFront URL only

SDK 미사용 · CLOUDFRONT_DOMAIN env
  • 다운로드 URL 조립: 설정 시 https://{domain}/{key}, 미설정 시 S3 직링크 폴백
  • 미설정 시 OAC 프라이빗 버킷은 403 → env 주입 확인 필요

이메일 SES 아님

JavaMailSender · smtp.gmail.com 하드코딩
  • 인증/비번재설정/초대 + 500 에러 알림
  • CLAUDE.md의 'SES/SMTP' 표기와 불일치 — SES 미연동으로 인벤토리 정정
